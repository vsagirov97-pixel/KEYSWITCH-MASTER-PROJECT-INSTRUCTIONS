# KeySwitch — Product Requirements Document (v1)

Статус: **черновик для GATE 1** · Автор: Product Analyst · Решения: см. `00-decisions.md`

## 1. Назначение
KeySwitch — фоновое desktop-приложение для Windows 10/11, которое по горячей клавише исправляет текст, набранный в неверной раскладке (EN ↔ RU), и выполняет пользовательский макрос по второй горячей клавише. Не переводчик и не транслитератор. Вся обработка локальная.

## 2. Вне рамок v1 (Non-goals)
- Автоматическое исправление «на лету» без нажатия горячей клавиши.
- Перехват набора клавиш (кейлоггинг) и любые низкоуровневые хуки клавиатуры.
- Сохранение/восстановление позиции курсора как отдельный механизм.
- Импорт, экспорт и обмен макросами; магазин макросов.
- Платная версия, лицензирование, несколько слотов (архитектура допускает, UI — нет).
- Телеметрия, автообновление через сеть (решается отдельно перед релизом).
- macOS (архитектура готова, реализации нет).
- Языки кроме EN/RU (архитектура готова, данных нет).

## 3. Пользовательские сценарии

### US-01. Исправление текста в поле чата
Пользователь в Telegram набрал `Ghbdtn, rfr ltkf?`, нажал горячую клавишу → поле содержит `Привет, как дела?`, системная раскладка переключилась на RU. Уведомлений нет.

### US-02. Исправление выделенного фрагмента
В Word выделено `ytn` → заменено на `нет`, остальной документ не изменён.

### US-03. Многострочный документ без выделения
В Блокноте курсор в конце строки `rfr ltkf` (выше — другие строки) → заменяется только фрагмент от последнего разрыва строки до курсора. Если фрагмент определить нельзя — отмена.

### US-04. Смешанный текст
Поле содержит `Привет, rfr ltkf?` → появляется компактное окно: «Русский / English / Отмена». «Русский» → `Привет, как дела?`. «Отмена» → ничего не меняется.

### US-05. Неуверенность
Конвертер не может уверенно выбрать вариант (низкая оценка модели для всех кандидатов) → операция отменяется, текст и буфер не изменены. Короткий системный звук (отключаемый).

### US-06. Запрет
Фокус в поле пароля / окне администратора / исключённом приложении → операция не выполняется.

### US-07. Текстовый макрос
Слот содержит текстовый макрос; по горячей клавише макроса текст вставляется в позицию курсора активного поля.

### US-08. Скрипт-макрос
Слот содержит JS или Python. По горячей клавише скрипт получает контекст (текст выделения/поля — по настройке) и возвращает действие: вставить / заменить / ничего. Ошибка или превышение лимита → операция отменяется, ошибка видна в Diagnostics и в Macro Studio.

### US-09. Управление
Трей: открыть окно, вкл/выкл функциональность, выход. Настройки: автозапуск, тема, язык интерфейса, горячие клавиши, список исключений.

## 4. Функциональные требования

### FR-CONV. Конвертация
- FR-CONV-1. Таблица соответствия по физическим клавишам US QWERTY ↔ ЙЦУКЕН, хранится как данные.
- FR-CONV-2. Сохраняются регистр, цифры, пробелы, переносы строк, неизвестные символы.
- FR-CONV-3. Для символов, у которых в обеих раскладках есть смысл (`, . ; ' [ ] / ? " @ # $ ^ & ~ \``), вариант выбирается по контексту языковой моделью (D-01). Обязательные тест-кейсы:
  - `Ghbdtn, rfr ltkf?` → `Привет, как дела?`
  - `k.,k.` → `люблю`
  - `j,sxyj` → `обычно`
  - `Руддщ` → `Hello`
  - `Ntcn 123` → `Тест 123`
- FR-CONV-4. Направление определяется по составу текста (D-02). Активная раскладка — при равенстве.
- FR-CONV-5. Фрагменты, уже корректные на целевом языке, не меняются (смешанный текст).
- FR-CONV-6. Добавление языка не требует изменения кода ядра (D-15).

### FR-FIELD. Работа с полем
- FR-FIELD-1. Порядок выбора объёма (D-03): выделение → всё однострочное поле → фрагмент до разрыва строки в многострочном → отмена.
- FR-FIELD-2. Лимит 5 000 символов; больше — отмена.
- FR-FIELD-3. Исключения D-05 проверяются до чтения текста.
- FR-FIELD-4. Перед заменой повторно проверяется, что фокус в том же поле (HWND, PID, UIA RuntimeId). Иначе — отмена.
- FR-FIELD-5. После замены Ctrl+Z в целевом приложении возвращает исходный текст (D-12) — проверяется на эталонных приложениях.
- FR-FIELD-6. После успешной замены раскладка окна переключается на целевую.

### FR-CLIP. Буфер обмена
- FR-CLIP-1. Короткий текст (порог настраивается, по умолчанию ≤ 200 символов) вводится через `SendInput` Unicode без буфера — если приложение это поддерживает (по профилю).
- FR-CLIP-2. Иначе: сохранить все сохранимые форматы → поместить текст с метками исключения (D-13) → вставить → дождаться потребления → восстановить, только если sequence number не изменился сторонним приложением.
- FR-CLIP-3. Если в буфере есть несохранимые данные (отложенная отрисовка, неизвестные приватные форматы) — использовать `SendInput` или отменить операцию.

### FR-HK. Горячие клавиши
- FR-HK-1. Две независимые клавиши: конвертация и макрос.
- FR-HK-2. Сочетание из 2–3 клавиш, обязательно одна не-модификаторная (D-14).
- FR-HK-3. Конфликт (регистрация не удалась / совпадение двух клавиш) — понятная ошибка и предложение переназначить.
- FR-HK-4. Перед отправкой ввода ожидается отпускание модификаторов (таймаут 1 с → отмена).

### FR-MACRO. Macro Studio
- FR-MACRO-1. Один слот; тип: текст / JavaScript / Python.
- FR-MACRO-2. Редактор CodeMirror 6 с подсветкой; проверка синтаксиса выполняется в той же песочнице.
- FR-MACRO-3. API: см. `02-architecture.md` §6. Ограничения D-07, D-08.
- FR-MACRO-4. Лимиты по умолчанию: 2 с выполнения, 64 МБ памяти, 100 000 символов вывода.

### FR-UI. Интерфейс
- Разделы: Overview, Languages & Layouts, Hotkeys, Macro Studio, Settings, Diagnostics.
- Темы: Dark / Light / System. Языки: RU / EN, расширяемо.
- Diagnostics показывает журнал операций **без текста пользователя**: время, приложение (имя exe), результат, причина отказа.

### FR-SYS. Фон
- Трей, автозапуск (HKCU Run, по настройке), временное отключение, без уведомлений об успехе.

## 5. Нефункциональные требования
- NFR-1. Задержка конвертации ≤ 150 мс для 500 символов (без учёта ожидания модификаторов).
- NFR-2. Потребление в простое: ≤ 1% CPU, ≤ 80 МБ RAM (без песочницы; песочница запускается по требованию).
- NFR-3. Нет сетевых запросов во время работы. Проверяется тестом и CSP/capabilities.
- NFR-4. Текст пользователя не попадает в логи, файлы, crash-репорты.
- NFR-5. Приложение работает без прав администратора.
