## 1. Главная развилка: без сервера vs. с сервером

| ID | Кандидат | Без сервера (совместимо с «нет сети в runtime») | Требует сервер → **КОНЦЕПЦИЯ, владелец** |
|---|---|---|---|
| E-01 | Центральное управление | ADMX/ADML + HKLM-политики; Intune (ADMX ingestion / OMA-URI, как PowerToys [R]); GPO; ConfigMgr baselines | облачная консоль управления парком |
| E-02 | Корпоративные лицензии | подписанный файл лицензии организации (site/объём, срок), офлайн; true-up по договору | онлайн-активация, пул/плавающие лицензии, отзыв в реальном времени |
| E-03 | Управление устройствами/пользователями | через MDM заказчика (группы AD/Entra → разные политики) | реестр устройств у вендора, SSO/SCIM |
| E-04 | Центральная конфигурация | слоистая модель: политика HKLM > подписанный org-конфиг (`%ProgramData%`) > пользователь | облачная доставка конфигурации |
| E-05 | Корпоративные макросы | подписанный org-ключом пакет; allow-list хэшей; «только макросы организации» | облачная библиотека/синхронизация |
| E-06 | Политики безопасности | запреты через HKLM (Macro Studio, буфер, W2, Enter/Tab, минимальный набор исключений) | — |
| E-07 | Офлайн-развёртывание | MSI + WebView2 offline/fixed runtime, офлайн-лицензия, офлайн-документация | — |
| E-08 | Управление обновлениями | подписанные MSI, канал LTS/stable, supersedence в Intune/ConfigMgr, winget; локальное «версия вне поддержки» по дате | сервер обновлений / автообновление (NG-7) |
| E-09 | Консоль администратора | локальный редактор политик/пакетов (десктоп, без сети), генерирует ADMX-значения/подписанные файлы | веб-консоль |
| E-10 | Организационная поддержка | SLA, контакт, уведомления о безопасности **вне продукта** (почта/RSS/GitHub Advisories) | клиентский портал (вне продукта; не runtime) |
| E-11 | ИТ-документация | deployment guide, справочник политик, security whitepaper, SBOM, data-flow statement, гайд WDAC/AppLocker | — |
| E-12 | SSO/SCIM, централизованная отчётность у вендора | — | **только с сервером**; спрос подтверждён лишь у SaaS (Text Blaze/TextExpander Enterprise [R]) |
| E-13 | VDI/RDS/мультисессия (Citrix, AVD) | да, но есть конфликт с текущим контрактом буфера (см. карточку) | — |
| E-14 | Документы доступности для закупок (EN 301 549 / VPAT-подобный отчёт) | да | — |

**Вывод [A]:** весь набор Enterprise первой волны (E-01…E-11, E-13, E-14) достижим **без какого-либо облачного сервиса**. Сервер нужен только E-12 и «облачным» вариантам E-01/02/03/05/09. Рекомендация — не менять концепцию до подтверждённого спроса; «нет сети» само по себе — enterprise-аргумент (изолированные сети, нет облачного вендора в анкете ИБ).

## 2. Карточки

### E-01. Центральное управление (ADMX + Intune + GPO + ConfigMgr)
1. **Аудитория:** средние и крупные организации с AD/Entra, Intune, ConfigMgr.
2. **Проблема:** настройки на тысячах ПК должны быть едиными и неизменяемыми пользователем.
3. **Спрос:** PowerToys — ADMX с 0.64, глобальное/поштучное включение утилит, Intune OMA-URI [R learn.microsoft.com/windows/powertoys/grouppolicy]. У переключателей — не найдено. MI-16 [V].
4. **Конкуренты:** PowerToys (бесплатно); PhraseExpress — Client Manager + SQL Server [R]; TextExpander/Text Blaze — облачные админ-функции [R].
5. **Готовность платить:** у крупных — в составе enterprise-соглашения; отдельно — низкая [A].
6. **Ценность:** Высок. для ИТ.
7. **Сложность:** M–L — полный набор политик (B-03 + E-06), ADML на нескольких языках, проверка ingestion в Intune, документация, тесты на матрице Win10/11.
8. **Поддержка:** Средн.
9. **Производительность:** пренебрежимо.
10. **Безопасность:** политики только сужают права; чтение только HKLM\Software\Policies; UI показывает «управляется организацией».
11. **Право:** ПДн нет.
12. **Коммерция:** Средн.–Высок. как «входной билет» в enterprise.

### E-02. Корпоративные лицензии (enterprise / site agreement, офлайн)
1. **Аудитория:** закупки крупных организаций, госсектор (вне РФ, см. ниже).
2. **Проблема:** учёт мест, многолетние договоры, изолированные сети.
3. **Спрос:** PhraseExpress — именные + конкурентные лицензии, объёмные скидки [R]; Typinator — > 20 лицензий через продажи [R]; JetBrains — офлайн-коды [R].
4. **Конкуренты:** см. выше.
5. **Готовность платить:** не проверена для переключателя.
6. **Ценность:** юридическая.
7. **Сложность:** M (тот же формат, что B-01, + поля site/срок/период поддержки).
8. **Поддержка:** Средн.–Высок. (договоры, тендеры, счета).
9. **Производительность:** —.
10. **Безопасность:** ключ вендора; лицензия не должна быть «выключателем» безопасности — истечение лицензии **не** отключает исправления безопасности (CRA: бесплатные обновления безопасности в период поддержки [V register R-03]).
11. **Право (для CLO + CISO + PA — совместная проверка по V4 п.9):** B2B EULA, ответственность, период поддержки ≥ 5 лет (CRA ст.13(8)), налоги; РФ-госсектор: ПП 1236 (реестр) — для иностранного правообладателя закрыт [R/A]; санкции (N-8).
12. **Коммерция:** Высок., если модель «платно для организаций» выбрана.
**Онлайн-лицензирование — КОНЦЕПЦИЯ.**

### E-03. Управление устройствами и пользователями
1. Аудитория: крупные ИТ.
2. Проблема: разные настройки для отделов/ролей.
3. Спрос: у SaaS — SCIM/SSO в Enterprise [R]; для on-device продуктов — нацеливание делает MDM [A].
4. Конкуренты: Text Blaze Enterprise (SAML SSO, SCIM), TextExpander Growth/Enterprise [R].
5. Готовность платить: у SaaS доказана; у KeySwitch без облака — не применимо.
6. Ценность: Средн.
7. Сложность: S без сервера (документация «как нацелить политики группами AD/Entra»); XL с сервером.
8. Поддержка: Низк. без сервера.
9. Производительность: —.
10. Безопасность: собственный реестр устройств у вендора = новые данные и поверхность атаки.
11. Право: реестр устройств/пользователей у вендора → вендор становится обработчиком ПДн (DPA, GDPR) — существенное изменение правового профиля.
12. Коммерция: Низк. без сервера; Средн. с сервером, ценой концепции.
**Рекомендация:** без сервера — «через ваш MDM».

### E-04. Центральная конфигурация (слоистая, подписанная)
1. Аудитория: средние/крупные.
2. Проблема: кроме запретов нужны значения: хоткеи, профили приложений, языковые пары по офисам.
3. Спрос: Средн. по аналогии (Espanso — конфиг-файлы и git [R]; PhraseExpress — общие файлы на NAS [R]).
4. Конкуренты: см. выше.
5. Готовность платить: в пакете.
6. Ценность: Средн.–Высок.
7. Сложность: M — порядок слоёв, подпись org-ключом (публичный ключ организации — в HKLM), валидация схемы.
8. Поддержка: Средн.
9. Производительность: пренебрежимо.
10. Безопасность: подменённый конфиг → подпись; конфиг не может снять D-05 исключения и не может разрешить запрещённое политикой.
11. Право: нет ПДн.
12. Коммерция: Средн.

### E-05. Корпоративные макросы
1. Аудитория: поддержка, колл-центры, юр./финансовые отделы.
2. Проблема: единые шаблоны и трансформации; запрет пользовательских скриптов.
3. Спрос: высок. у экспандеров (общие библиотеки) [R]; для KeySwitch — не проверен.
4. Конкуренты: TextExpander/Text Blaze (облако), PhraseExpress (SQL), Typinator (NAS); у всех — без песочницы [V AGENT 10 для Espanso/PhraseExpress].
5. Готовность платить: Средн.–Высок. [A].
6. Ценность: Высок. для целевых ролей.
7. Сложность: L — B-04 + режим «только подписанные макросы организации» + allow-list хэшей исходников.
8. Поддержка: Высок.
9. Производительность: как B-04.
10. **Безопасность:** ИБ блокирует интерпретаторы скриптов (MITRE T1059.010, рекомендация — application control [R attack.mitre.org]); для enterprise нужно: отдельный подписанный `ks-sandbox.exe` (правило издателя в WDAC), режим «песочница не запускается вообще», whitepaper о песочнице (LPAC, Job Object, нет сети/ФС). Пересмотр D-07 → владелец; расширение модели угроз → CISO.
11. Право: шаблоны — данные заказчика; вендор их не получает.
12. Коммерция: Высок.; конкурентная уникальность — «макросы, которые ИБ может разрешить».

### E-06. Политики безопасности
1. Аудитория: CISO финансов, юристов, госсектора, медицины.
2. Проблема: минимизировать поверхность: без буфера, без макросов, без вставки через буфер, только выделение.
3. Спрос: Средн. по аналогии с PowerToys (отключение утилит) [R]; требования ИБ к инструментам с доступом к тексту [A].
4. Конкуренты: PowerToys; у переключателей — нет.
5. Готовность платить: в пакете.
6. Ценность: Высок. для допуска в регулируемые среды.
7. Сложность: M. Набор [A]: `MacroStudio=Disabled`; `MacroClipboardRead=Deny`; `MacroEnterTab=Deny`; `WriteViaClipboard(W2)=Deny`; `Scope=SelectionOnly`; принудительные исключения (exe-список); `LocalDiagLog=Off|CodesOnly`; запрет изменения хоткея.
8. Поддержка: Низк.–Средн.
9. Производительность: —.
10. Безопасность: **политики только ужесточают**; ни одна политика не может отключить D-05/D-14/«нет сети». **Рекомендация ⚑:** запретительные политики безопасности — бесплатны для всех (продавать «безопасность» противоречит V4 п.5 «безопасность не снижается ради монетизации») [A → владелец].
11. Право: нет ПДн.
12. Коммерция: Низк. напрямую (если бесплатно), Высок. косвенно.

### E-07. Офлайн-развёртывание (изолированные сети)
1. Аудитория: оборона, промышленность, финансы, госсектор.
2. Проблема: нет интернета/CDN; запрещена онлайн-активация.
3. Спрос: Средн. [A]; аналоги — JetBrains offline [R], Typinator «интернет только для лицензии и обновлений» [R] (KeySwitch — сильнее).
4. Конкуренты: облачные экспандеры здесь не работают [A].
5. Готовность платить: у этого сегмента — выше среднего [A].
6. Ценность: Высок. для сегмента.
7. Сложность: M — MSI с WebView2 offline (~127 МБ) или fixed runtime (~180 МБ; тогда обновление WebView2 — на вендоре) [R tauri docs]; без bootstrapper (тот молча падает без CDN [R]).
8. Поддержка: Средн.
9. Производительность: размер установщика; fixed runtime — память не разделяется с системным WebView2 [A].
10. Безопасность: fixed WebView2 = ответственность вендора за патчи Chromium (CVE) — **существенный риск**, CISO; предпочтительно Evergreen offline.
11. Право: распространение WebView2 runtime — условия Microsoft (CLO/AGENT 16).
12. Коммерция: Средн.

### E-08. Управление обновлениями
1. Аудитория: ИТ крупных организаций.
2. Проблема: обновлять кольцами, тестировать, не допускать самообновления.
3. Спрос: Intune EAM — supersedence и авто-обновление каталога (GA 06.2026 по Recast) [R]; self-updating apps требуют сетевых правил к вендору [R learn.microsoft.com] — это минус для ИТ [A].
4. Конкуренты: PowerToys — winget/MSI; Kright — подписанное автообновление [V AGENT 10].
5. Готовность платить: за LTS/расширенную поддержку — да у крупных [A].
6. Ценность: Высок.
7. Сложность: M — каналы stable/LTS, номера версий, release notes с разделом безопасности, подписанные MSI, манифест winget; политика `UpdateNotice=Off`.
8. Поддержка: **Высок.** — LTS = бэкпорт исправлений.
9. Производительность: —.
10. Безопасность: канал уведомления об уязвимостях вне продукта (CVD, GitHub Security Advisories); подпись всех артефактов.
11. Право: **снимает часть блокера B-2** (CRA/DCD требуют доставки обновлений) для B2B — доставку делает ИТ заказчика [V register B-2; A]. Для B2C блокер остаётся.
12. Коммерция: Средн.–Высок. (LTS — классический enterprise-дифференциатор).
**Сервер обновлений у вендора — КОНЦЕПЦИЯ (NG-7).**

6. Ценность: Средн.

8. Поддержка: Средн.
9. Производительность: —.

11. Право: нет ПДн (локально).
12. Коммерция: Средн.
**Веб-консоль — КОНЦЕПЦИЯ.**

### E-12. SSO/SCIM и централизованная отчётность у вендора — **КОНЦЕПЦИЯ**
1. Аудитория: крупные с облачными стеками.
2. Проблема: вход и учёт пользователей в облачном сервисе.
3. Спрос: есть только у SaaS (Text Blaze Enterprise SAML/SCIM/аудит; TextExpander SSO/SCIM на верхних уровнях) [R].
4–5. Конкуренты/WTP: как у SaaS.
6. Ценность: для KeySwitch без облачной учётки — **нет смысла**.
7. Сложность: XL (сервер, учётки, SLA доступности, сертификация).
8. Поддержка: Высок.
9. Производительность: —.
10. Безопасность: вендор начинает хранить данные клиентов; появляется облачная поверхность атаки; конфликт с принципом «нет сети/телеметрии».
11. Право: обработчик ПДн, DPA, трансграничная передача, SOC 2 ожидается.
12. Коммерция: потенциально Высок., но ценой ядра позиционирования. **Рекомендация:** не предлагать.

### E-13. VDI/RDS/мультисессия (Citrix, Azure Virtual Desktop)
1. Аудитория: колл-центры, банки, госсектор — часто работают в VDI [A].
2. Проблема: установка в образ, мультисессия, перенаправленный буфер.
