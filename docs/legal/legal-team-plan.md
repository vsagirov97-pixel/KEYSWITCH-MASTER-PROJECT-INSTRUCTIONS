# План юридической команды и процедура legal review

Автор: AGENT 12 CLO · Дата: **2026-11-10** · Связано: `docs/TEAM_STRUCTURE.md` (Legal & Compliance — «специалисты по запросу CLO»), `docs/master-instructions-v3.md` пп. 4–5, 9–11.

## 1. Принципы
- CLO — AI-директор, **не лицензированный юрист**. AI-специалисты Legal-команды готовят анализ и черновики; **существенные выводы подтверждает квалифицированный человек-юрист** (вопросы — §3).
- Привлечение внешних юристов — **платная услуга → согласование владельца** (V3 п. 11). CLO готовит точные вопросы, чтобы минимизировать часы.
- Ревью — **риск-ориентированное** (V3 п. 5): не каждая правка, а по триггерам §4.

## 4. Процедура legal review задач

### 4.1 Триггеры (задача получает статус `Legal Review` до `Done`)

| ID | Триггер | Уровень | Кто проверяет |
|---|---|---|---|
| LT-1 | Любая **сетевая** функция, обработка данных вне устройства, новый вид хранимых данных (вкл. списки слов пользователя MI-21), экспорт диагностики, crash-reporting, WER | **Обязательный, блокирующий** | CLO (+ CISO) |
| LT-2 | Новая/обновлённая **зависимость**, wasm-артефакт, шрифт, иконки, данные, корпус, раскладка из внешнего источника | Обязательный (быстрый — по реестру; лицензии вне allow-list `deny.toml` → полный) | LS-1 / CLO |
| LT-3 | Изменение **установщика, подписи, автозапуска, обновлений**, канала распространения (Store, winget, сайт) | Обязательный | CLO + AGENT 09 |
| LT-4 | Публичные **тексты**: UI о приватности/безопасности, README, сайт, маркетинг, упоминания конкурентов, «О программе», EULA, политика конфиденциальности | Обязательный | CLO / LS-3 |
| LT-5 | Функции с **ML/AI**, автопереключение, «умное» исправление, обучение на данных пользователя | Обязательный | CLO |
| LT-6 | Обмен контентом между пользователями (импорт/каталог макросов, синхронизация, форум) | Обязательный, блокирующий | CLO |
| LT-7 | **Монетизация**: платные функции, лицензионные ключи, триалы, цены, регионы | Обязательный, блокирующий; человек-юрист | CLO + HL-1 |
| LT-8 | Выбор **стран** распространения, языков, название/бренд/логотип | Обязательный | CLO (+ HL-2) |
| LT-9 | Релиз (GATE 11) | Обязательный, блокирующий | CLO |
| — | Внутренний рефакторинг, тесты, CSS, документация без внешних обязательств | **Не требуется** | — |

### 4.2 Порядок
1. Исполнитель/руководитель отмечает триггер в задаче (поле «Legal: LT-x»). Project Director при планировании проверяет пропуски.
2. CLO (или назначенный LS) даёт заключение в задаче: **PASS / PASS с условиями / BLOCK**, со ссылкой на акт/статью/лицензию, датой проверки и статусом источника (VERIFIED/UNVERIFIED).
3. BLOCK может снять только CLO после устранения или **владелец** при эскалации (Project Director отменить не может — V3 п. 4).
4. Вопросы, требующие человека-юриста, — в реестр L-Q с пометкой срочности; задача остаётся `Blocked` только если вопрос блокирующий.
5. Срок ответа CLO: быстрый (LT-2 по реестру) — в том же цикле; полный — до следующего gate.
6. Итог фиксируется в `docs/LEGAL_COMPLIANCE_REGISTER.md` / `docs/LICENSE_REGISTER.md` (история изменений).

### 4.3 GATE 11 (Legal) — критерии выхода (черновик)
- R-7 закрыт решением + атрибуция/лицензия данных в продукте;
- `THIRD_PARTY_NOTICES` сгенерирован из фактической сборки и включён в установщик/«О программе»;
- решение по названию (B-3) и, при сохранении имени, заключение HL-2;
- лицензия кода (MI-19) и EULA/политика конфиденциальности утверждены владельцем; при монетизации — проверены HL-1;
- CRA-чек-лист (если применимо по L-Q3) пройден совместно с CISO; SBOM и CVD-политика опубликованы;
- все публичные заявления о приватности подтверждены CISO;
- открытые L-Q без ответа — явно приняты владельцем как остаточный риск (V3 п. 11; Critical/High — только владелец).
