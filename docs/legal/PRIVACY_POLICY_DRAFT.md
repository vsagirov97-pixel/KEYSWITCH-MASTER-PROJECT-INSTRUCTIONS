### А.2 Роль разработчика в P-2 (проверка обновлений) — [ЮРИСТ]

1. **Собственный хост с логами** — разработчик определяет цели и средства обработки IP → **контролёр** (ст. 4(7)). Хостинг-провайдер — обработчик (ст. 28, нужен DPA).
2. **GitHub Releases как хост.** GitHub обрабатывает IP и логи **для своих целей** (безопасность, предотвращение злоупотреблений, статистика) как **самостоятельный контролёр** по GitHub General Privacy Statement (UNVERIFIED — docs.github.com недоступен). Разработчик не получает IP-логов скачиваний (доступен только агрегированный счётчик загрузок релиза — UNVERIFIED). Однако разработчик **решает, что приложение будет обращаться к GitHub**, — по аналогии с CJEU C-40/17 *Fashion ID* (29.07.2019; встраивание плагина, передающего данные третьему лицу → совместный контроль на этапе сбора и передачи) возможна **совместная ответственность (ст. 26) в части инициирования передачи IP**. Риск оценивается CLO как **средний/низкий** (передача технически неизбежна для любой загрузки; цель — исключительно доставка обновлений), но квалификация требует юриста.
3. **Передача в третьи страны:** GitHub, Inc. — США. Основание — EU-US Data Privacy Framework (решение Комиссии 2023/1795; участие GitHub/Microsoft в DPF — UNVERIFIED) или SCC. Статус DPF после оспаривания в Общем суде ЕС (дело *Latombe*, T-553/23) — проверить на дату публикации. **[ЮРИСТ]**
4. **Вывод CLO:** предпочтителен **собственный статический хост в ЕС с выключенным логированием IP** (или логи ≤ 7 дней с усечением IP) — тогда разработчик контролёр с минимальной обработкой и без передачи в США. GitHub допустим при прозрачном раскрытии (раздел Б.4). Выбор — владелец + CISO (целостность/доступность) в `UPDATE_SECURITY_ARCHITECTURE.md`.

### А.4 Минимизация (ст. 5(1)(c), ст. 25) — требования к проекту обновлений (передать в `UPDATE_SECURITY_ARCHITECTURE.md`)

- **MIN-1** Никаких идентификаторов установки, пользователя, устройства, лицензионных ключей, хешей оборудования в запросе.
- **MIN-2** Не добавлять собственные HTTP-заголовки; `User-Agent` — без версии, имени пользователя/компьютера/сборки ОС (в проекте: `KeySwitch-Updater`; без ETag/cookies — соответствует).
- **MIN-3** URL: по возможности статический манифест (`latest.json`) без `{{current_version}}`; выбор пакета по платформе — на клиенте. Если подстановки нужны — только `{{target}}`/`{{arch}}`.
- **MIN-4** Никаких данных о результатах обновления, ошибках, сбоях не отправлять («VERIFY» по V7 — только локально).
- **MIN-5** Частота фоновой проверки — не чаще необходимого (предложение: при запуске + раз в 24 ч; EMERGENCY — тот же запрос), джиттер без идентификаторов.
- **MIN-6** Собственный хост: логирование IP выключено или IP усечён, срок хранения логов ≤ 7 дней (предложение CLO; для защиты от DDoS допустимо до 30 дней — обосновать в LIA).
- **MIN-7** Выключатель для пользователя и для администратора (политика/реестр, MDM на macOS); корпоративные ограничения не обходятся (V7 §3). **Расхождение с проектом:** `UPDATE_SECURITY_ARCHITECTURE.md` §11/§19 — пользователь может перейти на «только уведомлять», полное отключение — открытый вопрос владельцу. **Позиция CLO:** полное отключение пользователем (хотя бы в «Дополнительно», с предупреждением) **обязательно** — это реализация права возражения (ст. 21 GDPR), «ясного механизма отказа» CRA Прил. I ч. I п. 2(c) и снижение ePrivacy-риска. Режим «только уведомлять» всё равно выполняет сетевой запрос и отказом не является.
- **MIN-8** Прокси: соблюдать системные настройки прокси (корпоративная среда) — не скрытый канал.

### Б.2 Коротко
- KeySwitch исправляет текст **на вашем компьютере**. Текст, который вы исправляете, содержимое буфера обмена, ваши макросы, настройки и журнал диагностики **никуда не отправляются** и нам недоступны.
- У KeySwitch **нет телеметрии, аналитики, рекламы, аккаунтов и отчётов о сбоях**.
- Единственное сетевое соединение, которое делает KeySwitch, — **проверка и загрузка обновлений**. Оно включено по умолчанию, чтобы вы быстро получали исправления безопасности, и его можно выключить (раздел Б.4).
- Компоненты операционной системы (например, Microsoft Edge WebView2 Runtime в Windows, WebKit и службы Apple в macOS, Windows Update) могут сами обращаться в сеть по правилам Microsoft или Apple; KeySwitch этим не управляет и никаких данных через них не передаёт. **[проверить истинность — CISO, SEC-38; LEGAL R-07 UCPD]**

### Б.3 Обработка на вашем устройстве
KeySwitch читает текст в активном поле или выделении **только когда вы нажимаете горячую клавишу** и только чтобы преобразовать его. Поля паролей и исключённые приложения не читаются. Временное использование буфера обмена помечается так, чтобы не попадать в историю буфера и облачную синхронизацию; исходное содержимое буфера можно восстановить вручную.
Локальный журнал диагностики хранит только технические сведения (время, имя программы, результат, код причины) — **без текста** — на вашем устройстве [СРОК/ОБЪЁМ, напр. последние 1 000 записей]; вы можете его очистить в настройках.
Мы не являемся контролёром этих данных: они остаются под вашим контролем. Если вы используете KeySwitch на рабочем компьютере, правила обработки определяет ваш работодатель. **[ЮРИСТ — L-Q1]**

### Б.4 Проверка и установка обновлений
**Что происходит.** При запуске и периодически в фоне (примерно [раз в 24 часа]) KeySwitch запрашивает у сервера обновлений файл с описанием последней версии; если есть подходящее обновление, загружает пакет, проверяет его цифровую подпись и устанавливает. Критические и важные обновления безопасности могут устанавливаться автоматически в безопасный момент, без отдельного подтверждения; об установке вы будете уведомлены.
**Какие данные при этом передаются.** Как и при любом подключении к интернету, сервер получает **ваш IP-адрес** и время запроса. Кроме того, сервер видит, что запрос сделан программой KeySwitch (заголовок `KeySwitch-Updater`, без номера версии), и какой файл запрошен [одинаковые пути для всех пользователей — по проекту]. **Мы не передаём** идентификаторы устройства или пользователя, текст, настройки, журналы, сведения о программах, которые вы используете.
