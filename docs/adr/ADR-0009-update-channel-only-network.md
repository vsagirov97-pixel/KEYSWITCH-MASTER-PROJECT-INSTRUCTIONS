# ADR-0009 — Канал обновлений — единственная сеть в runtime

Статус: **Accepted (решение владельца D-25); реализация — Proposed** · Дата: 2026-11-10 · Решения: D-25 (заменяет D-22(4)), V7 §3 · Автор: AGENT 03

## Контекст
Принцип «нет сети в runtime» защищал пользовательский текст; но без обновлений уязвимости (Wasmtime, WebView2-обвязка) остаются у пользователей (SEC-32).

## Проблема
Любой сетевой код в процессе с пользовательским текстом — канал утечки; обновление — канал доставки вредоносного кода.

## Альтернативы
1. Без сети, только локальное напоминание о возрасте сборки (SR-63) — не выполняет V7 §3.
2. Сеть в основном процессе (Tauri-плагин) — TLS-стек рядом с текстом.
3. **Единственный сетевой канал — отдельный процесс `ks-updater` с минимальными правами, только GET подписанных метаданных/пакетов с утверждённых хостов.**

## Решение
Обновления включены по умолчанию (D-25); отключаемы администратором; основной процесс и песочница не содержат сетевого кода; запрос без пользовательских данных и идентификаторов; модель доверия и правила — `UPDATE_SECURITY_ARCHITECTURE.md`.

## Обоснование
Изоляция процесса сохраняет свойство «процесс с текстом не ходит в сеть» и делает сеть проверяемой (SR-90 по PID).

## Последствия
- SR-90 переформулируется (исключение для `ks-updater` с белым списком хостов) — CISO.
- Формулировка правила CLAUDE.md №2 уточняется владельцем.
- Хост видит IP — раскрытие в Privacy Policy (CLO).

## Проверка
GATE 10: тест соединений по процессам; CISO и CLO одобряют проект.
