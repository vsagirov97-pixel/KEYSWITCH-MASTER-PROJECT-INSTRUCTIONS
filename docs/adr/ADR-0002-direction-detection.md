# ADR-0002 — Направление конвертации по составу текста

Статус: **Accepted** · Дата: 2026-11-10 · Решения: D-02, D-20, D-19(b), D-21 · Автор: AGENT 03

## Контекст
По хоткею нужно понять, в какую сторону конвертировать: EN→RU или RU→EN.

## Проблема
Текущая системная раскладка часто уже переключена пользователем после ошибки — если брать направление из неё, конвертация пойдёт «не туда» (V3 §6.3 в буквальном прочтении).

## Альтернативы
1. Только по активной раскладке — ломает сценарий «уже переключил».
2. Спрашивать пользователя каждый раз — медленно, противоречит продукту.
3. **По составу текста (буквы какого алфавита и какая модель языка правдоподобнее); раскладка — только при равенстве.**

## Решение
`ks-core::Converter::detect` оценивает исходный текст и кандидат по моделям языков; активная раскладка цели передаётся как tie-breaker. Смешанный текст → окно выбора (ADR-0007). Низкая уверенность → отказ без диалога, причина видна в трее/Диагностике (D-19(b), подтверждено V4).

## Обоснование
Состав текста — самый надёжный сигнал и не зависит от ОС; ядро не получает ОС-данных, кроме необязательной подсказки.

## Последствия
- Короткие слова (1–2 буквы) часто дают низкую уверенность → отказ.
- Для UWP/консоли раскладка цели неизвестна → только состав текста.

## Проверка
Тесты `ks-core` на направления и tie-breaker; ручная приёмка сценария «пользователь уже переключил раскладку» (D-10).
