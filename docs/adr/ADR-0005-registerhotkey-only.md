# ADR-0005 — Горячие клавиши только через `RegisterHotKey`, без хуков

Статус: **Accepted** · Дата: 2026-11-09 · Решения: D-14, правило CLAUDE.md №8, SEC-24-R (CISO) · Автор: AGENT 03

## Контекст
Конвертация и макросы запускаются глобальными сочетаниями клавиш.

## Проблема
Низкоуровневый хук клавиатуры (`WH_KEYBOARD_LL`) видит **все** нажатия, включая пароли, — по сути кейлоггер: риск утечки, AV-эвристики (R-A16), потеря доверия.

## Альтернативы
1. `SetWindowsHookEx(WH_KEYBOARD_LL)` — гибко, но видит весь ввод.
2. Raw Input sink — то же по сути.
3. `tauri-plugin-global-shortcut`/`global-hotkey` — внутри тоже `RegisterHotKey`, но события идут через цикл tao и JS-API.
4. **Собственный поток T1 с `RegisterHotKey` + `MOD_NOREPEAT`.**

## Решение
Только `RegisterHotKey` в выделенном STA-потоке T1; сочетание обязано содержать не-модификаторную клавишу; Win и F12 запрещены; проверка AltGr-конфликтов через `VkKeyScanEx`. Окно выбора языка использует временные `RegisterHotKey` для `1/2/Esc` (ADR-0007). На macOS — Carbon `RegisterEventHotKey`, без event tap.

## Обоснование
ОС доставляет только зарегистрированное сочетание; остальной ввод KeySwitch не видит.

## Последствия
- Нельзя обнаружить физический ввод во время операции (SR-21 заменено проверкой между пакетами).
- Синтетический запуск хоткея процессом того же пользователя неотличим — принят CISO как Medium.

## Проверка
Ревью импортов (`SetWindowsHookEx` отсутствует — проверка в CI); unit валидатора; Windows CI с немецкой раскладкой (SEC-24).
