# ADR-0004 — Контракт буфера обмена: без «слепого» восстановления

Статус: **Accepted** · Дата: 2026-11-10 · Решения: Q-1 (CISO, `SECURITY_REVIEW.md` §4.1), D-13, D-26 (V7 §10.6) · Автор: AGENT 03

## Контекст
Метод W2 (ADR-0003) временно кладёт исправленный текст в буфер и посылает Ctrl+V; прежнее содержимое буфера пользователя нужно сохранить.

## Проблема
Приложение читает буфер асинхронно. Восстановление «по таймеру» может вставить в чат **прежний** буфер (часто пароль из менеджера) — утечка (High). Отсутствие сигнала ≠ «вставки не было».

## Альтернативы
1. Восстанавливать через фиксированную задержку — гонка (R-A2).
2. Восстанавливать при отсутствии сигнала — та же гонка (позиция FR §5.10 шаг 5, отозвана).
3. **Восстанавливать только при подтверждённом потреблении; иначе оставить исправленный текст и дать ручное восстановление.**

## Решение
Snapshot только белого списка форматов (≤ 16 МБ); временные данные с метками D-13; `WM_RENDERFORMAT` до Ctrl+V → прервать W2; после Ctrl+V сигнал принимается только от процесса цели/брокера профиля; восстановление — только при сигнале **и** пост-проверке `Yes` (seq под `OpenClipboard`). Нет сигнала → не восстанавливать: исправленный текст остаётся, действие «Вернуть буфер» доступно 120 с, снимок в обнуляемой памяти. При RDP и чувствительном исходном буфере W2 запрещён.

## Обоснование
Потеря прежнего буфера восстановима пользователем (Medium); вставка пароля третьей стороне — нет (High). Соответствует V7 §10.6 «не уничтожать исходные данные без подтверждения».

## Последствия
Редкая утрата прежнего буфера, если пользователь не нажмёт «Вернуть буфер» (риск утраты данных — владелец информирован, `SECURITY_REVIEW.md` §5 п.6).

## Проверка
S-2: цель читает с задержкой 0/50/500/2000 мс, сторонний слушатель, 100 прогонов — прежний буфер ни разу не в поле (SEC-10).
