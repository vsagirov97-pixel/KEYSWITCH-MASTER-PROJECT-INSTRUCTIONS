# ADR-0003 — Методы записи W1/W3/W2, без `ValuePattern.SetValue`

Статус: **Accepted** · Дата: 2026-11-10 · Решения: D-12, D-19(c), CISO §4.7 (порог W3) · Автор: AGENT 03

## Контекст
Исправленный текст нужно записать в чужое поле так, чтобы Ctrl+Z возвращал исходный текст и ничего не «отправилось».

## Проблема
`ValuePattern.SetValue` заменяет всё значение, обычно не создаёт шаг Undo, ломает форматирование и может затронуть больше, чем выделено. Ввод через `SendInput` с `\n` в чатах = отправка сообщения.

## Альтернативы
1. `SetValue` — просто, но нарушает D-12.
2. Только вставка через буфер — затрагивает данные буфера пользователя (ADR-0004).
3. Только `SendInput` — медленно на длинном тексте, гранулярный Undo.
4. **Порядок W1 → W3 → W2 → отказ.**

## Решение
- W1: `EM_REPLACESEL(fCanUndo=TRUE)` — только класс Win32 Edit (RichEdit — после теста RTF, XR-03).
- W3: `SendInput` Unicode — длина ≤ порога профиля (по умолчанию 200), без `\n`/`\t`, пакеты ≤ 64, проверка фокуса и модификаторов перед каждым.
- W2: вставка через буфер — только по профилю приложения, по контракту ADR-0004.
- Иначе — отказ `NoSafeWriteMethod`. `SetValue` не используется.

## Обоснование
W1 даёт нативный Undo; W3 не трогает буфер; W2 — только там, где проверен сигнал потребления.

## Последствия
- Ctrl+Z может потребовать 2 шага в части программ (D-19(c), документируется).
- Профиль неизвестного приложения: `allows_paste = false`.

## Проверка
Спайк S-2 (FR §8, review-arch §4 п.4): Undo и пропускная способность при 200/1000/5000 символов; `VK_RETURN = 0` при тексте с `\n`.
