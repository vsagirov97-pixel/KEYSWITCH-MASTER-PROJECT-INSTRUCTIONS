# ADR-0006 — Песочница макросов: Wasmtime в отдельном процессе с минимальными правами, ноль preopen

Статус: **Accepted** · Дата: 2026-11-10 · Решения: D-08, XR-07 и Q-9 (CISO §4.4, §4.6), D-18 · Автор: AGENT 03

## Контекст
Macro Studio исполняет пользовательский JS и Python.

## Проблема
Встроенный интерпретатор в основном процессе получает доступ ко всему: буфер, ввод, файлы, сеть, пользовательский текст. Баг рантайма = полный захват.

## Альтернативы
1. Встроенные интерпретаторы (`pyo3`, `rquickjs`, `boa`) в процессе — запрещены (SR-40/62).
2. Wasm в том же процессе — один слой защиты.
3. **Wasmtime (QuickJS-ng, CPython WASI) в отдельном `ks-sandbox.exe` под LPAC/AppContainer + Job Object + win32k lockdown.**

## Решение
Wasmtime LTS 48 (≥ 48.0.8, минимальные фичи); wasm-модули собираются в CI из закреплённых SHA и встраиваются `include_bytes!` с проверкой хэша; stdlib Python — из памяти, **ни одного host-preopen**; нет сокетов/env; лимиты времени/памяти/вывода/кадра (64 КиБ гость→хост); скрипт возвращает только действия `insert/replace/keys/none`, которые `ks-engine` проверяет политикой и применяет сам; Enter/Tab и `\n`/`\t` — отдельное разрешение слота. Слот с доступом к буферу — новый процесс на каждый запуск. Гостевые crate — вне workspace.

## Обоснование
Два независимых слоя (Wasm + ОС-изоляция процесса); песочница физически не умеет трогать буфер/ввод/UIA.

## Последствия
Установщик +20–30 МБ, урезанная stdlib, время старта (замер S-3); остаточный High (обход одного слоя) принимает только владелец после S-3.

## Проверка
S-3: H-01…H-40 на `windows-latest`, unit «список preopen пуст», проверка импортов, fuzz протокола 10⁶ сообщений (SEC-01, SEC-06).
