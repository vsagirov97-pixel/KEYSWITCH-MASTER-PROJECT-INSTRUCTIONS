# ADR-0001 — Раскладки как данные по скан-кодам + языковая модель

Статус: **Accepted** · Дата: 2026-11-09 · Решения: D-01, D-15 · Автор: AGENT 03

## Контекст
Текст, набранный в неверной раскладке, нужно преобразовать в «правильный». Языков и раскладок будет больше двух (EN ↔ RU — первый шаг).

## Проблема
Таблица «символ → символ» для каждой пары языков растёт квадратично, ломается на пунктуации (`?`/`,`/`.` в RU и EN на разных клавишах) и неоднозначна там, где одна клавиша даёт разные символы.

## Альтернативы
1. Жёсткие таблицы пар в коде — быстро, но каждый язык = правка кода и тесты всех пар.
2. Системный API раскладок (`ToUnicodeEx`) в рантайме — ОС-зависимо, нельзя в `ks-core`, не работает в тестах на Linux.
3. **Данные по физическим скан-кодам (set 1) + локальная n-граммная модель языка для выбора варианта.**

## Решение
Каждая раскладка — текстовый файл `crates/ks-core/layouts/<id>.layout` (скан-код, базовый символ, Shift-символ). Конвертация идёт через физическую клавишу; неоднозначности (пунктуация) решаются частотной моделью (`data/<lang>.freq`). При низкой уверенности — отказ от замены.

## Обоснование
Новый язык = новый файл (навык `/add-layout`), без изменения кода; ядро остаётся без I/O (файлы встраиваются при сборке); поведение детерминировано и тестируется на любом хосте.

## Последствия
- Нужны источники раскладок с лицензией (CLO) и частотных данных (R-A19, CC-BY-SA — решение владельца).
- Мёртвые клавиши, AltGr и IME пока вне модели (отказ).
- macOS использует те же файлы; соответствие KLID/Input Source ID хранится в адаптере.
