# W-MAN-1 — набор для ручной проверки на вашем Windows-компьютере

Ветка: `spike/win-manual-kit` · Подготовил: AGENT 20 (Windows Platform Lead) · Дата: 2026-11-11.
Статус: **инструмент собран в CI; ручной прогон владельцем ещё не выполнялся.** Это не продукт KeySwitch, а одноразовая проверочная программа. Ничего не слито в `main`.

## 0. Коротко
- Одна программа `ks-win-manual-probe.exe`, ничего устанавливать не нужно (никаких инструментов разработчика).
- Два запуска: сначала `fixture` (~5 мин), потом `survey` (~15–25 мин). Всего **~20–30 минут**.
- В конце на Рабочем столе появится файл `KeySwitch-probe-report.txt` — его содержимое нужно вставить в чат.
- Права администратора **не нужны и запрещены**: с ними программа откажется работать.

## 1. Что программа делает и чего не делает
**Не делает никогда:** не выходит в сеть; не ставит перехватчики клавиатуры («хуки»); не внедряется в другие программы; не просит прав администратора; не добавляет и не удаляет раскладки; не записывает в отчёт ваш текст, заголовки окон, имена файлов документов, имя пользователя или компьютера.

**Режим `fixture`** — программа открывает **своё** тестовое окно (справа на экране) и проверяет на нём то, что будет делать KeySwitch: чтение поля через UI Automation (пароль не читается), замену выделенного текста и отмену (Ctrl+Z), «печать» символов, переключение между **уже установленными** у вас раскладками EN и RU (в конце возвращается исходная), горячую клавишу. Печатает **только в своё окно**; если окно теряет фокус или вы зажали Ctrl/Alt/Shift/Win — ввод сразу останавливается.
Буфер обмена: программа сначала запоминает, что в нём лежит. Если там **простой текст или пусто** — тест проводится, затем буфер восстанавливается (и только если за это время в буфер никто ничего не положил). Если там картинка, файлы, таблица и т. п. — тест буфера пропускается, буфер не трогается.

**Режим `survey`** — **только чтение**. Вы ставите курсор в поле ввода реального приложения и нажимаете `Ctrl+Alt+Shift+F12`. Программа записывает о поле только служебные сведения: имя exe-файла (например `chrome.exe`), класс окна, тип элемента, поддерживаемые интерфейсы, удалось ли получить документ и выделение, и **длину** текста (число символов, не сам текст). В полях паролей текст не запрашивается вовсе. Ничего не пишет, ничего не нажимает, буфер обмена не использует.

Что будет в отчёте (пример строки): `S3 INFO exe="WINWORD.EXE" integrity="medium" control_type="50030" framework="Win32" is_password="false" doc_len="1532" sel_len="0" ...`. Перед отправкой вы можете открыть файл и посмотреть всё сами.

## 2. Скачать программу (нужно войти в GitHub)
1. Откройте в браузере ссылку на прогон CI, которую прислал Project Director (вид `https://github.com/vsagirov97-pixel/keyswitch-master-project-instructions/actions/runs/<номер>`). Если ссылки нет: на странице репозитория → вкладка **Actions** → слева **CI** → в списке строка с веткой **spike/win-manual-kit** и зелёной галочкой → щёлкните по ней.
2. Убедитесь, что вы вошли в GitHub (справа вверху ваш аватар). Без входа файл скачать нельзя.
3. Прокрутите страницу прогона вниз до раздела **Artifacts**. Щёлкните **ks-win-manual-probe** — скачается архив `ks-win-manual-probe.zip`. Артефакт хранится 14 дней.
4. Откройте папку «Загрузки». **Щёлкните правой кнопкой по `ks-win-manual-probe.zip` → Свойства.** Если внизу вкладки «Общие» есть флажок **«Разблокировать»** — поставьте его → **ОК**. (Так Windows меньше будет предупреждать при запуске.)
5. Правой кнопкой по zip → **Извлечь все…** → **Извлечь**. Откроется папка `ks-win-manual-probe` с двумя файлами: `ks-win-manual-probe.exe` и `SHA256.txt`.

Необязательная проверка целостности: в PowerShell (п. 3) выполните `Get-FileHash .\ks-win-manual-probe.exe` — число должно совпасть с числом в `SHA256.txt` и в описании прогона на GitHub (раздел Summary, «W-MAN-1 kit»).

## 3. Открыть PowerShell в папке с программой
1. Откройте извлечённую папку в Проводнике.
2. Щёлкните правой кнопкой по **пустому месту** внутри папки → **Открыть в Терминале** (в Windows 11 26H2 пункт есть сразу; если нет — «Показать дополнительные параметры» → «Открыть окно PowerShell здесь»).
3. **Не выбирайте «от имени администратора».** В заголовке окна не должно быть слова «Администратор».

## 4. Предупреждения Windows — что делать
- **«Система Windows защитила ваш компьютер» (SmartScreen, синее окно):** программа не подписана сертификатом, поэтому Windows её не знает. Нажмите **«Подробнее»** → **«Выполнить в любом случае»**.
- **«Не удаётся проверить издателя… Запустить?»** (жёлтое окно безопасности) — нажмите **«Запустить»**.
- **Smart App Control («Интеллектуальное управление приложениями») заблокировал программу** — **ничего не отключайте**. Напишите в чат: «SAC заблокировал». Мы пришлём другой вариант.
- **Microsoft Defender сообщил об угрозе** (например «Trojan:Win32/…» или «Wacatac»): у неподписанных новых программ бывают ложные срабатывания. **Не добавляйте исключения и не восстанавливайте файл из карантина.** Сделайте скриншот уведомления, удалите скачанное и напишите в чат — разберёмся (CISO).

## 5. Запуск 1 — `fixture` (~5 минут)
1. Закройте или сверните программы, где вы набираете текст (мессенджеры, документы).
2. В окне PowerShell введите и нажмите Enter:
   ```
   .\ks-win-manual-probe.exe --i-understand fixture
   ```
3. Прочитайте текст в окне и нажмите **Enter**. Справа появится окно «KeySwitch probe - test window». Если программа попросит — **щёлкните по заголовку этого окна**. Затем **не трогайте клавиатуру и мышь**, пока идут тесты A–E (около минуты; в тестовом окне сам собой будет появляться текст — это нормально).
4. **Тест буфера (D).** Программа положит в буфер строку `KeySwitch-TEST-7731` с пометкой «не сохранять в журнал». Нажмите **Win+V**. Ничего в списке не выбирайте, закройте его клавишей **Esc**, щёлкните в окно PowerShell и ответьте буквой: `y` — строка видна в списке; `n` — журнал открылся, а строки нет (это ожидаемый правильный результат); `d` — журнал выключен (Windows предлагает его включить) или не уверены. Буквы можно вводить и в русской раскладке.
5. **Тест горячей клавиши (H).** По просьбе программы нажмите **Ctrl+Alt+Shift+F12** и подержите ~2 секунды (на ноутбуке может понадобиться ещё **Fn**).
6. Программа выведет отчёт и сохранит его на Рабочий стол. Раскладка и буфер обмена возвращаются автоматически; если программа написала, что раскладку вернуть не удалось, переключите её как обычно (Win+Пробел).

## 6. Запуск 2 — `survey` (~15–25 минут, только чтение)
1. В том же окне PowerShell:
   ```
   .\ks-win-manual-probe.exe --i-understand survey
   ```
2. Для каждого пункта списка ниже: откройте приложение → **щёлкните в указанное поле** (должен мигать курсор; можно напечатать пару слов, но **никаких паролей и личных данных**) → нажмите **Ctrl+Alt+Shift+F12** → вернитесь в окно PowerShell: появится «#N записано». Введите короткую метку из столбца «Метка» и Enter (или просто Enter).
3. Когда пройдёте список (можно не весь), введите `q` и Enter. Отчёт допишется в тот же файл на Рабочем столе.

| № | Приложение | Куда поставить курсор | Метка |
|---|------------|------------------------|-------|
| 1 | Telegram | поле ввода сообщения в любом чате (например «Избранное») | `tg msg` |
| 2 | WhatsApp | поле ввода сообщения в любом чате (например чат с самим собой) | `wa msg` |
| 3 | Chrome | поле поиска на странице (например строка поиска на google.com) | `chrome search` |
| 4 | Chrome | многострочное поле `<textarea>`: поле комментария/отзыва на любом сайте, или https://www.w3schools.com/tags/tryit.asp?filename=tryhtml_textarea — поле в правой части | `chrome textarea` |
| 5 | Chrome | адресная строка (вверху окна) | `chrome address` |
| 6 | Edge | поле поиска на странице (например bing.com) | `edge search` |
| 7 | Edge | `<textarea>` — то же, что в п. 4 | `edge textarea` |
| 8 | Word | тело документа (новый пустой документ, напечатайте пару слов) | `word body` |
| 9 | Excel | ячейка **в режиме редактирования**: выберите ячейку, нажмите **F2** (мигает курсор в ячейке) | `excel cell F2` |
| 10 | Excel | ячейка **не** в режиме редактирования: просто щёлкните по ячейке (без F2) | `excel cell` |
| 11 | Блокнот (Notepad) | основная область текста | `notepad` |
| 12 | (по желанию) любое поле **пароля** на сайте в Chrome — ничего не вводите, просто щёлкните в поле | `chrome password` |

Пункт 12 проверяет, что программа распознаёт пароль и **не запрашивает** его содержимое (в отчёте будет `treated_as_password="true"`, `doc_len="refused_password"`).

## 7. Отправить результат
1. На Рабочем столе откройте `KeySwitch-probe-report.txt` (двойной щелчок — откроется Блокнот).
2. Просмотрите: там только служебные строки (`ENV`, `A1…H1`, `S1…`). Если вдруг увидите свой текст — **не отправляйте**, сообщите об этом в чат (это будет ошибкой инструмента).
3. Ctrl+A → Ctrl+C → вставьте в чат.

## 8. Удалить всё после проверки
1. Закройте окно PowerShell.
2. Удалите папку `ks-win-manual-probe` и файл `ks-win-manual-probe.zip` из «Загрузок».
3. После отправки отчёта удалите `KeySwitch-probe-report.txt` с Рабочего стола.
4. Если в тесте D вы ответили `y`: Win+V → «…» у строки `KeySwitch-TEST-7731` → **Удалить**.
5. Корзину можно очистить. Программа ничего не устанавливает, не создаёт служб, задач, ключей автозапуска и других файлов.

## 9. Если что-то пошло не так
- «Refused: add --i-understand» — команда введена не полностью; скопируйте её из инструкции.
- «ОТКАЗ: программа запущена с правами администратора» — откройте PowerShell обычным способом (п. 3).
- Программа «зависла» / непонятное поведение — нажмите **Ctrl+C** в окне PowerShell или просто закройте окно; раскладку при необходимости верните Win+Пробел. Напишите в чат, на каком шаге это случилось.

## 10. Для команды (технические сведения)
- Код: `crates/ks-win-manual-probe` (копия обёрток из `ks-winprobe` с исправлениями S-2a review): WS-01 — номер последовательности буфера читается до `CloseClipboard`; WS-02 — snapshot по белому списку (`CF_UNICODETEXT` + синтезируемые + три метки D-13 с исходными байтами), иначе тест буфера пропускается; WS-03 — единственная точка `GetText`, отказ по `IsPassword` (ошибка = пароль) или `ES_PASSWORD`; WS-04 — только `SendMessageTimeoutW(SMTO_ABORTIFHUNG, 2 с)`; WS-05 — перед каждым пакетом W3: наше окно foreground + наш контрол в фокусе + не зажаты модификаторы; WS-06 — отказ для Cc/Zl/Zp/Cf; WS-07 — отправки виртуальных клавиш нет; `AttachThreadInput` не используется; W1 — только класс `Edit` (`GetClassNameW` и `RealGetWindowClassW`), не `ES_PASSWORD`/`ES_READONLY` (условия D-30).
- В survey не читаются заголовки окон, UIA `Name` и `Value`, полный путь exe (только имя файла); `GetText` вызывается только чтобы получить длину (буфер сразу освобождается), не более 200 000 символов.
- CI job `windows-manual-kit`: clippy, unit-тесты, release-сборка `+crt-static`, проверка отказа без `--i-understand`, grep-запрет API в crate, SHA-256 в Summary, артефакт `ks-win-manual-probe` (exe + `SHA256.txt`), 14 дней.
- Статусы отчёта: PASS/FAIL — ожидание выполнено/нет; SKIP — не проверялось (причина указана); OBSERVED/INFO — записан факт. До получения отчёта владельца все сценарии на реальном ПК — **не проверено**. Результаты survey попадут в `docs/COMPATIBILITY_MATRIX.md` как «проверено вручную (метаданные UIA)» только после разбора отчёта; это ещё не поддержка приложения (нужна проверка записи в S-2b/GATE 7).
