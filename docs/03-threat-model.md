# KeySwitch — Модель угроз (v1)

Статус: **черновик для GATE 2** · Автор: Security Analyst (независимый) · Метод: STRIDE по границам доверия

## 1. Активы
A1 текст пользователя в поле · A2 содержимое буфера обмена · A3 пароли и секреты в других полях/окнах · A4 файловая система и сеть пользователя · A5 целостность документа (случайная массовая замена) · A6 скрипт макроса и настройки.

## 2. Границы доверия
- B1: целевое приложение ↔ KeySwitch (UIA, ввод, буфер).
- B2: ядро ↔ процесс песочницы (pipe).
- B3: код скрипта ↔ Wasm-рантайм.
- B4: WebView (UI) ↔ Rust-бэкенд (Tauri IPC).
- B5: цепочка поставок (crates, npm, wasm-бинари, CI).

## 3. Угрозы и требования

| ID | Угроза | Уровень (до митигации) | Сценарий | Требование | Проверка |
|----|--------|-----------|----------|------------|----------|
| T-01 | Выход скрипта из песочницы → выполнение команд | Critical | Скрипт пытается `os.system`, `import ctypes`, `std.loadFile` | Wasmtime без WASI-preopen/сокетов + AppContainer + Job Object (D-08) | Набор враждебных скриптов в CI: fs, net, subprocess, env, ctypes, fork-bomb, бесконечный цикл, выделение 4 ГБ |
| T-02 | Выполнение команд через клавиатурный API | Critical | `keys: [Win+R, ...]` | Закрытый enum `AllowedKey` без модификаторов (D-07); проверка в ks-engine, не в песочнице | Unit-тест: любой не-белый ключ отвергается; fuzz десериализации |
| T-03 | Эксфильтрация буфера через ввод | High | Скрипт читает пароль из буфера и печатает в браузер | Доступ к буферу только по флагу слота (D-07), флаг виден в UI | Тест: без флага `clipboard == null` |
| T-04 | Утечка текста в историю/облако буфера | High | Win+V хранит конвертированный текст, синхронизирует в облако | Форматы исключения (D-13) | Windows CI: проверка наличия форматов; ручная проверка Win+V |
| T-05 | Потеря содержимого буфера | High | Восстановление стирает изображение/файлы | Snapshot + отказ при несохранимых форматах + restore_if_unchanged | Интеграционные тесты на CI с HTML/RTF/bitmap/CF_HDROP |
| T-06 | Подмена окна/поля между чтением и записью | High | Фокус сменился во время диалога смешанного текста | Re-verify HWND+PID+RuntimeId перед Write | Тест со сменой фокуса |
| T-07 | Массовая замена документа | High | Ctrl+A в Word заменяет весь документ | D-03, D-04, лимит 5 000 | Тест на тестовом окне + ручная приёмка Word |
| T-08 | Чтение поля пароля | High | Конвертация в поле пароля → текст в памяти/буфере | Проверка IsPassword до чтения | Тест на тестовом окне с ES_PASSWORD |
| T-09 | Текст в логах/крэш-дампах | Medium | Debug-лог печатает `text` | Тип `UserText` без `Debug`/`Display`, zeroize при drop; lint в CI | grep/clippy-правило + ревью |
| T-10 | WebView получает лишние права | Medium | XSS в UI → вызов опасной команды | Минимальные capabilities, строгая CSP, без shell/fs/http плагинов | Аудит `capabilities/*.json` |
| T-11 | Сетевая активность | Medium | Зависимость отправляет данные | Нет сетевых крейтов в runtime-графе; CSP; AppContainer для песочницы | `cargo tree` проверка в CI; тест на отсутствие соединений |
| T-12 | DoS через скрипт | Medium | Бесконечный цикл/память | fuel/epoch, memory limiter, Job Object, kill по таймауту | Враждебные скрипты |
| T-13 | Подмена wasm-рантаймов | Medium | Изменённый python.wasm в установке | Встраивание и проверка SHA-256 при загрузке | Тест с изменённым файлом |
| T-14 | Атака на цепочку поставок | Medium | Вредоносный crate/npm пакет | Lock-файлы, `cargo deny`/`cargo audit`, `npm audit`, pinned actions по SHA, минимум зависимостей | CI-джоб |
| T-15 | Повышение привилегий через KeySwitch | Low | Взаимодействие с окном администратора | Не повышаться, отказ для elevated (D-05) | Ручная проверка |
| T-16 | Подмена настроек/скрипта другим процессом пользователя | Informational | Процесс с правами пользователя правит SQLite | Вне модели (тот же пользователь = доверенный); скрипт всё равно в песочнице | — |

## 4. Правила для разработчиков (обязательны)
1. Пользовательский текст — только в типе `UserText`; запрещены `Debug`, `Display`, сериализация в лог.
2. Никакого `unsafe` вне `ks-platform-win`; там — каждый блок с комментарием-обоснованием.
3. Скрипт не получает никаких дескрипторов ОС; все действия выполняет ядро после политики.
4. Новая зависимость → запись в PR с назначением, лицензией и оценкой риска.

## 5. Критерии GATE 2 (безопасность)
- [ ] Архитектура реализует требования T-01…T-14.
- [ ] Спайк песочницы (S-3) прошёл набор враждебных скриптов на Windows CI.
- [ ] Открытых Critical/High рисков архитектуры нет.
