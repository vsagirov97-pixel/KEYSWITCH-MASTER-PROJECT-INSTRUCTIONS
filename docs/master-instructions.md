# KeySwitch — Master Project Instructions (от владельца продукта)

Копия исходного задания владельца. Изменения — только с его подтверждения. Уточнения владельца зафиксированы в `00-decisions.md` и имеют приоритет там, где явно уточняют пункт ниже.

## 1. Миссия
Project Orchestrator руководит командой AI-специалистов и организует полный цикл создания кроссплатформенного desktop-приложения KeySwitch: требования → проектирование интерфейса → программирование → тестирование → аудит безопасности → релиз. Вся работа — в облаке (Claude Code + GitHub). Не требовать локальной среды разработки у пользователя.

## 2. Команда
01 Project Orchestrator · 02 Product Analyst · 03 System Architect · 04 UI/UX Designer · 05 Rust/Windows Developer · 06 Frontend Developer · 07 Security Analyst (независимый, может блокировать релиз; находки: описание, критичность Critical/High/Medium/Low/Informational, сценарий эксплуатации, компоненты, рекомендация, способ проверки; не меняет код без назначения) · 08 QA Engineer (не принимает работу на слово) · 09 Build & Release Engineer.

Стек: Tauri 2, Rust, React, TypeScript, Vite, Tailwind CSS, SQLite, CodeMirror 6. Версии проверять по официальной документации. Не добавлять зависимости без необходимости.

Дизайн: стиль Professional Developer Tools (современные IDE), чистая иерархия, минималистичная навигация, качественная типографика. Темы Dark / Light / System. Языки UI: русский, английский.

## 3. Продукт
Преобразование текста, набранного в неверной раскладке. Не переводчик и не транслитератор. Пример: `Ghbdtn, rfr ltkf?` → `Привет, как дела?`

## 4. Платформы
v1: Windows 10, Windows 11. Будущее: macOS. Общее ядро не зависит от ОС; системные функции — в отдельных адаптерах.

## 5. Основная функциональность
EN→RU и RU→EN. Направление — по активной системной раскладке (уточнено D-02: по составу текста, раскладка — tie-breaker). После преобразования переключить раскладку на целевой язык. Физическое соответствие US QWERTY ↔ ЙЦУКЕН. Сохранять регистр, пунктуацию, цифры, пробелы, переносы строк, неизвестные символы. Расширение на украинский, немецкий, французский и др. без переписывания Core Engine.

## 6. Смешанный текст
Запросить целевой язык: Русский / English / Отмена. Отмена — ничего не менять. При выборе — преобразовать фрагменты исходной раскладки, сохранив корректные фрагменты целевого языка. При неоднозначности — не выполнять рискованную замену.

## 7. Активное поле ввода
Фон; максимально широкий набор приложений: браузеры, Word, Excel, Telegram, Discord, WhatsApp, Notepad, другие редакторы.
По горячей клавише: 1) активное окно; 2) активное поле; 3) всё содержимое поля; 4) проверка безопасности; 5) преобразование; 6) выделение всего содержимого поля; 7) замена; 8) переключение раскладки.
Не использовать Ctrl+A вслепую. Не изменять весь документ или веб-страницу случайно. При невозможности безопасной обработки — отменить. (Уточнено D-03, D-04, D-05.)

## 8. Курсор
Не реализовывать отдельный механизм сохранения/перемещения/восстановления курсора.

## 9. Clipboard
Временно сохранять буфер; после замены восстанавливать, если он не был независимо изменён. Форматы по возможности: Text, HTML, RTF, другие. Не гарантировать невосстановимые форматы. При риске потери данных — отменить операцию.

## 10. Hotkey Manager
Две независимые клавиши: конвертация и Macro Studio (D-06: запуск макроса). Сочетания из 2–3 клавиш (Ctrl+Q, Alt+Z, Ctrl+Alt+Q, Ctrl+Shift+Space). Проверка конфликтов и переназначение.

## 11. Macro Studio
Бесплатно — один слот: текстовый макрос / JavaScript / Python. JS и Python обязательны в v1. Редактор кода, подсветка, сохранение, проверка ошибок, выполнение по горячей клавише. Ограниченный API: только функции KeySwitch (текст, буфер, клавиатурные действия, безопасная замена). Без доступа к ФС, интернету, оболочке, произвольным системным функциям. Security Analyst проверяет реальную изоляцию обоих runtime; блокировка отдельных функций языка — недостаточная защита.

## 12. Дизайн
Разделы: Overview, Languages & Layouts, Hotkeys, Macro Studio, Settings, Diagnostics. Темы Dark/Light/System. Локализация RU/EN, расширяемая.

## 13. Фоновая работа
Системный трей; автозапуск по настройке; без уведомлений об успехе; окно выбора языка только для смешанного текста; настройки через трей; временное отключение.

## 14. Приватность
Обработка локально. Текст не отправляется на серверы, не собирается; буфер не передаётся; без скрытой телеметрии; настройки и скрипты локально.

## 15–16. Процесс
ANALYZE → PLAN → DESIGN → DEVELOP → REVIEW → TEST → SECURITY AUDIT → RELEASE. Не начинать массовую реализацию до анализа требований и архитектуры. Начальный лимит — 4 параллельных потока; у каждого одна задача и критерии завершения; не редактировать одни файлы параллельно; каждый кодовый поток — своя ветка; интеграция через PR после независимой проверки.

## 17. Quality Gates
1 Requirements · 2 Architecture (архитектор + Security) · 3 Design · 4 Core (RU↔EN тесты) · 5 Windows Integration · 6 Macro Studio (изоляция) · 7 QA (нет критических дефектов) · 8 Security (нет Critical/High) · 9 Release. Не объявлять этап завершённым только потому, что код написан.

## 18. Решения
Подтверждение владельца обязательно перед: необратимыми изменениями репозитория, слиянием в защищённую основную ветку, публикацией релиза, удалением пользовательских данных, платными внешними сервисами, изменением принципиальных требований, принятием критического остаточного риска. Не придумывать результаты тестов. Без Windows GUI — Windows CI, непроверенные UI-сценарии помечать явно.

## 19–20. Облако и отчётность
Только облако; Windows-сборка через GitHub Actions. После каждого этапа отчёт: задачи, специалисты, ветки/PR, проверенные функции, результаты тестов, дефекты, Security Review, риски, следующий этап. Не смешивать факты и предположения.

## 21. Цель
Автозамена неверной раскладки, несколько языков, глобальные горячие клавиши, надёжная системная интеграция, Macro Studio с JS и Python, профессиональный интерфейс, высокая безопасность, кроссплатформенная архитектура, возможность коммерческого развития.
**Качество, безопасность и сохранность данных важнее скорости.**

## Дополнительное указание владельца (этап анализа)
Особое внимание — технической реализуемости безопасной замены всего текста активного поля ввода в Windows 10/11. Не обещать универсальную поддержку программ без тестов. После анализа — первый технический прототип: RU↔EN Core Engine и проверка системной интеграции Windows.
