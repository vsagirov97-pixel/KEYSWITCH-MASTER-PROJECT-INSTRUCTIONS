# Beta 1 (Windows) UI notes — BL-UI-B1

Scope: conversion only. No macros, no updater UI, no payments. Source of look and wording:
`docs/research/design-system.md` (tokens copied 1:1 into `app/src/index.css`), `design-concept.md`, `pa-prd.md`.

Screenshots (mock backend, Chromium on Linux, 960x640 @2x — fonts differ from Segoe UI on Windows):
`beta1-settings-light.png`, `beta1-settings-dark.png`.

## Layout of `app/src`

| Path | What |
|---|---|
| `api.ts` | The only UI↔Rust boundary: types + `KeySwitchApi` + `api` instance |
| `api.mock.ts` | In-memory backend (no storage, no network) |
| `hotkey.ts` | Hotkey helpers (D-14 rule: 1–2 modifiers + one regular key) |

| `tray/model.ts` | `buildTrayMenu(state, t)` → JSON-serialisable `TrayMenuModel`; command ids `TrayCommand` |
| `components/` | `ui.tsx` primitives, `HotkeyCapture`, `LanguagePicker`, `OperationStatus` (+ `Toast`) |
| `settings/` | Settings window: General, Conversion, Excluded apps, About |
| `PreviewPage.tsx` | Dev-only gallery: `npm run dev` → `/?view=preview` (not in the production bundle) |

Dev-only mock overrides: `?theme=dark|light|system&lang=ru|en`.

## Backend contract (Rust)

Implemented in `app/src-tauri/src/main.rs` (BL-WIN-B1). Inside the Tauri shell `api.ts` calls these
commands; the mock serves only `npm run dev`. Settings live in `%APPDATA%\KeySwitch\settings.json`;
autostart state is read from the `HKCU` `Run` key (not stored in the file).

| `KeySwitchApi` method | Proposed command | Notes |
|---|---|---|
| `getSettings` | `get_settings` | `{ hotkey, autostart, uiLanguage, theme }` |
| `setAutostart(bool)` | `set_autostart` | error → UI rolls the toggle back and shows an inline alert |
| `setUiLanguage`, `setTheme` | `set_ui_language`, `set_theme` | tray menu must be rebuilt on language change |
| `setHotkey(hotkey)` | `set_hotkey` | returns `{ok:true}` or `{ok:false,error:"invalid"\|"reserved"\|"conflict"}`; previous hotkey stays registered on failure |
| `listExcludedApps` / `addExcludedApp` / `removeExcludedApp` | `list_/add_/remove_excluded_app` | backend re-validates the exe name (invalid name → rejected promise); `default` entries are not removable |
| `getAppInfo` | `core_version` + `getVersion()` + `build_signed` | `build_signed` returns `false` in Beta 1 (unsigned) |
| `getLastOperation` | `last_operation` | `null` before the first operation, else `{ kind, code, clipboardHeld }`: `kind` = `converted` \| `inserted` \| `nothing` \| `cancelled` \| `refused` \| `failed`; `code` = backend outcome code (`CONVERTED`, `CONVERTED_UNVERIFIED`, `NOTHING`, `CANCELLED`, a `RefusalReason`, a `FailureReason`). Rendered on the General page (card "Last operation", `LastOperationStatus`): kind pill, the `status.reason.<CODE>` message when one exists, the raw code; re-read on window focus |

`OperationOutcome` / `RefusalReason` / `FailureReason` / `LastOperation` carry reason codes only — no type on
the boundary can hold user text.

### Operation feedback (backend, BL-WIN-B1 step 2)

- No success notice. Only a refused or failed operation (and the "clipboard kept" hint, code `CLIPBOARD_HELD`)
  produces feedback: the reason message is appended to the tray tooltip and shown for 2.5 s in a small
  non-activating topmost window near the caret (`ks_platform_win::popup::notice`).
- The message texts are the UI's: the backend reads `status.reason.<CODE>` from `app/src/i18n/{ru,en}.ts` at
  compile time (`app/src-tauri/src/feedback.rs`). A backend test fails if a refusal / failure code has no
  message in either language, so a new code needs a new i18n key. Keep these values plain one-line strings
  (no escapes). The wording of the keys added for the backend codes needs designer review.
- Tray menu: the item "Restore clipboard" (command id 8) appears only while the clipboard from before an
  unconfirmed clipboard paste is held (D-26, at most 120 s). It is **not yet mirrored** in `app/src/tray/model.ts`.
- Tray icon: three embedded states (`ks_platform_win::tray_icon`, generated by
  `crates/ks-platform-win/assets/gen_tray_icons.py`, own monochrome keycap glyph): **active** (hotkey
  registered, not paused), **paused** (two bars), **attention** (exclamation mark: hotkey conflict /
  registration error or the worker could not start). The tooltip names the state
  (`tray.status.active|paused|attention`). The design source `app/src/tray/model.ts` does not model the icon.
- The language-choice popup is a native OS window (keys 1 / 2 / Esc, 10 s), not the `LanguagePicker` component.

### Macro Studio slot (backend, Beta 2 step 1 — `feat/win-beta2`)

Contract only; the Macro Studio screen is the UI developer's task. One free slot, **text macros only**
(JS / Python arrive with the sandbox, `feat/sandbox-win`). Stored in `settings.json` under `macroSlot`.

| `KeySwitchApi` method | Command | Notes |
|---|---|---|
| `getMacroSlot` | `get_macro_slot` | `{ name, enabled, hotkey \| null, type: "text", content, allowEnterTab, registered, testRunAvailable }` |
| `setMacroSlot(slot)` | `set_macro_slot` (argument `slot`) | `{ok:true}` or `{ok:false,error}`; on error the previous slot and its hotkey stay (except `save_failed`: active, not persisted) |

- Errors: hotkey `invalid` / `reserved` / `conflict` (as for the conversion hotkey; the macro hotkey can never
  equal the conversion hotkey — that is a `conflict` in both `set_hotkey` and `set_macro_slot`), `name_invalid`
  (> 64 characters or control characters), `type_unsupported`, `content_too_long` (> 5000 characters,
  `MACRO_MAX_CHARS`), `content_forbidden_chars` (control characters other than `\n` / `\t`, U+2028/2029,
  bidi controls), `content_enter_tab_not_permitted` (`\n` or `\t` while `allowEnterTab` is off — D-18, default
  off), `save_failed`.
- `registered: false` with `enabled: true` and a hotkey means Windows refused the combination at start-up
  (another app owns it): show the same "needs attention" state as for the conversion hotkey.
- `testRunAvailable` is `false` in this step: show "Test run" disabled.
- `content` is the user's own text: never put it into logs, telemetry or screenshots with real data.
- Outcome of a macro run in `last_operation`: `kind: "inserted"`, `code` `MACRO_INSERTED` /
  `MACRO_INSERTED_UNVERIFIED`; refusals use the same codes as conversion (`PASSWORD`, `EXCLUDED_APP`,
  `FORBIDDEN_CHARS` — e.g. a text with line breaks where only typing is possible, `TOO_LONG`, …) plus
  `NOT_AVAILABLE` (code macros; message key `status.reason.NOT_AVAILABLE` added, wording needs review).
- How the text is written (no UI setting): a classic `Edit` gets it directly (`EM_REPLACESEL`, line breaks only
  in multi-line fields); applications with a clipboard profile get a clipboard paste with the previous clipboard
  restored; anything else is typed (`SendInput`, at most 200 characters, no `\n` / `\t`). Enter and Tab are
  never pressed as keys. The keyboard layout is not switched.

## Deviations and simplest-option choices (need designer/owner confirmation)

1. **Result toast vs design rule "no success notifications"** (design-concept §5.1, design-system §9.10:
   toast = async errors only, never success/info). Built: `OperationStatus` (status pill + reason, usable
   in-window) and an error-only `Toast`. Neither is wired to real operations; where/if results are shown is open.
2. Navigation: 4 sidebar items (General / Conversion / Excluded apps / About) instead of the full design
   sidebar and the single scrolling Settings page; Overview, Diagnostics, Macro Studio, onboarding are out of scope.
3. Theme control (dark / light / system) added to General as in the design; default in the mock is `system`.
4. Hotkey: the capture field itself is the "change" control (§9.6). No "clear" button and no "restore previous"
   button — the hotkey can not be empty in Beta 1 and the previous one stays active on error.
5. Excluded apps: exe name typed by hand (no file dialog — no `fs` plugin). Default list in the mock is a placeholder.
6. Icons: four own minimal SVGs instead of Lucide (no new dependency); sidebar items have no icons.
7. Privacy block from the design is not shown (wording about network calls needs CLO after ADR-0011).
8. About: licence and third-party texts are derived from `LICENSE` / `THIRD_PARTY.md`; no clickable link
   (no `shell`/opener plugin) — plain text pointing to the bundled file. Wording needs CLO review.
9. Language picker: built as a component (keys 1 / 2 / Esc, arrows, 10 s timeout); the separate always-on-top
   OS window, its positioning and focus mode (a/b) are backend/architect work.
10. Key names on chips are not localised (`Space`, not `Пробел`).
