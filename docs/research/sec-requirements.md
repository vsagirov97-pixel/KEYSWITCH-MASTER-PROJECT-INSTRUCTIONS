# KeySwitch — обязательные требования безопасности (SR-xx) и план тестирования безопасности

Статус: **исследование для GATE 2** · Автор: Security Analyst (Agent 07) · Дата: 2026-11-09
Угрозы: `sec-threat-model.md` (ST-xx). Аудит и вердикт: `sec-architecture-audit.md` (AF-xx).
Каждое требование — **обязательно** (MUST), проверяемо, и имеет способ проверки: **L** — автоматизируется на Linux (облачная сессия/`ubuntu-latest`), **W** — автоматизируется на GitHub Actions `windows-latest`, **M** — ручная проверка владельцем на реальной Windows (D-10), **R** — ревью кода/конфигурации (автоматизируемый grep/скрипт, где указано).

## 1. Требования

### 1.1 Буфер обмена

| ID | Требование | Угрозы | Проверка |
|---|---|---|---|
| SR-10 | Основной путь записи — `SendInput` Unicode (до 5 000 символов) для приложений с подтверждённым профилем; путь через буфер — только fallback по профилю. Для неизвестных приложений путь через буфер запрещён. | ST-01, ST-02, ST-03 | L (unit политики выбора пути), W |
| SR-11 | При пути через буфер восстановление выполняется **только** после сигнала, что целевое приложение прочитало данные (`WM_RENDERFORMAT` при отложенной отрисовке) **и** пост-проверки UIA; при отсутствии сигнала до таймаута — буфер не восстанавливается вслепую, временный текст остаётся, пользователь получает уведомление. | ST-01 | W (тестовое окно, читающее буфер с задержкой 0/50/500/2000 мс: прежнее содержимое буфера никогда не оказывается в поле) |
| SR-12 | После записи через любой путь содержимое поля сверяется с ожидаемым (UIA); расхождение → прекращение операции, код причины в журнале, без повторов. | ST-01, ST-18 | W |
| SR-13 | Snapshot: перечисление форматов без рендеринга; данные читаются только для белого списка (`CF_UNICODETEXT`, `CF_LOCALE`, `HTML Format`, `Rich Text Format`, `CF_DIB`, `CF_DIBV5`, `CF_HDROP` и согласованных shell-форматов как байтов); любой иной формат, отложенная отрисовка, OLE-объект или размер > 16 МБ → буфер не трогается (SendInput или отказ). Чтение — в отдельном потоке, таймаут ≤ 500 мс. Restore: `OpenClipboard` → сравнение sequence number с ожидаемым → только затем `EmptyClipboard`/`SetClipboardData`. Снимок хранится в обнуляемом буфере и уничтожается по окончании операции. | ST-02, ST-05, ST-06 | W (фикстуры: текст+HTML+RTF, DIB, CF_HDROP, отложенная отрисовка, не отвечающий владелец, приватный формат, 100 МБ; гонка второго писателя ×1000) |
| SR-14 | Временные данные KeySwitch ставятся вместе с метками `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory`=0, `CanUploadToCloudClipboard`=0 в одной транзакции `OpenClipboard…CloseClipboard`. Метки исходных данных сохраняются в снимке и восстанавливаются. В удалённой сессии (`SM_REMOTESESSION`) путь через буфер запрещён. | ST-03, ST-04 | W (перечисление форматов после put; фикстура «данные с метками» → метки после restore) + M (Win+V, облачный буфер, RDP) |

### 1.2 Фокус, ввод, UIA, горячие клавиши

| ID | Требование | Угрозы | Проверка |
|---|---|---|---|
| SR-20 | Ввод `SendInput` пакетами ≤ 64 символа; перед каждым пакетом проверяются foreground HWND, PID, `hwndFocus` (`GetGUIThreadInfo`) и UIA RuntimeId фокус-элемента; несовпадение → немедленная остановка. `SetForegroundWindow`/`AttachThreadInput` к чужим окнам не используются (кроме возврата после диалога, SR-22). | ST-07 | W (второй процесс отбирает foreground через N мс: в чужое окно ушло ≤ 1 пакета) |
| SR-21 | Операция прерывается при: блокировке/смене сессии (`WTSRegisterSessionNotification`), смене foreground, физическом вводе пользователя во время инъекции. Переключение раскладки — только после успешной записи и повторной проверки, что фокус всё ещё в целевом окне; никогда для полей паролей/повышенных окон. | ST-07, ST-13, ST-15 | W (смена фокуса перед SwitchLayout) + M (Win+L посреди операции) |
| SR-22 | Диалог смешанного текста не активирует своё окно (`WS_EX_NOACTIVATE`), выбор — мышью или временно зарегистрированными хоткеями; если фокус всё же ушёл — после выбора текст поля перечитывается и сравнивается по хэшу с прочитанным до диалога, иначе отказ. Диалог не показывает пользовательский текст целиком (или реализован нативно, вне WebView). | ST-08, ST-43 | W + M (Telegram) |
| SR-23 | Отказ **до чтения текста**, если: `IsPassword`; эвристика имени/AutomationId/autocomplete (`password, pin, otp, cvv, cvc, пароль, код`); процесс в списке исключений (по умолчанию: менеджеры паролей, терминалы, клиенты RDP/VM); неизвестный `FrameworkId` с неподтверждённым профилем → только выделение. | ST-09 | W (тестовые окна `ES_PASSWORD`, WebView2 `type=password`, маскирующее поле CSS, `autocomplete=one-time-code`; счётчик вызовов `GetText` = 0) + M (KeePass, банки) |
| SR-24 | Манифест `asInvoker`, `uiAccess=false`. При старте с повышенным токеном KeySwitch отключает конвертацию и макросы и показывает предупреждение. Целевой процесс с более высоким IL или неоткрываемым токеном → отказ до чтения. | ST-10 | L (unit функции классификации токена на моках) + M (запуск elevated; админ-PowerShell в фокусе) |
| SR-25 | Перед каждым пакетом ввода проверяется, что Shift/Ctrl/Alt/Win (обе стороны) не нажаты; ожидание ≤ 1 с, затем отказ. Синтетическое «отпускание» модификаторов запрещено. | ST-11 | W (удержание Ctrl/Alt синтетически → отказ, 0 событий отправлено) |
| SR-26 | Валидатор сочетаний: обязательна не-модификаторная клавиша (D-14); запрещены Win, `Ctrl+Alt+<X>` (AltGr) если хотя бы одна установленная раскладка даёт символ на `AltGr+<X>` (`VkKeyScanEx` по `GetKeyboardLayoutList`), одиночные Shift-сочетания; конфликт регистрации → понятная ошибка. | ST-12 | L (таблица запрещённых) + W (немецкая раскладка) |
| SR-27 | Макрос с разрешением чтения буфера или `keys` не запускается, если foreground-процесс имеет Low IL или AppContainer. | ST-12 | W (тестовое окно Low IL, если раннер позволяет создать) / M |
| SR-28 | UIA: `IUIAutomation2` `ConnectionTimeout`/`TransactionTimeout` ≤ 2 с; все вызовы UIA и буфера — в выделенном потоке с отменой; отказ при таймауте. | ST-14, ST-06 | W (фейковый медленный провайдер) |
| SR-29 | Чтение текста ограничено: `GetText(5001)`, длина > 5 000 → отказ; нет глобальных подписок на события UIA (фокус/текст); читаются только нужные свойства. | ST-14 | W + R (grep `AddFocusChangedEventHandler|AddAutomationEventHandler` → 0) |

### 1.3 Замена текста в поле

| ID | Требование | Угрозы | Проверка |
|---|---|---|---|
| SR-31 | «Всё поле» разрешено только если одновременно: `ControlType=Edit`, не многострочное, длина ≤ 5 000, согласованы длины `ValuePattern.Value` и `TextPattern.DocumentRange`, приложение в белом списке профилей. Для браузеров и rich-редакторов по умолчанию — только выделение или фрагмент до разрыва строки. | ST-16 | W (WebView2 `contenteditable role=textbox` с 10 абзацами → отказ/только выделение) + M (Word, Gmail, Notion, Google Docs) |
| SR-32 | Выделение фрагмента (D-03) подтверждается повторным чтением выделения до записи; несовпадение → отказ. Ctrl+A — только для профилей, где это подтверждено ручной приёмкой. | ST-16 | W + M |
| SR-33 | Для каждого эталонного приложения матрица D-12 (Ctrl+Z возвращает исходный текст) подтверждена вручную до включения профиля; без подтверждения профиль консервативный. | ST-17 | M |
| SR-34 | `ValuePattern.SetValue` и запись в DOM/UIA напрямую запрещены; при активном IME — путь paste или отказ. | ST-18, ST-21 | R (grep `SetValue` в `ks-platform-win` → 0) + M |
| SR-35 | Текст, содержащий `\r`, `\n`, `\t`, никогда не вводится посимвольно `SendInput` в приложения с профилем «chat» или без профиля; для них — paste по профилю или отказ. | ST-19 | W (тестовое окно считает VK_RETURN/WM_CHAR 0x0D = 0) + M (Telegram, WhatsApp, Discord) |
| SR-36 | Профиль табличных процессоров (Excel, LibreOffice Calc): только режим редактирования ячейки (UIA), без Ctrl+A, без вставки текста с `\t`/`\n`; результаты макросов, начинающиеся с `= + - @`, требуют явного разрешения слота. | ST-20, ST-26 | L (unit политики) + M (Excel) |

## 4. Решения, необходимые от владельца
1. **D-07:** сделать `Enter`/`Tab` (и `\n` в тексте макроса) отдельным разрешением слота, выключенным по умолчанию (SR-49).
2. **CLAUDE.md правило 3:** исключение «не моложе 2 недель» для security-патчей (SR-60).
3. Остаточные риски: синтетический запуск хоткея (без LL-хука неотличим), сторонние менеджеры буфера, игнорирующие метки, поведение WebView2 Runtime (сеть/отчёты о сбоях).
4. Подпись кода (D-11) и updater — до GATE 9.
5. Лицензирование данных CC-BY-SA (R-7) — до GATE 9.
