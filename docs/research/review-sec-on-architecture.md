## 2. Новые находки

### XR-01 · Сигнал WM_RENDERFORMAT одноразовый и может быть «съеден» сторонним слушателем · High
- **Описание.** Отложенная отрисовка срабатывает один раз на формат. Менеджеры буфера и `mstsc.exe` при RDP могут прочитать данные по `WM_CLIPBOARDUPDATE` сразу после `CloseClipboard`, до Ctrl+V. После Ctrl+V чтение слушателем неотличимо от потребления целью без проверки, кто открыл буфер; `GetOpenClipboardWindow()` возвращает NULL при `OpenClipboard(NULL)`.
- **Сценарий.** Слушатель отрисовал данные раньше цели, сигнал засчитан, через 50 мс буфер восстановлен, медленная цель вставляет исходный буфер пользователя (ST-01). Либо ложный `PasteNotConsumed`.
- **Компоненты.** [FR] §5.10; v2 §3.2 `PasteTx::wait_consumed`; §4.1 (T1).
- **Рекомендация.** (а) Любой `WM_RENDERFORMAT` до Ctrl+V — прервать W2, восстановить snapshot, перейти на W3 или отказ `ClipboardListenerInterference`. (б) После Ctrl+V засчитывать сигнал только если PID окна, открывшего буфер, = PID цели или «брокера» из профиля; NULL/чужой PID — «не подтверждено». (в) Восстанавливать только при сигнале от цели **и** `read_back_matches == Yes` (SR-11).
- **Проверка (S-2).** Фикстура-слушатель до/после Ctrl+V, цель с задержкой чтения 1–2 с; исходный буфер не попадает в цель ни в одном из 100 прогонов.

### XR-02 · Восстановление буфера по таймауту вслепую · High
- **Описание.** «Нет сигнала» ≠ «вставки не было»: Ctrl+V уже в очереди ввода цели, медленная цель прочитает восстановленный буфер.
- **Сценарий.** Цель подвисла на 1 с; через 750 мс восстановлен буфер с паролем; пароль вставлен в чат.
- **Рекомендация.** Позиция SR-11: при таймауте не восстанавливать; временный текст (с метками D-13) остаётся, пользователю — действие «вернуть буфер». `WaitForInputIdle` — только вспомогательный сигнал [HYP].
- **Проверка.** Цель с `Sleep(1500)`; исходный буфер в поле не попадает.

### XR-03 · EM_REPLACESEL в RichEdit: возможна интерпретация RTF [UNVERIFIED] и запись мимо переднего плана · High (условно, до S-2)
- **Описание.** RichEdit может разбирать строку, начинающуюся с `{\rtf`/`{urtf`, как RTF (включая `\object`). Вектор — враждебный макрос. W1 адресован HWND и выполнится, даже если пользователь переключил окно.
- **Рекомендация.** В v1 W1 — только класс `Edit`. RichEdit — только после теста S-2 и если текст не начинается с `{\rtf`/`{urtf`; вывод макросов через W1 в RichEdit запрещён. Перед `SendMessageTimeout` проверять foreground и отпечаток.
- **Проверка.** `RICHEDIT50W`: `EM_REPLACESEL("{\rtf1 \b x}")` вставляется литералом.

### XR-04 · Snapshot читает все форматы и может держать буфер открытым при зависании · Medium
- **Описание.** `GetClipboardData` для каждого формата запускает отрисовку у чужих владельцев; при зависании поток держит буфер открытым для всей системы.
- **Рекомендация.** SR-13: перечислять без чтения, читать только белый список; чужие/OLE-форматы или `IsHungAppWindow` — W2 запрещён.
- **Проверка.** Владелец со `Sleep(5000)` в `WM_RENDERFORMAT`: отказ от W2 за ≤ 300 мс, буфер доступен.

### XR-05 · «Отравленный» поток T2 после сторожа может довести запись до конца · High
- **Описание.** После зависания T2 создаётся новый поток, старый «завершится сам» и может перейти к Write без повторного verify.
- **Сценарий.** Провайдер завис на 3 с, пользователь ушёл в терминал, старый T2 набирает текст в чужое окно (ST-07).
- **Рекомендация.** Атомарный счётчик поколения операций; единый шлюз побочных эффектов (мьютекс + проверка поколения) перед каждым SendInput, W1, `begin_paste`, restore; обработчик отрисовки в T1 тоже сверяет поколение.
- **Проверка.** Тест на `ks-platform-fake`: в журнале вызовов нет записей старого поколения.

### XR-06 · WM_RENDERFORMAT в T1 и UIA в T2: взаимная блокировка · Medium
- **Рекомендация.** Текст передаётся в T1 до Ctrl+V, обработчик не блокируется; фокус в собственном процессе — отказ `SelfTarget` до UIA; корректная обработка `WM_RENDERALLFORMATS`.
- **Проверка.** Ревью кода + тест «хоткей при фокусе в окне KeySwitch».

### XR-07 · Read-only preopen stdlib (P-12) против stdlib в памяти · High
- **Описание.** 5 из 9 advisory `wasmtime-wasi` за 2026 год — в коде ФС (RUSTSEC-2026-0149, -0188, -0352, -0323, -0314). Preopen делает его достижимым (граница ST-23). Каталог в `%LOCALAPPDATA%` доступен пользователю на запись; ленивое чтение — TOCTOU.
- **Рекомендация.** По умолчанию — ноль preopen: stdlib внутри гостевого образа (wasi-vfs-подобная упаковка или frozen-модули). Запасной вариант — только решением Security в S-3 и при всех условиях: READ-права; ACL каталога для SID AppContainer/LPAC только на чтение; нет symlink/junction; хэш-манифест при каждом старте; H-01…H-12 и тесты symlink/hardlink на `windows-latest`; всегда последний патч 48.x.
- **Проверка.** Unit-тест: пустой список preopens; S-3 — CPython стартует без каталогов хоста.

### XR-08 · Wasmtime =48.0.7 уже уязвим; ритм патчей против «правила 2 недель» · Medium
- **Описание.** Для 48.0.7 есть RUSTSEC-2026-0422/0423/0424, исправлены в 48.0.8 (2026-10-29). Вероятно, затрагивают только GC/component model, выключаемые SR-41 [HYP], но `cargo deny` упадёт. Три security-патча за 15 дней.
- **Рекомендация.** `=48.0.8` (14 дней — 2026-11-12). Решение владельца по исключению для security-патчей (≤ 7 дней). `ignore` в `deny.toml` — только с обоснованием.

### XR-09 · «Тёплый» процесс песочницы общий для нескольких запусков · Medium
- **Рекомендация.** Отдельный процесс на запуск при доступе к буферу или минимум перезапуск после изменения скрипта (ответ на Q-B3).

### XR-10 · Номер последовательности при отложенной отрисовке · Low
- **Рекомендация.** Фиксировать ожидаемые seq до/после отрисовки и сравнивать под `OpenClipboard`.

## 3. Разногласия архитектора и Security

1. **Метод записи.** Security (SR-10): SendInput до 5 000 символов, W2 для неизвестных запрещён. Архитектор: W1 → W3 ≤ 200 → W2. **Рекомендация:** W1(Edit) → W3 ≤ 200 символов без `\n`, пакеты ≤ 64 символа с проверкой фокуса перед каждым → W2 для неизвестных только при строгом сигнале (XR-01 б) и пост-проверке, иначе отказ. SR-10 поправить.
2. **Таймаут сигнала.** Позиция Security (XR-02).
3. **Диалог смешанного текста.** Принять вариант архитектора (активировать, вернуть фокус, перечитать, сверить хэш) с условиями: не возвращать фокус, если передний план сменился на чужое окно; текст пользователя не показывать; снять `WS_EX_TOPMOST` после выбора; в S-2 проверить, что blur в веб-композерах ничего не отправляет. SR-22 поправить.
4. **stdlib.** Образ без preopen по умолчанию; preopen — запасной вариант по XR-07.
5. **Лимиты протокола.** Принять 64 КиБ / 5 000; поправить FR-MACRO-4.
6. **Enter/Tab.** Отдельное разрешение слота, по умолчанию выключено — изменение D-07, решает владелец.
7. **Wasmtime.** 48.0.8.

## 4. Вердикт GATE 2 (безопасность): BLOCK сохраняется

Прогресс по C-1, C-4, C-6 существенный, но ни одно условие не выполнено полностью; добавлены High XR-01, XR-02, XR-03 (условно), XR-05; S-2 и S-3 не выполнены.

Оставшиеся условия: **C-1′** (белый список, 16 МБ, seq под `OpenClipboard`, XR-01 а–в, без восстановления по таймауту, запрет при `SM_REMOTESESSION`, без W2 для неизвестных без строгого сигнала, XR-04) · **C-2** (64 КиБ, 5 000, ≤ 16 keys, фильтр управляющих символов, глубина ≤ 8, `deny_unknown_fields`) · **C-3′** (ноль preopen по умолчанию, список импортов SR-43) · **C-4′** (`DIE_ON_UNHANDLED_EXCEPTION`, `JOB_MEMORY`, SR-56, WER off, epoch + `TerminateJobObject`, процесс на запуск при буфере) · **C-5** (+ решение по D-07) · **C-6′** (пакетная проверка фокуса/модификаторов, прерывание при блокировке/физическом вводе, SR-23, браузеры — только выделение, протокол диалога, шлюз побочных эффектов, W1 только Edit, `SelfTarget`) · **C-7** · **C-8′** (commit SHA, WASI SDK по хэшу, `include_bytes!`, wasmtime ≥ 48.0.8, решение по P-16) · **C-9** · **C-10 (новое)** — перенести принятое в `docs/02-architecture.md`, поправить SR-10 и SR-22.

Решения владельца: D-07 (Enter/Tab); исключение из правила №3 для security-патчей; остаточный риск сторонних слушателей буфера; Q-B3 (тёплый процесс).
