## 0. Легенда и правила чтения

- **[ASSUMPTION A-xx]** — допущение аналитика. Не является решением владельца, требует подтверждения или проверки. Сводный список — §12.
- **[Q-xx]** — открытый вопрос владельцу (§13.2). Пока вопрос открыт, действует указанная рекомендация как рабочая гипотеза.
- **Приоритет:** P0 — без этого нельзя выпускать v1; P1 — обязательно для v1, но допускается ограниченная реализация; P2 — желательно, может быть перенесено.
- **Проверка:** `U` — unit-тест ядра (Linux/Windows CI); `I` — интеграционный тест на Windows CI с тестовым окном; `M` — ручная приёмка на реальной Windows по чек-листу (D-10); `R` — ревью кода/конфигурации.
- **Статус проверки:** ничего из требований к Windows-интеграции **не проверено**. Проверено только то, что перечислено в S-1 (ядро, Linux, 30 тестов).
- Термин «отказ» везде означает операцию `Abort(reason)` с гарантиями из FR-ABORT-1 (ничего не изменено).

## 2. Назначение, цели и метрики успеха

KeySwitch — фоновое приложение Windows 10/11, которое **по явному нажатию горячей клавиши** исправляет текст, набранный в неверной раскладке (EN ↔ RU), и выполняет один пользовательский макрос по второй горячей клавише. Не переводчик и не транслитератор (ТЗ §3). Вся обработка — локально (ТЗ §14).

Главный продуктовый принцип (ТЗ §21, CLAUDE.md): **лучше отказаться, чем испортить**. Ложный отказ — неудобство; ошибочная замена, потеря буфера или массовая правка документа — дефект уровня P0.

Цели v1 и измеримые индикаторы (все пороги — [ASSUMPTION A-01], утверждаются владельцем):

| Цель | Индикатор | Порог v1 |
|------|-----------|----------|
| G-1 Корректная конвертация | Доля верно сконвертированных фраз на QA-корпусе (NFR-QUAL-1) | ≥ 97 % |
| G-2 Никакого вреда | Ошибочных замен на корпусе «уже корректного текста» (NFR-QUAL-2) | ≤ 0,5 % |
| G-3 Сохранность данных | Потерь содержимого буфера в наборе тестов FR-CLIP | 0 |
| G-4 Без массовой порчи | Замен за пределами области D-03 в ручной приёмке | 0 |
| G-5 Предсказуемая поддержка | Приложения матрицы со статусом «Pass» на уровне v1 | все строки уровня «Обязательно» (`pa-app-matrix.md` §3) |
| G-6 Приватность | Сетевые соединения в runtime / текст в логах | 0 / 0 |

## 3. Рамки (Scope) и вне рамок (Non-goals)

### 3.1 В рамках v1
1. Конвертация EN (US QWERTY, KLID 00000409) ↔ RU (ЙЦУКЕН, KLID 00000419) по горячей клавише — выделение / поле / фрагмент (D-03).
2. Диалог выбора целевого языка для смешанного текста (ТЗ §6).
3. Переключение раскладки окна на целевую после успешной замены (ТЗ §5).
4. Сохранение и восстановление буфера обмена (ТЗ §9, D-13).
5. Две глобальные горячие клавиши через `RegisterHotKey` с проверкой конфликтов (ТЗ §10, D-14).
6. Macro Studio: один слот, тип текст / JavaScript / Python; редактор CodeMirror 6, подсветка, проверка синтаксиса, выполнение по горячей клавише в песочнице (ТЗ §11, D-06…D-08).
7. Трей, автозапуск (по настройке), временное отключение (ТЗ §13).
8. UI: Overview, Languages & Layouts, Hotkeys, Macro Studio, Settings, Diagnostics; темы Dark/Light/System; локализация RU/EN (ТЗ §12).
9. Журнал диагностики без пользовательского текста.
10. Архитектурная расширяемость на другие языки как данные (D-15) — проверяется тестом, но новых языков в поставке нет.

## 4. Глоссарий

| Термин | Определение |
|--------|-------------|
| Целевое окно | Окно переднего плана в момент нажатия горячей клавиши (HWND, PID, exe). |
| Фокусный элемент | Элемент UI Automation с клавиатурным фокусом (`GetFocusedElement`) с RuntimeId. |
| Область (scope) | Диапазон текста, который KeySwitch прочитает и заменит: `Selection`, `WholeField`, `LineFragment` (D-03). |
| Однострочное поле | UIA ControlType = Edit, не Document, `IsPassword=false`, `IsReadOnly=false`, и поле не многострочное: для Win32 Edit — без `ES_MULTILINE`; для прочих — текст не содержит переводов строки **и** профиль приложения не помечает его как документ. [ASSUMPTION A-02] |
| Поле чата | Многострочное поле ввода сообщения, помеченное как «chat» в профиле приложения (`app-profiles.toml`) после ручной проверки. Для неизвестных приложений многострочное поле **не** считается полем чата. [ASSUMPTION A-03, Q-03] |
| Документ | UIA ControlType = Document **или** многострочное Edit, не помеченное как поле чата (например, Блокнот, тело Word, редактор VS Code). |
| Фрагмент строки (`LineFragment`) | Текст от последнего разрыва строки перед кареткой (или от начала поля) до каретки. Разрыв строки — CR, LF, CRLF, U+2028, U+2029, VT (Shift+Enter в Word). [ASSUMPTION A-04, Q-04] |
| Длина | Количество скалярных значений Unicode (code points) в области после чтения. [ASSUMPTION A-05] |
| Уверенность | Результат ядра `Confidence::{High, Low}` (S-1). `Low` — исходный текст правдоподобнее результата или модель не различает варианты. |
| Смешанный текст | `detect()` вернул ≥ 2 языка с буквами в области. |
| Отказ | Операция прервана до шага Write или Write не начат; см. FR-ABORT-1. |
| Профиль приложения | Запись в `app-profiles.toml`: способ записи (SendInput/paste), разрешён ли `WholeField`, задержки, признак «chat». Неизвестное приложение получает консервативный профиль (FR-PROF-2). |

## 6. Пользовательские сценарии (US-xx)

Формат: **Основной путь** → **Альтернативы (A)** → **Сбои/отказы (F)**. Ссылки на FR и EC.

### US-01. Конвертация в однострочном поле / поле чата (P-1, P-3) — P0
**Основной путь.** Telegram Desktop, поле сообщения содержит `Ghbdtn, rfr ltkf?`, выделения нет, каретка в конце. Пользователь нажимает горячую клавишу конвертации. Через ≤ 300 мс (NFR-PERF-2) поле содержит `Привет, как дела?`, раскладка окна — RU, буфер обмена — прежний, сообщение не отправлено, уведомлений нет.
- A1. Поле — однострочное Edit в браузере (строка поиска) → тот же результат.
- A2. Поле чата многострочное (`Ghbdtn` ⏎ `rfr ltkf`), профиль приложения помечает его «chat» → заменяется всё поле, переводы строк сохранены, сообщение **не отправлено** (FR-WRITE-4).
- A3. Текст набран в RU, а должен быть EN (`Руддщ` → `Hello`) → направление по составу (D-02), раскладка → EN.
- A4. Раскладка уже RU, но текст английскими буквами → направление всё равно EN→RU (D-02).
- F1. Поле пустое или только пробелы → отказ `EMPTY` (FR-SCOPE-7).
- F2. Длина > 5 000 → отказ `TOO_LONG`.
- F3. Поле содержит встроенный объект (упоминание, стикер, кастомный эмодзи, U+FFFC) → отказ `EMBEDDED_OBJECT` (FR-SCOPE-6).
- F4. Приложение не даёт ни UIA-текста, ни безопасного способа выделить всё поле → отказ `UNSUPPORTED_FIELD`.
- F5. Модификаторы не отпущены за 1 с → отказ `MODIFIERS_TIMEOUT`.
Связано: FR-SCOPE-1…7, FR-CONV-*, FR-WRITE-*, FR-CLIP-*, FR-LAYOUT-1, EC-01…EC-20.

### US-02. Конвертация выделенного фрагмента (P-1) — P0
**Основной путь.** В Word выделено `ytn` внутри абзаца. Горячая клавиша → выделение заменено на `нет`, остальной документ не изменён (побайтно, по чтению через UIA до/после), раскладка → RU.
- A1. Выделение в Chrome в `<textarea>` / contenteditable → заменяется только выделение.
- A2. Выделение содержит перевод строки (2 абзаца) → заменяется, разрывы сохранены; форматирование внутри выделения может быть утрачено (NG-11) — [Q-10].
- A3. Выделение смешанное → US-04.
- A4. Выделение на нередактируемой веб-странице (не в поле) → отказ `READ_ONLY`/`NO_FIELD` (FR-POL-5).
- F1. Выделение > 5 000 → отказ `TOO_LONG` (даже в Word — без попытки частичной обработки).
- F2. Выделение в ячейке Excel вне режима редактирования (выделен диапазон ячеек) → отказ `UNSUPPORTED_FIELD` (`pa-app-matrix.md`).
- F3. Приложение не отдаёт выделение через UIA → поведение по Q-05 (рекомендация: чтение выделения через Ctrl+C с полной защитой буфера, только по профилю).

### US-03. Многострочный документ без выделения (P-1, P-2) — P0
**Основной путь.** Блокнот (Win10, классический), выше несколько строк, каретка в конце последней строки `rfr ltkf`. Горячая клавиша → заменяется только `rfr ltkf` → `как дела`; остальные строки не изменены.
- A1. Каретка в середине документа, в конце строки N → заменяется только фрагмент строки N от её начала до каретки.
- A2. Каретка в середине строки → заменяется только часть строки до каретки; текст после каретки не трогается [A-04, Q-04].
- A3. Word, тело документа (Document) — тот же принцип; Ctrl+A запрещён (D-04).
- A4. Фрагмент содержит уже корректный русский текст и неверный → US-04.
- F1. Каретка в начале строки (фрагмент пуст) → отказ `EMPTY`.
- F2. Нельзя надёжно определить позицию каретки или выделить фрагмент через UIA TextPattern → отказ `UNSUPPORTED_FIELD` (D-03 «иначе отмена»).
- F3. Фрагмент > 5 000 символов (одна длинная строка) → отказ `TOO_LONG`.

### US-04. Диалог смешанного текста (P-1, P-2) — P0
**Основной путь.** Поле: `Привет, rfr ltkf?`. Горячая клавиша → появляется компактное окно с кнопками «Русский», «English», «Отмена» (фокус на окне, клавиши `1`/`2`/`Esc`). «Русский» → фокус возвращается в исходное поле, проверка того же поля (FR-POL-6), результат `Привет, как дела?`, раскладка RU.
- A1. «English» → русские фрагменты конвертируются в EN, английские остаются.
- A2. Корректные иностранные слова целевого языка сохраняются (`Открой google, gj;fkeqcnf` → `Открой google, пожалуйста`, S-1).
- A3. Для выбранного направления ядро вернуло `Low` → отказ `LOW_CONFIDENCE` («не выполнять рискованную замену», ТЗ §6).
- F1. «Отмена» / Esc / закрытие окна → ничего не меняется, буфер не тронут, раскладка не тронута.
- F2. Пользователь не ответил 30 с [A-06] → автоматическая отмена `DIALOG_TIMEOUT`.
- F3. Во время диалога фокус ушёл в другое окно, целевое окно закрыто или содержимое поля изменилось → после выбора отказ `FOCUS_CHANGED` / `CONTENT_CHANGED`.
- F4. Повторное нажатие горячей клавиши при открытом диалоге → игнорируется (FR-ENG-2), диалог остаётся.

### US-05. Низкая уверенность (P-1, P-2) — P0
**Основной путь.** Выделено `Hello, how are you?` (корректный английский). Горячая клавиша → ядро: `Low` → отказ `LOW_CONFIDENCE`; поле, буфер, раскладка не изменены; запись в Diagnostics; звук — по Q-02.
- A1. Короткий текст из 1–2 букв, неоднозначный (`z` → `я`?) → поведение по NFR-QUAL-4 и EC-27.
- A2. По Q-01 (если владелец примет предложение S-1 №3) — вместо отказа показывается диалог подтверждения. **До решения владельца — отказ.**
- F1. Текст похож на код (`if (x == 1) {`) → `Low` → отказ.

### US-07. Сохранность буфера обмена (P-1, P-4) — P0
**Основной путь.** В буфере таблица из Excel (Text + HTML + RTF + CSV + Bitmap). Конвертация через буфер → после замены буфер содержит те же форматы с теми же данными (побайтное сравнение сохранимых форматов), в истории Win+V не появилась запись с конвертированным текстом (D-13).
- A1. Короткий текст записан через SendInput — буфер вообще не трогался.
- A2. Буфер пуст → после операции пуст.
- F1. В буфере несохранимые данные (отложенная отрисовка, которую нельзя материализовать; приватные форматы с GDI/handle-данными) → используется SendInput (если допустимо по FR-WRITE-3) **или** отказ `CLIPBOARD_UNSAFE`. Никогда — частичное восстановление молча.
- F2. Другое приложение изменило буфер **до** нажатия Ctrl+V KeySwitch → вставка не выполняется, отказ `CLIPBOARD_CHANGED`, буфер не восстанавливается (новое содержимое принадлежит другому приложению).
- F3. Другое приложение изменило буфер **после** вставки, до восстановления → восстановление не выполняется (ТЗ §9), запись `CLIPBOARD_NOT_RESTORED` в Diagnostics.
- F4. Менеджер буфера (Ditto и т. п.) перезаписывает буфер сразу после KeySwitch → см. EC-74, Q-11.

### US-08. Переключение раскладки (P-1) — P0

### US-09. Настройка горячих клавиш и конфликты (P-1, P-2) — P0

- A2. Сброс к значению по умолчанию.

- F2. Одна клавиша без модификатора или Shift+печатный символ → запрещено (FR-HK-2).
- F3. Совпадает со второй горячей клавишей KeySwitch → запрещено, подсказка.
- F4. `RegisterHotKey` вернул ошибку (занято другим приложением) → сообщение «Сочетание занято другой программой», старая клавиша остаётся активной.

- F6. При старте приложения ранее сохранённая клавиша не регистрируется → статус «Не активна: занята», индикатор в трее (FR-TRAY-1), запись в Diagnostics.

### US-12. JavaScript-макрос (P-2) — P0
**Основной путь.** Тип «JavaScript», код: `return { replace: ks.context.text.toUpperCase() };`. Проверка синтаксиса — «Ошибок нет». Сохранить. В Chrome выделено `hello` → горячая клавиша → `HELLO`.

- F3. Бесконечный цикл → принудительное завершение через ≤ 2 с (+ допуск NFR-PERF-5), `MACRO_TIMEOUT`.
- F4. Возврат `{ keys: ["Win+R"] }` или неизвестного ключа → **всё действие** отклонено, `MACRO_POLICY` (T-02).
- F5. Попытки доступа к сети/ФС/процессам (`fetch`, `std.loadFile`, `os.exec`) → функция отсутствует/ошибка, ничего не выполняется.

## 7. Функциональные требования (FR-xx) с критериями приёмки

Обозначения AC: `Дано / Когда / Тогда`. В колонке «Пров.» — способ проверки.

### 7.1 FR-CONV — Ядро конвертации

**FR-CONV-1 (P0).** Соответствие символов определяется физической клавишей (скан-код) по таблицам `en-us.layout` / `ru.layout`, хранимым как данные (D-15).
- AC1 (U): Дано таблицы S-1, Когда конвертируется каждый символ основного и Shift-уровня каждой клавиши EN→RU→EN, Тогда для однозначных букв результат совпадает с исходником (круговая конвертация).
- AC2 (U): Дано файл раскладки с дубликатом скан-кода или символа, Когда он загружается, Тогда ошибка загрузки с указанием строки, приложение не стартует конвертацию (а не падает).

**FR-CONV-2 (P0).** Сохраняются регистр каждого символа, цифры, все виды пробелов (U+0020, U+00A0, табуляция), переводы строк (точная последовательность CR/LF), символы вне таблиц (эмодзи, иероглифы, RTL, комбинирующие знаки), длина в code points.
- AC1 (U): Дано 300 псевдослучайных строк (инвариант S-1) + строки из EC-01…EC-49, Когда `convert`/`convert_mixed`, Тогда длина в code points, позиции пробелов/переводов строк/цифр/неизвестных символов совпадают с исходными.
- AC2 (U): Дано `GhBdTn`, Тогда `ПрИвЕт` (регистр 1:1, без «исправления»).

**FR-CONV-3 (P0).** Для символов, имеющих смысл в обеих раскладках (`` , . ; ' [ ] ` / ? " @ # $ ^ & : < > { } ~ | ``, а также RU `б ю ж э х ъ ё №`), вариант выбирается языковой моделью по контексту (D-01).
- AC1 (U): обязательный набор — все кейсы черновика и таблицы S-1 проходят: `Ghbdtn, rfr ltkf?`→`Привет, как дела?`; `Ghbdtn? rfr ltkf&`→`Привет, как дела?`; `k.,k.`→`люблю`; `j,sxyj`→`обычно`; `ytn.`→`нет.`; `xbckj 3.14`→`число 3.14`; `Руддщ`→`Hello`; `Руддщб цщкдв!`→`Hello, world!`; `ш вщтэе лтщц`→`i don't know`; `Ntcn 123`→`Тест 123`.
- AC2 (U): Дано QA-корпус ≥ 500 фраз (NFR-QUAL-1), Тогда пороги NFR-QUAL выполнены.

**FR-CONV-4 (P0).** Направление — по составу текста (D-02); активная раскладка целевого окна — только при равенстве (нет букв ни одного языка, только неоднозначные знаки).
- AC1 (U): Дано `ghbdtn` и активная раскладка RU (передаётся в ядро как подсказка), Тогда направление EN→RU.
- AC2 (U): Дано `,.;'` (только знаки, букв нет) и подсказка EN, Тогда направление EN→RU; при подсказке RU — RU→EN; результат проходит проверку уверенности.

**FR-CONV-5 (P0).** В смешанном режиме фрагменты, уже корректные в целевом языке, и настоящие слова целевого языка сохраняются; спорные — `Low` (S-1).
- AC1 (U): `Привет, rfr ltkf?` + цель RU → `Привет, как дела?`; `Открой google, gj;fkeqcnf` + цель RU → `Открой google, пожалуйста`.

**FR-CONV-6 (P0).** Уверенность: результат `High` только если результат правдоподобнее исходника по модели с запасом; иначе `Low`. Пороги — в конфигурации, покрыты тестами (архитектура §3).
- AC1 (U): `Hello, how are you?` → `Low`. AC2 (U): корпус «уже корректного текста» (NFR-QUAL-2) — ≥ 99,5 % `Low` или результат, равный исходнику.

**FR-CONV-7 (P0).** Защита от деградации: токен длиннее 48 символов конвертируется без перебора вариантов (S-1, предложение 2); общее время ядра на 5 000 символов ограничено NFR-PERF-1.
- AC1 (U): Дано токен 5 000 символов из букв и пунктуации, Тогда время ≤ 50 мс (p95, эталонная машина CI) и результат детерминирован.

**FR-CONV-8 (P0).** Детерминированность: одинаковый вход + одинаковая подсказка раскладки → одинаковый выход.
- AC1 (U): 1 000 повторов каждого кейса AC1 FR-CONV-3 дают идентичный результат.

**FR-CONV-9 (P1).** Токены, распознанные как URL (`scheme://…`, `www.…`), e-mail (`x@y.z`), путь (`C:\…`), уже корректные в исходной латинице, **не конвертируются** при направлении EN→RU, если остальной текст конвертируется; при RU→EN — токены, которые после конвертации образуют валидный URL/e-mail, конвертируются как целое [ASSUMPTION A-15, Q-06].
- AC1 (U): `Ghbdtn, cvjnhb https://example.com` → `Привет, смотри https://example.com`.
- AC2 (U): `реезыЖ..учфьздуюсщь` (URL, набранный в RU) → `https://example.com` при `High`, иначе `Low`.

**FR-CONV-10 (P1).** Новый язык добавляется файлом раскладки + файлом модели без изменения кода ядра (D-15).
- AC1 (U): тест загружает третью тестовую раскладку (фиктивную) и модель из фикстур, конвертация проходит через публичный API без изменения кода `ks-core`.

### 7.2 FR-SCOPE — Определение области обработки (D-03, D-04)

**FR-SCOPE-1 (P0).** Порядок: (1) непустое выделение → `Selection`; (2) иначе, если фокусный элемент — однострочное поле или поле чата → `WholeField`; (3) иначе, если документ и каретка определима → `LineFragment`; (4) иначе — отказ `UNSUPPORTED_FIELD`.
- AC1 (I): тестовое окно с Edit без `ES_MULTILINE`, текст `ghbdtn`, без выделения → заменено всё поле.
- AC2 (I): тестовое окно с многострочным Edit (`ES_MULTILINE`), 3 строки, каретка в конце 3-й → изменена только 3-я строка; строки 1–2 побайтно равны исходным.
- AC3 (I): то же окно, выделены 2 символа в строке 1 → изменены только они.
- AC4 (M): по матрице приложений — ожидаемая область совпадает с колонкой «Ожидаемое поведение».

**FR-SCOPE-2 (P0).** Классификация поля выполняется до выделения/записи, по UIA (ControlType, IsPassword, IsReadOnly, паттерны), стилям Win32 (если окно Win32 Edit/RichEdit) и профилю приложения. Многострочное поле неизвестного приложения считается **документом**, не полем чата [A-03].
- AC1 (I): многострочное Edit в тестовом окне без профиля → область `LineFragment`, не `WholeField`.
- AC2 (R): классификатор — чистая функция, покрыта unit-тестами на таблице входов (ControlType × флаги × профиль).

**FR-SCOPE-3 (P0).** Выделение всего поля (Ctrl+A или эквивалент через UIA) допускается только при: ControlType = Edit, не Document; IsPassword=false; фокус внутри этого элемента (RuntimeId фокусного элемента = элемент поля); профиль не запрещает (D-04).
- AC1 (I): Document-элемент без выделения → Ctrl+A **не отправлялся** (проверка журналом отправленного ввода в тестовом окне).
- AC2 (M): Word, тело документа, каретка в конце строки → документ не выделен целиком, изменена только строка.

**FR-SCOPE-4 (P0).** Лимит: длина области ≤ 5 000 code points; больше — отказ `TOO_LONG` до конвертации и до любого изменения.
- AC1 (I): поле из 5 000 символов → обработано; 5 001 → отказ, поле не изменено.

**FR-SCOPE-5 (P0).** Для `LineFragment` и `Selection` KeySwitch выделяет ровно читаемый диапазон и перед записью проверяет, что выделенный текст (через UIA) равен прочитанному. Иначе — отказ `CONTENT_CHANGED`.
- AC1 (I): тестовое окно, которое меняет текст между чтением и записью → отказ, вставка не выполнена.

**FR-SCOPE-6 (P0).** Если область содержит U+FFFC (встроенный объект) или профиль сообщает о нетекстовых элементах (упоминания, кастомные эмодзи, вложения) — отказ `EMBEDDED_OBJECT`.
- AC1 (U/I): область с U+FFFC → отказ. AC2 (M): Discord — сообщение с упоминанием `@user` (как объект) → отказ, упоминание не уничтожено.

**FR-SCOPE-7 (P0).** Пустая область или только пробельные символы/знаки, которые не меняются ни в одном направлении → отказ `EMPTY` / `NOTHING_TO_CONVERT`, без каких-либо действий ввода.
- AC1 (I): пустое поле → в журнал ввода тестового окна не поступило ни одного события.

### 7.3 FR-ABORT / FR-ENG — Семантика операции

**FR-ABORT-1 (P0).** Отказ на любом шаге до Write гарантирует: текст поля не изменён, буфер не изменён, раскладка не изменена, выделение — см. AC2. Отказ после начала Write (ошибка вставки) — буфер восстанавливается по FR-CLIP-4, раскладка не переключается.
- AC1 (I): для каждого кода причины из таблицы ниже есть тест, проверяющий неизменность поля, буфера (sequence number и содержимое) и раскладки.
- AC2 (I): если отказ произошёл после того, как KeySwitch выделил фрагмент (`LineFragment`), выделение может остаться — **[ASSUMPTION A-16]**: допустимо, т. к. ТЗ §8 запрещает механизм восстановления курсора; Q-04.

**FR-ABORT-2 (P0).** Каждый исход операции имеет код причины; коды фиксированы и локализованы в UI.

| Код | Когда |
|-----|-------|
| `OK` | Успех |
| `DISABLED` | KeySwitch отключён (если клавиша всё же получена) |
| `BUSY` | Идёт другая операция |
| `MODIFIERS_TIMEOUT` | Модификаторы не отпущены за 1 с |
| `NO_FIELD` | Нет фокусного редактируемого элемента |
| `PASSWORD` / `ELEVATED` / `SECURE_DESKTOP` / `EXCLUDED_APP` / `READ_ONLY` | Политика D-05 и FR-POL-5 |
| `UNSUPPORTED_FIELD` | Область по D-03 определить нельзя |
| `EMPTY` / `NOTHING_TO_CONVERT` | Нечего конвертировать |
| `TOO_LONG` | > 5 000 |
| `EMBEDDED_OBJECT` | U+FFFC / объекты |
| `LOW_CONFIDENCE` | Ядро `Low` |
| `CANCELLED` / `DIALOG_TIMEOUT` | Диалог смешанного текста |
| `FOCUS_CHANGED` / `CONTENT_CHANGED` | Повторная проверка перед записью |
| `IME_ACTIVE` | Активна композиция IME (если определяется) |
| `CLIPBOARD_UNSAFE` / `CLIPBOARD_CHANGED` | Буфер нельзя безопасно использовать |
| `WRITE_FAILED` / `VERIFY_FAILED` | Ошибка записи / результат не совпал с ожидаемым |
| `CLIPBOARD_NOT_RESTORED` | Успех, но буфер не восстановлен, т. к. изменён другим приложением (информационный) |
| `LAYOUT_NOT_INSTALLED` | Успех без переключения раскладки (информационный) |
| `MACRO_*` | См. FR-MACRO |

**FR-ENG-1 (P0).** Порядок шагов — по конвейеру архитектуры §5; политика (FR-POL) проверяется **до чтения текста**.
- AC1 (I): в поле пароля тестового окна UIA `GetText`/`Value` не вызывались (журнал вызовов адаптера в тестовом режиме).

**FR-ENG-2 (P0).** Операции сериализованы: нажатие любой горячей клавиши KeySwitch во время операции (включая открытый диалог) игнорируется с записью `BUSY`.
- AC1 (I): два нажатия с интервалом 10 мс → одна операция, одна запись `OK` и одна `BUSY`.

**FR-ENG-3 (P0).** Перед отправкой любого ввода KeySwitch ждёт отпускания всех модификаторов (Ctrl/Alt/Shift/Win), не более 1 с; иначе `MODIFIERS_TIMEOUT`.
- AC1 (I): удержание Ctrl 2 с после хоткея → отказ, никакой ввод не отправлен.

**FR-ENG-4 (P1).** Общий таймаут операции конвертации (без времени диалога) — 3 с [A-17]; превышение → отказ с восстановлением буфера.

### 7.4 FR-POL — Политика безопасности (D-05)

**FR-POL-1 (P0).** Поле пароля (UIA `IsPassword` или Win32 `ES_PASSWORD`) → отказ `PASSWORD` до чтения текста. Применяется к конвертации и макросам.
- AC1 (I): тестовое окно с `ES_PASSWORD` → отказ, текст не прочитан, буфер не тронут. AC2 (M): поле пароля в Chrome (`<input type=password>`) и в окне входа Telegram (если есть) → отказ.

**FR-POL-2 (P0).** Целевой процесс с более высоким уровнем целостности, чем KeySwitch → отказ `ELEVATED` до чтения и до ввода. Если KeySwitch сам запущен с повышенными правами, целевые elevated-окна всё равно исключаются (D-05 «безусловно») [A-18].
- AC1 (I): тестовое окно, запущенное elevated на Windows CI-раннере → отказ.

**FR-POL-3 (P0).** Список исключений: по умолчанию — терминалы (`WindowsTerminal.exe`, `conhost.exe`, `cmd.exe`, `powershell.exe`, `pwsh.exe`, `OpenConsole.exe`, `mintty.exe`) и менеджеры паролей (`KeePass.exe`, `KeePassXC.exe`, `1Password.exe`, `Bitwarden.exe` и др. — окончательный список Q-16) [A-19]. Пользователь может добавлять/удалять exe. Сопоставление — по имени exe без учёта регистра [A-20].
- AC1 (I): exe тестового окна добавлен в исключения → отказ `EXCLUDED_APP` до чтения.
- AC2 (M): Windows Terminal, cmd → отказ.

**FR-POL-4 (P0).** Secure desktop → отказ (практически горячая клавиша не доставляется — проверяется вручную).
- AC1 (M): на экране UAC нажатие хоткея не вызывает действий KeySwitch.

**FR-POL-5 (P0).** Только редактируемые элементы: `IsReadOnly=true`, отсутствие фокусного Edit/Document с возможностью ввода → отказ `READ_ONLY`/`NO_FIELD`.
- AC1 (M): выделенный текст на обычной веб-странице (не в поле) → отказ, ничего не вставлено.

**FR-POL-6 (P0).** Перед Write повторно проверяются HWND, PID, RuntimeId фокусного элемента и (для `WholeField`) неизменность содержимого. Несовпадение → `FOCUS_CHANGED`/`CONTENT_CHANGED` (T-06).
- AC1 (I): во время диалога фокус переводится в другое тестовое окно → после выбора языка отказ, второе окно не получило ввода.

**FR-POL-7 (P1).** Если активна композиция IME и это определяется через доступные API — отказ `IME_ACTIVE` [A-21].

### 7.5 FR-MIX — Диалог смешанного текста (ТЗ §6, §13)

**FR-MIX-1 (P0).** Показывается только для смешанного текста. Кнопки «Русский», «English», «Отмена» (порядок и подписи локализуются, «Русский/English» — названия языков на своём языке [A-22]).
**FR-MIX-2 (P0).** Управление с клавиатуры: `1`/`2` (или первая буква), `Esc` = Отмена, `Enter` — без кнопки по умолчанию [A-23] (чтобы случайный Enter не применял замену).
**FR-MIX-3 (P0).** Окно появляется поверх целевого окна (у каретки или по центру целевого окна) за ≤ 200 мс после отпускания модификаторов.
**FR-MIX-4 (P0).** После выбора фокус возвращается в целевое окно; затем FR-POL-6. Если вернуть фокус нельзя (ограничения SetForegroundWindow) → отказ `FOCUS_CHANGED`.
**FR-MIX-5 (P0).** Таймаут без ответа — 30 с → `DIALOG_TIMEOUT` [A-06].
**FR-MIX-6 (P1).** Диалог не показывает текст пользователя [A-24, Q-17].
**FR-MIX-7 (P0).** Потеря фокуса диалогом (клик в другое окно) → отмена.
- AC (I/M) для FR-MIX-1…7: Дано поле `Привет, rfr ltkf?`, Когда хоткей, Тогда диалог виден ≤ 200 мс; Когда `Esc`, Тогда поле/буфер/раскладка не изменены; Когда `1`, Тогда `Привет, как дела?`; Когда 30 с без ответа, Тогда отказ `DIALOG_TIMEOUT`; Когда `Enter` сразу после появления, Тогда ничего не применено.

### 7.6 FR-WRITE — Запись результата

**FR-WRITE-1 (P0).** Запись — через вставку из буфера (FR-CLIP) или через `SendInput` с `KEYEVENTF_UNICODE`, по профилю приложения. `ValuePattern.SetValue` как основной способ не используется (D-12).
**FR-WRITE-2 (P0).** Перед записью область выделена (Selection уже есть; для `WholeField` — по FR-SCOPE-3; для `LineFragment` — через UIA TextPattern `Select`).
**FR-WRITE-3 (P0).** `SendInput` допустим, только если: длина ≤ порога (по умолчанию 200 [A-25]), текст **не содержит переводов строк** [A-26], профиль разрешает. Иначе — буфер.
- AC1 (I): текст с переводом строки и длиной 10 → путь «буфер», ни одного `VK_RETURN` в журнале ввода.
**FR-WRITE-4 (P0).** Никогда не отправлять `VK_RETURN`/`VK_TAB` как часть вставки текста конвертации. В чатах многострочный текст вставляется только через буфер.
- AC1 (M): Telegram, Discord, WhatsApp: многострочное сообщение после конвертации **не отправлено**.
**FR-WRITE-5 (P0).** Суррогатные пары (эмодзи) через `SendInput` отправляются двумя последовательными UTF-16 событиями; если профиль сообщает о проблемах — путь «буфер».
**FR-WRITE-6 (P0).** После успешной замены одно нажатие Ctrl+Z в целевом приложении возвращает исходный текст области (D-12) — **для приложений, где это отмечено в матрице как требование**; для остальных — фиксируется фактическое поведение (Q-18).
- AC1 (M): по матрице — колонка «Ctrl+Z».
**FR-WRITE-7 (P1).** После записи KeySwitch не перемещает каретку; ожидаемое положение — конец вставленного текста (поведение вставки приложения). Не является требованием, если приложение ведёт себя иначе (ТЗ §8).
**FR-WRITE-8 (P1).** Верификация: если UIA позволяет прочитать результат, KeySwitch сравнивает итог области с ожидаемым (с учётом нормализации переводов строк приложением); несовпадение → `VERIFY_FAILED` в журнале, **без повторных попыток и без автоматического отката** [A-27].

### 7.7 FR-CLIP — Буфер обмена (ТЗ §9, D-13)

**FR-CLIP-1 (P0).** Перед использованием буфера — снимок всех форматов, данные которых можно прочитать и восстановить (включая материализацию отложенной отрисовки, если источник отвечает в пределах 500 мс [A-28]).
**FR-CLIP-2 (P0).** Если хотя бы один формат несохраним → не использовать буфер: `SendInput` (если допустимо FR-WRITE-3) или отказ `CLIPBOARD_UNSAFE`.
**FR-CLIP-3 (P0).** Временное содержимое помечается форматами исключения: `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory=0`, `CanUploadToCloudClipboard=0` (D-13).
- AC1 (I): во время операции буфер содержит эти три формата. AC2 (M): Win+V не показывает конвертированный текст.
**FR-CLIP-4 (P0).** Непосредственно перед Ctrl+V сверяется sequence number; изменился → вставка не отправляется, `CLIPBOARD_CHANGED`. После вставки — ожидание потребления (по профилю, по умолчанию 150 мс [A-29]) и восстановление, только если sequence number равен записанному KeySwitch.
- AC1 (I): стороннее тестовое приложение пишет в буфер между put и paste → вставки нет. AC2 (I): пишет после paste → буфер не восстановлен, содержимое стороннего приложения сохранено.
**FR-CLIP-5 (P0).** Восстановление побайтно идентично для форматов: CF_UNICODETEXT, CF_TEXT, HTML Format, Rich Text Format, CF_DIB/CF_DIBV5, CF_HDROP, CSV, Preferred DropEffect и зарегистрированные форматы с HGLOBAL-данными.
- AC1 (I): набор фикстур (текст; HTML+текст; RTF+HTML+текст; bitmap; файлы из проводника; Excel-подобный набор из ≥ 6 форматов) → после операции содержимое совпадает побайтно.
**FR-CLIP-6 (P0).** Пустой буфер восстанавливается в пустой.
**FR-CLIP-7 (P0).** Если восстановление завершилось ошибкой — повтор до 3 раз за 500 мс; затем `CLIPBOARD_NOT_RESTORED` в журнал и индикация в трее (не всплывающее уведомление) [A-30, Q-02].

### 7.8 FR-LAYOUT — Переключение раскладки

**FR-LAYOUT-1 (P0).** После `OK` раскладка целевого окна переключается на раскладку целевого языка (RU 00000419 или EN 00000409; если установлена другая раскладка того же языка — первая установленная этого языка [A-31]).
- AC1 (I): тестовое окно, раскладка EN, конвертация EN→RU → `GetKeyboardLayout` потока окна = RU.
**FR-LAYOUT-2 (P0).** При любом отказе раскладка не меняется. **FR-LAYOUT-3 (P1).** Нет раскладки целевого языка → замена выполняется, переключение пропускается, `LAYOUT_NOT_INSTALLED`.

### 7.9 FR-PROF — Профили приложений

**FR-PROF-1 (P0).** Профили (`app-profiles.toml`) поставляются с приложением, содержат только записи для приложений со статусом «Pass» в матрице; каждая запись ссылается на протокол ручной проверки.
**FR-PROF-2 (P0).** Неизвестное приложение: `WholeField` только для однострочного Edit; многострочные — `LineFragment`/`Selection`; запись только через буфер для текста > 50 символов [A-32]; при отсутствии UIA TextPattern — только `Selection`, если выделение можно прочитать без буфера, иначе отказ.
**FR-PROF-3 (P2).** Пользователь не редактирует профили в v1 (только список исключений).

### 7.10 FR-HK — Горячие клавиши (ТЗ §10, D-14)

**FR-HK-1 (P0).** Две независимые клавиши: «Конвертация» и «Запуск макроса». Регистрация — только `RegisterHotKey`.
**FR-HK-2 (P0).** Допустимое сочетание: 2–3 клавиши; ровно одна не-модификаторная; хотя бы один из Ctrl/Alt/Win; Shift + печатный символ без других модификаторов — запрещено [A-33].
- AC1 (U): валидатор отклоняет `Ctrl+Shift`, `Q`, `Shift+Q`, `Ctrl+Alt+Shift+Q` (4 клавиши); принимает `Ctrl+Q`, `Alt+Z`, `Ctrl+Alt+Q`, `Ctrl+Shift+Space`.
**FR-HK-3 (P0).** Запрещены: совпадение двух клавиш KeySwitch; системные/критичные (`Ctrl+C/V/X/Z/Y/A/S`, `Alt+F4`, `Alt+Tab`, `Ctrl+Esc`, `Win+L`, `Ctrl+Alt+Del`). Предупреждение (можно сохранить): список «часто занятых приложениями» [A-08].
**FR-HK-4 (P0).** Ошибка `RegisterHotKey` → сообщение «Сочетание занято другой программой или системой», прежняя клавиша остаётся активной; при старте — статус «Не активна» в Hotkeys/Overview и в трее.
- AC1 (I): тестовый процесс заранее регистрирует `Ctrl+Alt+Q` → попытка сохранить его в KeySwitch → ошибка, предыдущая клавиша зарегистрирована.
**FR-HK-5 (P0).** Значения по умолчанию — решение владельца (Q-05b). До решения значения по умолчанию для релиза не выбираются; в сборках разработки — `Ctrl+Alt+Q` (конвертация) и `Ctrl+Alt+M` (макрос) [A-34].
**FR-HK-6 (P0).** Горячая клавиша срабатывает независимо от текущей раскладки (по виртуальной клавише).
- AC1 (M): при раскладке RU `Ctrl+Alt+Q` срабатывает.

### 7.11 FR-TRAY — Трей и фоновая работа (ТЗ §13)

**FR-TRAY-1 (P0).** Значок в трее с состояниями: «Активно», «Отключено», «Внимание» (горячая клавиша не зарегистрирована / буфер не восстановлен / ошибка песочницы) [A-35]. Подсказка значка — статус словами.
**FR-TRAY-2 (P0).** Меню: Открыть KeySwitch · Включено (флажок) · Macro Studio · Настройки · Выход.
**FR-TRAY-3 (P0).** «Отключено» → обе горячие клавиши **разрегистрированы** (сочетания доходят до приложений); «Включено» → регистрируются снова; ошибка регистрации → состояние «Внимание».
- AC1 (I): после отключения тестовое окно получает `WM_KEYDOWN` для сочетания.
**FR-TRAY-4 (P1).** Состояние «Отключено» после перезапуска: [Q-19] рекомендация — сбрасывается во «Включено» (отключение «временное», ТЗ §13).
**FR-TRAY-5 (P0).** Нет уведомлений об успехе. Никаких всплывающих тостов, кроме ошибок, требующих действия пользователя (Q-02).
**FR-TRAY-6 (P0).** «Выход» ждёт завершения текущей операции (≤ 3 с) и восстановления буфера, затем завершает процесс песочницы.
**FR-TRAY-7 (P0).** Автозапуск — запись в `HKCU\...\Run` (без прав администратора), по умолчанию **выключен** [A-36, Q-20]; при автозапуске окно не показывается.
- AC1 (M): включить автозапуск → перезагрузка → значок в трее, окна нет. Выключить → запись удалена.
**FR-TRAY-8 (P0).** Single instance: второй запуск активирует окно первого и завершается.
**FR-TRAY-9 (P0).** Закрытие окна — скрытие в трей; WebView освобождается, если это необходимо для NFR-PERF-3 [A-10].

### 7.12 FR-MACRO — Macro Studio (ТЗ §11, D-06…D-08)

**FR-MACRO-1 (P0).** Один слот; тип: Текст / JavaScript / Python. Смена типа при непустом содержимом — подтверждение (содержимое другого типа не теряется молча [A-37]).
**FR-MACRO-2 (P0).** Редактор CodeMirror 6: подсветка JS и Python, номера строк, отметка ошибок, отмена/повтор, поиск; индикатор «есть несохранённые изменения»; выход с несохранёнными изменениями — подтверждение.
**FR-MACRO-3 (P0).** Текстовый макрос: простой текст ≤ 5 000 code points, переводы строк допустимы; без шаблонных переменных в v1 [A-38]. Вставка — через буфер, если есть переводы строк (FR-WRITE-3/4).
**FR-MACRO-4 (P0).** Проверка синтаксиса JS/Python выполняется в песочнице (compile-only) по кнопке и при сохранении; ошибки — строка, столбец, сообщение. Сохранение с ошибками разрешено, запуск по горячей клавише — нет (`MACRO_COMPILE_ERROR`) [A-39].
**FR-MACRO-5 (P0).** Горячая клавиша запускает **последнюю сохранённую** версию слота (D-06).
**FR-MACRO-6 (P0).** Контекст: `text` — выделение или поле по настройке слота (область по правилам FR-SCOPE, политика FR-POL); если область недоступна — `text = null`, скрипт всё равно выполняется [A-40]; `clipboard` — только при включённом флаге слота, иначе `null` (D-07); флаг заметно отображается в UI.
**FR-MACRO-7 (P0).** Результат: `{insert}` | `{replace}` | `{keys: [AllowedKey]}` | `null`. Проверка — в `ks-engine` после песочницы. `AllowedKey` = Enter, Tab, ←, →, ↑, ↓, Backspace, Delete, Home, End (D-07); максимум 50 клавиш за запуск [A-41]. Любой недопустимый элемент → отклоняется **весь** результат (`MACRO_POLICY`).
- AC1 (U): fuzz-тест десериализации результата: любой ключ вне списка → отказ; нет частичного исполнения.
**FR-MACRO-8 (P0).** Лимиты: время выполнения скрипта 2 с (без инициализации рантайма), память 64 МБ, без дочерних процессов, без сети, без ФС, без env (D-08, архитектура §6).
- AC1 (I, Windows CI): набор враждебных скриптов T-01/T-12 (fs, net, subprocess, env, ctypes, fork-bomb, бесконечный цикл, 4 ГБ) — все завершаются отказом, система не затронута.
**FR-MACRO-9 (P0).** Длина `insert`/`replace` ≤ 5 000 code points [предложение, C-06/Q-08]; больше → `MACRO_OUTPUT_TOO_LARGE`.
**FR-MACRO-10 (P0).** Ошибки выполнения: в Macro Studio — панель «Последний запуск» (время, результат, сообщение, номер строки, stdout/stderr ≤ 10 000 символов) — хранится только в памяти до перезапуска [A-42]; в Diagnostics — только код и тип ошибки.
**FR-MACRO-11 (P0).** «Тестовый запуск» в редакторе с вводимым вручную тестовым `text` — действие не применяется к другим приложениям, показывается результат [A-43].
**FR-MACRO-12 (P0).** Политика D-05 применяется к макросам (Q-09): в поле пароля, elevated, исключённом приложении — отказ.
**FR-MACRO-13 (P0).** Целостность рантаймов: SHA-256 `quickjs.wasm`/`python.wasm` проверяется при загрузке; несовпадение → `SANDBOX_INTEGRITY` (T-13).

### 7.13 FR-UI — Интерфейс, темы, локализация (ТЗ §2, §12)

**FR-UI-1 (P0).** Разделы: Overview, Languages & Layouts, Hotkeys, Macro Studio, Settings, Diagnostics; навигация — боковая панель; все разделы доступны с клавиатуры.
**FR-UI-2 (P0).** Overview: статус (Активно/Отключено/Внимание), горячие клавиши и их статус регистрации, краткая инструкция, ссылка на список поддерживаемых приложений (из матрицы, честные статусы).
**FR-THEME-1 (P1).** Dark/Light/System; System — по `AppsUseLightTheme`, реакция на смену ≤ 1 с; выбор сохраняется.
**FR-I18N-1 (P1).** RU/EN; язык по умолчанию — по языку интерфейса Windows (ru-* → RU, иначе EN) [A-13]; переключение без перезапуска; словари — JSON-файлы, новый язык = новый файл; русские плюральные формы (1 запись / 2 записи / 5 записей).
- AC1 (R/U): все ключи присутствуют в обоих словарях (тест в CI); нет захардкоженных строк в компонентах (линтер/тест).
**FR-UI-3 (P1).** Диалог смешанного текста, меню трея и сообщения об ошибках горячих клавиш локализованы.

### 7.14 FR-SET — Настройки

**FR-SET-1 (P0).** Настройки и слот макроса хранятся локально (`%APPDATA%\KeySwitch\`), применяются немедленно, переживают перезапуск.
**FR-SET-2 (P0).** Повреждение хранилища → значения по умолчанию, предупреждение, исходный файл переименовывается в резервную копию (не удаляется) (ТЗ §18).
**FR-SET-3 (P0).** «Сбросить настройки» не удаляет макрос; удаление макроса — отдельное действие с подтверждением.
**FR-SET-4 (P1).** Порог SendInput (0–500, 0 = всегда буфер), звук при отказе (Q-02), список исключений (FR-POL-3), язык, тема, автозапуск.

### 7.15 FR-DIAG — Диагностика

**FR-DIAG-1 (P0).** Журнал: время, тип операции, имя exe, область, способ записи, код результата, длительность (мс), версия профиля. Ротация 1 000 записей.
**FR-DIAG-2 (P0).** В журнале нет: текста пользователя, заголовков окон, URL, содержимого буфера, имён файлов, текста скрипта, сообщений исключений скрипта (могут содержать текст).
- AC1 (U/R): тест с маркерной строкой `KS_CANARY_7f3a` во всех путях (успех, каждый отказ, ошибка макроса с `raise Exception("KS_CANARY_7f3a")`) — маркер не найден в БД, файлах `%APPDATA%\KeySwitch`, stdout/stderr процесса.
**FR-DIAG-3 (P1).** Очистка журнала; «Скопировать отчёт» без текста пользователя [A-14].
**FR-DIAG-4 (P1).** «Проверка текущего поля» — показывает метаданные фокусного элемента (ControlType, флаги, классификация, профиль, допустимая область) без текста.

### 13.3 Требования, которые в текущей формулировке непроверяемы

| ID | Формулировка | Почему непроверяемо | Предлагаемая проверяемая замена |
|----|-------------|---------------------|-------------------------------|
| U-01 | «Максимально широкий набор приложений» (ТЗ §7) | Нет конечного списка и критерия | Матрица `pa-app-matrix.md` + консервативный профиль для неизвестных + критерий «никогда не повреждать» (FR-PROF-2) |
| U-02 | «Не изменять весь документ случайно» (ТЗ §7) | Нельзя доказать для всех приложений | FR-SCOPE-3 AC1 (Ctrl+A не отправлен для Document) + ручная проверка по матрице |

| U-07 | «Безопасная замена» (ТЗ §11 API) | Не определено | FR-ABORT-1 + FR-POL + FR-SCOPE применяются к `replace` макроса |
