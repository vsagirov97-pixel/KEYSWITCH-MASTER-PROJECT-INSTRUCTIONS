# KeySwitch — Матрица поддержки целевых приложений (v1)

Статус: **предложение для GATE 1** · Автор: AGENT 02 Product Analyst · Дата: 2026-11-09
Связано: `pa-prd.md` (FR-SCOPE, FR-POL, FR-WRITE, FR-CLIP, FR-PROF), `pa-edge-cases.md`.

> **Ни одна строка не проверена.** Все статусы — `UNVERIFIED — requires test`. Колонки «Технология/UIA» и «Ожидаемое поведение» — **допущения аналитика** о том, как приложение, вероятно, выглядит для UI Automation и как KeySwitch *должен* себя вести по D-03/D-04/D-05. Фактическое поведение UIA каждого приложения выясняется в S-2 и при ручной приёмке (D-10). Указание владельца: **не обещать универсальную поддержку без тестов** — поэтому в UI и документации приложение может называться «поддерживаемым» только после статуса Pass.

## 1. Уровни поддержки и что значит Pass

### 1.1 Уровни (минимум для выпуска v1)

| Уровень | Смысл | Влияние на релиз |
|---------|-------|------------------|
| **L-REQ — Обязательно** | Приложение должно получить Pass по всем обязательным для него проверкам. | Fail любой обязательной проверки **блокирует релиз v1** (GATE 5/9). |
| **L-BEST — Желательно** | Цель — Pass; допускается выпуск с «Ограниченно» (часть областей — отказ), если безопасность (S-проверки) — Pass. | Fail S-проверки блокирует релиз; Fail функциональной проверки — известное ограничение в документации. |
| **L-REFUSE — Только отказ** | Ожидаемое поведение — безопасный отказ. | Pass = KeySwitch гарантированно ничего не меняет. Fail блокирует релиз. |

### 1.2 Набор проверок для каждой строки
Каждая проверка выполняется вручную на реальной Windows 10 22H2 **и** Windows 11 (23H2/24H2) по чек-листу (D-10). Проверка имеет результат Pass / Fail / N/A и ссылку на протокол.

**Проверки безопасности (S) — обязательны для всех строк любого уровня:**
| ID | Проверка | Pass, если |
|----|----------|-----------|
| S1 | Нет порчи вне области | Текст вне выделения/поля/фрагмента побайтно не изменён (сравнение по UIA или по сохранённому файлу/скриншоту до/после) |
| S2 | Буфер сохранён | После операции буфер содержит исходные данные (проверка: скопировать текст+картинку, выполнить операцию, вставить в Paint/Word) |
| S3 | Пароль | В поле пароля приложения (если есть) — отказ `PASSWORD`, ничего не вставлено |
| S4 | Нет непреднамеренных действий | Не отправлено сообщение, не выполнена команда, не открыто меню, не закрыто окно |
| S5 | Win+V | В истории буфера нет конвертированного текста |
| S6 | Смена фокуса | Переключение в другое окно во время диалога смешанного текста → отказ, другое окно не получило ввода |

**Функциональные проверки (F) — обязательны по колонке «Обязательные F» строки:**
| ID | Проверка | Pass, если |
|----|----------|-----------|
| F1 | Поле/фрагмент без выделения | `Ghbdtn, rfr ltkf?` → `Привет, как дела?` в ожидаемой области |
| F2 | Выделение | Выделенное `ytn` внутри текста → `нет`, остальное не изменено |
| F3 | Многострочный текст | Многострочное содержимое (области по колонке «Ожидаемое») обработано, переводы строк сохранены |
| F4 | Смешанный текст | `Привет, rfr ltkf?` → диалог → «Русский» → `Привет, как дела?`; «Отмена» → без изменений |
| F5 | RU→EN | `Руддщб цщкдв!` → `Hello, world!` |
| F6 | Раскладка | После успеха раскладка окна = целевая |
| F7 | Ctrl+Z | Одно нажатие Ctrl+Z возвращает исходный текст области (D-12; см. Q-18) |
| F8 | Длинный текст | 4 900 символов — обработано ≤ 1 с; 5 100 — отказ `TOO_LONG` без изменений |
| F9 | Макрос | Текстовый макрос (с переводом строки) вставлен в позицию каретки, сообщение не отправлено |
| F10 | Эмодзи | Текст с эмодзи `rfr ltkf 😀` → `как дела 😀`, эмодзи не повреждён |

**Pass строки** = все S-проверки Pass **и** все обязательные F-проверки Pass на обеих версиях Windows. **Ограниченно** = все S Pass, часть F Fail/N/A с явной записью «что не поддерживается». **Fail** = любой S Fail (для любого уровня) или обязательный F Fail для L-REQ.

Понижение Excel/Discord/WhatsApp до L-BEST — потому что ТЗ §7 говорит «максимально широкий набор», а не «гарантированно все», и указание владельца запрещает обещать без тестов. **Требует подтверждения владельца** (вопрос MQ-1).

## 4. Правила ведения матрицы
1. Статус меняется только на основании протокола ручной проверки (дата, версия Windows, версия приложения, версия KeySwitch, проверяющий, результат каждой проверки). Без протокола — `UNVERIFIED`.
2. Версия приложения фиксируется: обновление приложения (особенно Electron/Store) может изменить UIA-поведение. Pass действителен для проверенной версии; повторная проверка перед каждым релизом KeySwitch [A-M2].
3. Профиль в `app-profiles.toml` добавляется только для строк со статусом Pass/Ограниченно и ссылается на протокол (FR-PROF-1).
4. В UI (Overview) и в документации отображается список с честным статусом: «Проверено», «Ограниченно (что именно)», «Не проверено».
5. Fail S-проверки на любой строке → дефект P0 и блокировка релиза, даже если строка L-BEST.

## 5. Открытые вопросы по матрице
- **MQ-1.** Утвердить уровни (§3): особенно — остаётся ли Telegram L-REQ, если его UIA окажется недостаточным, и согласен ли владелец на L-BEST для Excel/Discord/WhatsApp.
- **MQ-2.** Какие версии приложений считать эталонными (последняя стабильная на дату приёмки?) — рекомендация: последняя стабильная на дату приёмки, фиксируется в протоколе.
- **MQ-3.** Excel: допустима ли конвертация ячейки с формулой? Рекомендация: отказ.
- **MQ-4.** VS Code: достаточно ли «только выделение» (без Line) для v1? Рекомендация: да.
- **MQ-5.** Нужна ли проверка на Windows 10 и Windows 11 для каждой строки, или достаточно одной ОС для L-BEST? Рекомендация: обе для L-REQ, одна (Windows 11) для L-BEST.
