## 1. Визуальная концепция: «Professional Developer Tools»

KeySwitch — утилита, которая 99% времени невидима. Главное окно открывают редко: настроить горячие клавиши, написать макрос, разобраться, почему операция отменилась. Поэтому окно должно ощущаться как **инструмент**, а не как «приложение-витрина»: плотное, спокойное, предсказуемое, с хорошей типографикой и честной диагностикой.

Ориентиры — общие принципы современных IDE и редакторов кода (не брендинг, не конкретный продукт):

| Принцип | Как применяется в KeySwitch |
|---|---|
| **Хром отступает, содержимое — главное** | Нейтральные тёмные/светлые поверхности, один акцентный цвет, без градиентов, иллюстраций и декоративных теней. Цвет несёт смысл (статус, фокус, ошибка), а не украшает. |
| **Левая навигация + рабочая область + строка состояния** | Узкий сайдбар с 6 разделами, заголовок раздела с действиями справа, нижняя строка состояния (статус службы, активные горячие клавиши, «Локально · без сети»). |
| **Плотность «средняя»** | Базовая сетка 4 px, высота контролов 32 px (компактно, но удобно для мыши и тача на ноутбуке), текст 13–14 px. |
| **Моноширинный шрифт там, где это данные** | Горячие клавиши (`Ctrl` `Shift` `Space` как «клавиши-чипы»), код макроса, коды причин в Diagnostics, время в логе. |
| **Панели как в IDE** | Macro Studio: редактор слева, панель свойств справа, нижняя панель «Проблемы / Вывод» с номерами строк и переходом к ошибке. |
| **Команды доступны с клавиатуры** | Ctrl+S — сохранить, F5 — тестовый запуск, Shift+F5/Ctrl+Shift+B — проверить, Ctrl+1…6 — переход между разделами. |
| **Тишина по умолчанию** | Никаких всплывающих «Готово!». Состояние видно там, где на него смотрят: в строке состояния, в иконке трея, в журнале. |
| **Честность** | Если функция не поддерживается или отключена — так и написано, с причиной и следующим шагом. Никаких обещаний «работает везде». |

**Тон текстов:** короткий, нейтральный, без восклицательных знаков и маркетинга. Глаголы в кнопках («Проверить», «Запустить», «Переназначить»). Ошибка = что случилось + почему + что сделать.

**Акцентный цвет:** предлагается спокойный синий (`#2D6AD6` / `#1F5FCC`) — нейтральный, хорошо различимый и безопасный по контрасту в обеих темах. Окончательный выбор — **[OWNER]** (альтернативы в разделе 9).

**Иконка приложения и трея** — отдельная задача; в прототипе используется абстрактный знак (две стрелки-«переключатель» в квадрате), без отсылок к чужим брендам.

## 2. Информационная архитектура

```
KeySwitch
├── Главное окно (min 720×480, по умолчанию 1040×680)
│   ├── 1. Обзор (Overview)                 Ctrl+1
│   ├── 2. Языки и раскладки (Languages)    Ctrl+2
│   ├── 3. Горячие клавиши (Hotkeys)        Ctrl+3
│   ├── 4. Macro Studio                     Ctrl+4
│   ├── 5. Настройки (Settings)             Ctrl+5
│   │     ├── Общие (автозапуск, язык UI, тема)
│   │     ├── Поведение (звук при отказе, способ вставки)
│   │     ├── Исключения (список приложений)
│   │     └── Приватность и «О программе»
│   └── 6. Диагностика (Diagnostics)        Ctrl+6
│         ├── Состояние компонентов
│         └── Журнал операций (только метаданные)
├── Меню трея (основная точка входа в фоне)
├── Окно выбора языка для смешанного текста (отдельное мини-окно поверх всех)
├── Контрол захвата горячей клавиши (используется в Hotkeys и в онбординге)
└── Первый запуск (онбординг, 3 шага, в главном окне)
```

**Почему именно так:**
- Разделы упорядочены по частоте и «глубине»: Обзор (статус) → настройка основной функции (Языки, Клавиши) → продвинутое (Macro Studio) → редкое (Настройки, Диагностика).
- Название **Macro Studio** — имя собственное функции, не переводится (в RU-интерфейсе так и пишется). Остальные разделы переводятся.
- «Горячие клавиши» — отдельный раздел, а не часть Настроек: это главная пользовательская настройка, конфликты с другими приложениями — частая проблема.
- Список исключений (D-05) — в Настройках, но со ссылкой из Диагностики («Операция отклонена: приложение в исключениях → Открыть исключения»).

### 2.1. Навигация между поверхностями
- Трей → «Открыть KeySwitch» → последний открытый раздел (или Обзор).
- Трей → «Macro Studio» → главное окно, раздел Macro Studio (D-06: горячая клавиша макроса запускает макрос, а не открывает редактор).
- Трей → «Настройки» → раздел Настройки.
- Иконка трея с состоянием ошибки → клик открывает Диагностику.
- Закрытие главного окна (крестик) **не завершает приложение** — сворачивает в трей. Выход — только «Выход» в трее (и Alt+F4 → то же поведение, что крестик). Первое закрытие показывает однократную встроенную подсказку в окне перед скрытием? — **нет**: это была бы лишняя модальность. Вместо этого на шаге 3 онбординга явно сказано «Закрытие окна сворачивает KeySwitch в трей».

│   Языки      │                                                           │
│   Горячие кл.│              Рабочая область раздела                      │

│   Настройки  │                                                           │
│   Диагност.  │                                                           │
│              │                                                           │
│ ───────────  │                                                           │

│ ● Активно │ Конвертация Ctrl+Shift+Space │ Макрос Ctrl+Alt+M │ Локально  │

- **Сайдбар**: 224 px; при ширине окна < 900 px сворачивается до 56 px (только иконки, подписи — во всплывающей подсказке и в `aria-label`). Внизу сайдбара — переключатель «Активно / Приостановлено».
- **Заголовок раздела**: H1 20 px/600, справа — основные действия (например, в Macro Studio: «Проверить», «Запустить тест», «Сохранить»).
- **Строка состояния** (24 px): статус службы, текущие горячие клавиши, индикатор «Локально · без сети» (информационный, не кликабельный), в Macro Studio — позиция курсора и «Не сохранено».
- **Заголовок окна** — нативный (рекомендация): меньше кода, корректная работа Snap Layouts, доступности и DPI. Кастомный заголовок — **[OWNER]/[ARCH]**.
- Тема и язык интерфейса меняются в Настройках; в прототипе для удобства вынесены в верхнюю панель.

## 4. Экраны (wireframe-описание)

Для каждого экрана: регионы → компоненты → содержимое → состояния (пусто / ошибка / отключено).

### 4.1. Обзор (Overview)

**Назначение:** за 2 секунды ответить «работает ли KeySwitch и какими клавишами».

Регионы:
1. **Карточка статуса** (во всю ширину): крупный индикатор `● Активно` / `◌ Приостановлено до 14:30` / `▲ Требует внимания`; кнопка «Приостановить ▾» (меню: 15 минут, 1 час, до перезапуска) или «Возобновить».
2. **Сетка из 3 карточек** (2 колонки при < 960 px):
   - «Конвертация раскладки» — сочетание (клавиши-чипы), пара `EN ⇄ RU`, ссылка «Изменить».
   - «Макрос» — тип слота (Текст / JavaScript / Python), состояние (Включён / Выключен / Ошибка проверки), сочетание, ссылка «Открыть Macro Studio».
   - «Последняя операция» — только метаданные: «2 мин назад · telegram.exe · Конвертация · Выполнено». Ссылка «Журнал».
3. **Подсказка «Как это работает»** (свёрнутая по умолчанию после онбординга): 3 строки с примером `Ghbdtn` → `Привет` (пример — статичный текст интерфейса, не пользовательские данные).

Состояния:
- **Пусто** (ещё не было операций): карточка «Последняя операция» — «Операций пока не было. Нажмите Ctrl+Shift+Space в любом текстовом поле».
- **Ошибка**: горячая клавиша не зарегистрирована → статус `▲ Требует внимания`, inline-алерт «Сочетание Ctrl+Shift+Space занято другим приложением. [Переназначить]». Раскладка RU не установлена в Windows → алерт со ссылкой на раздел «Языки».
- **Отключено** (пауза): карточки приглушены (не disabled — данные читаемы), сверху баннер «KeySwitch приостановлен до 14:30. Горячие клавиши не перехватываются». **[ARCH]**: в паузе горячие клавиши должны быть *сняты с регистрации* (`UnregisterHotKey`), чтобы их могли использовать другие программы.

### 4.2. Языки и раскладки (Languages & Layouts)

Регионы:
1. **Языковая пара** — карточка `English (US QWERTY) ⇄ Русский (ЙЦУКЕН)`:
   - статус каждой раскладки в Windows: «Установлена» / «Не найдена в системе» (с инструкцией, как добавить через параметры Windows; без автоматического изменения системы);
   - направление: текст-пояснение «Направление определяется по составу текста; активная раскладка учитывается только при равенстве» (D-02);
   - переключатель «После исправления переключать раскладку на целевой язык» — **по умолчанию вкл.**, см. FR-FIELD-6; нужно ли делать его отключаемым — **[OWNER]**.
2. **Песочница проверки** («Попробовать»): поле ввода внутри окна KeySwitch + результат конвертации + определённое направление и уверенность («Высокая / Низкая — замена была бы отменена»). Явная подпись: «Текст из этого поля не сохраняется и не записывается в журнал». **[SEC]**: подтвердить, что этот текст проходит через `UserText` и не попадает в логи; поле — `autocomplete=off`, `spellcheck=false`.
3. **Другие языки**: строка «Поддержка других языков (украинский, немецкий, французский…) появится в следующих версиях» — без неактивных фейковых кнопок.

Состояния: раскладка отсутствует → предупреждение (warning), конвертация в эту сторону всё равно работает (по скан-кодам), но переключение раскладки невозможно — **[ARCH]** уточнить поведение.

### 4.3. Горячие клавиши (Hotkeys)

Регионы:
1. Таблица из двух строк (не карточки — так проще выравнивать и читать):

| Действие | Сочетание | Состояние | |
|---|---|---|---|
| Исправить раскладку | `[ Ctrl ][ Shift ][ Space ]` (контрол захвата) | ● Зарегистрировано | «По умолчанию» |
| Запустить макрос | `[ Ctrl ][ Alt ][ M ]` | ● Зарегистрировано | «По умолчанию» |

2. Под таблицей — правила (вспомогательный текст): «2–3 клавиши, обязательно одна обычная клавиша (не только Ctrl/Alt/Shift/Win). Сочетания, занятые Windows, недоступны».
3. Блок «Как KeySwitch обрабатывает нажатие» — справка: ожидание отпускания модификаторов до 1 с, иначе отмена (FR-HK-4).

Состояния строки: `Зарегистрировано` (success), `Конфликт: занято другим приложением` (danger), `Совпадает с «Запустить макрос»` (danger), `Не задано` (neutral, действие отключено), `Приостановлено` (neutral — при паузе).

### 4.4. Контрол захвата горячей клавиши (Hotkey capture)

Отдельный компонент (спека в `design-system.md` §8.8). Поведение:

1. **Покой**: поле с клавишами-чипами `Ctrl` `Shift` `Space` и кнопкой-иконкой «✕ Очистить».
2. **Клик / Enter / Space на поле** → режим записи: рамка акцентная, пульсирующая точка, текст «Нажмите сочетание… (Esc — отмена)». **[ARCH]**: на время записи текущая глобальная регистрация этого действия временно снимается, иначе нажатие уйдёт в `RegisterHotKey`, а не в окно.
3. Пользователь зажимает модификаторы → чипы появляются по мере нажатия (живой предпросмотр).
4. Нажата обычная клавиша → сочетание фиксируется, запуск проверки:
   - только модификаторы / > 3 клавиш → inline-ошибка «Добавьте обычную клавишу» (D-14);
   - совпадает со вторым действием → ошибка «Уже используется для „Запустить макрос“»;
   - зарезервировано системой (Alt+Tab, Ctrl+Alt+Del, Win+L, Alt+F4, Ctrl+Esc, Win+…) → «Сочетание зарезервировано Windows»;
   - `RegisterHotKey` вернул ошибку → «Занято другим приложением. Выберите другое сочетание» + кнопки «Попробовать снова» и «Вернуть прежнее».
   - успех → состояние `Зарегистрировано`, без тоста.
5. **Esc** во время записи → отмена, возвращается прежнее сочетание. Tab во время записи — выход из записи (не захватывается), чтобы не создавать ловушку фокуса (WCAG 2.1.2).
6. Ошибочное сочетание **не сохраняется**: прежнее остаётся активным, пока новое не зарегистрировано успешно.

Использование Win-клавиши в сочетаниях: предлагается **не разрешать** в v1 (большинство Win-сочетаний занято системой, поведение непредсказуемо) — **[OWNER]/[ARCH]**.

### 4.5. Macro Studio

Компоновка «как в IDE»:

```
┌ Заголовок: Macro Studio · Слот 1        [Проверить] [▶ Запустить тест] [Сохранить] ┐
├ Тулбар: Тип [Текст|JavaScript|Python]  ● Включён   Горячая клавиша: Ctrl+Alt+M      ┤
├──────────────────────────────────────────────┬────────────────────────────────────┤
│ 1  // Макрос получает ctx и возвращает       │ Разрешения                         │
│ 2  // действие                               │  ○ Чтение буфера обмена   [off]    │
│ 3  export default function run(ctx) {        │  Контекст: [Выделение|Поле]        │
│ 4    const t = ctx.text.trim();              │ Лимиты (только чтение)             │
│ …  (редактор CodeMirror 6)                   │  Время 2 с · Память 64 МБ ·        │
│                                              │  Вывод 100 000 символов            │
│                                              │ Тестовые входные данные            │
│                                              │  [ textarea ]                      │
│                                              │ Справка API ▸                      │
├──────────────────────────────────────────────┴────────────────────────────────────┤
│ [Проблемы 1] [Вывод]                                                               │
│ ✕ Стр. 4, кол. 22  SyntaxError: ожидалась «)»                     [Перейти]        │
├────────────────────────────────────────────────────────────────────────────────────┤
│ Стр. 4, кол. 22 · JavaScript · Не сохранено                                        │
└────────────────────────────────────────────────────────────────────────────────────┘
```

Компоненты и содержимое:
- **Сегментированный выбор типа**: Текст / JavaScript / Python. Смена типа при непустом коде → модалка «Сменить тип? Текущий код будет сохранён как черновик этого типа» **[OWNER]**: хранить ли по черновику на тип или заменять. Предлагается хранить (дешево, защищает от потери данных).
- **Тип «Текст»**: обычное многострочное поле (без подсветки), счётчик символов, подсказка «Текст будет вставлен в позицию курсора». Панель разрешений скрыта (разрешений нет).
- **Тип JS/Python**: редактор кода (CodeMirror 6), моноширинный шрифт, номера строк, подсветка текущей строки, подчёркивание ошибок (wavy underline danger), шаблон по умолчанию с комментариями на языке интерфейса.
- **Разрешения** (D-07): «Чтение буфера обмена» — по умолчанию выкл., под тумблером пояснение «Макрос сможет прочитать текст из буфера обмена при запуске». Источник контекста: «Выделение» / «Всё поле» (US-08).
- **Лимиты** — только чтение (FR-MACRO-4), чтобы пользователь понимал, почему «долгий» скрипт остановлен.
- **Тестовые входные данные**: тестовый запуск выполняется **в той же песочнице** с текстом из этого поля (не из реального активного поля). Результат во вкладке «Вывод»: действие (`replace` / `insert` / `none`), длина результата, время выполнения, предпросмотр результата (это данные, введённые пользователем в само окно — не логируются).
- **Нижняя панель**: вкладки «Проблемы (N)» и «Вывод». Строка проблемы: иконка серьёзности, «Стр. X, кол. Y», сообщение, кнопка «Перейти» (фокус в редактор на позицию). Ошибки песочницы (превышение времени/памяти, запрещённый API) отображаются так же, с кодом (`E_TIMEOUT`, `E_MEMORY`, `E_FORBIDDEN_API`).
- **Справка API** — раскрывающийся список функций KeySwitch API (из `02-architecture.md` §6, контент — от архитектора).

Состояния:
- **Пусто**: слот без кода → empty state «Слот пуст. Выберите тип макроса и начните со шаблона» + кнопки «Текст», «JavaScript», «Python».
- **Ошибка проверки**: бейдж «Ошибка» у заголовка, макрос *не выполняется* по горячей клавише, пока ошибка не исправлена и не сохранено, — inline-алерт «Горячая клавиша макроса не будет работать, пока есть ошибки». **[ARCH]**: проверять при сохранении или разрешать сохранить с ошибкой (рекомендация: сохранять можно, но слот помечается невалидным).
- **Отключено**: тумблер «Включён» выкл. → редактор доступен, но статус «Макрос выключен; горячая клавиша не зарегистрирована».
- **Песочница недоступна** (runtime не загрузился): danger-алерт «Среда выполнения JavaScript недоступна. Подробности — в Диагностике», кнопки «Проверить»/«Запустить тест» disabled с подсказкой о причине.
- **Не сохранено**: точка в заголовке и в строке состояния; при уходе из раздела — диалог «Сохранить изменения?» (Сохранить / Не сохранять / Отмена).

### 4.6. Настройки (Settings)

Одна прокручиваемая страница с группами (якорное подменю слева внутри раздела при ширине ≥ 1100 px):

1. **Общие**: «Запускать вместе с Windows» (тумблер, HKCU Run), «Язык интерфейса» (select: Русский, English), «Тема» (сегменты: Тёмная / Светлая / Системная).
2. **Поведение**: «Звук при отмене операции» (тумблер; значение по умолчанию — Q-2, **[OWNER]**), «Способ вставки коротких текстов» (информационно/расширенно: «Автоматически» — по профилю приложения; порог ≤ 200 символов — FR-CLIP-1; показывать ли пользователю — **[ARCH]**).
3. **Исключения** (D-05): таблица приложений (`имя exe`, источник «По умолчанию»/«Добавлено вами», кнопка удаления только для своих). «Добавить приложение…» — ввод имени exe (без выбора файла через диалог ФС; **[ARCH]**: допустим ли нативный диалог выбора файла без плагина `fs`). Неудаляемые встроенные правила (поля паролей, окна администратора, secure desktop) показаны отдельным списком «Всегда исключено» с замком.
4. **Приватность**: статичный текст: «Весь текст обрабатывается на этом компьютере. KeySwitch не выполняет сетевых запросов, не собирает телеметрию и не хранит набранный текст». Без тумблеров (нечего отключать).
5. **О программе**: версия, версия ядра, «Сборка не подписана цифровой подписью» (D-11, пока актуально), лицензии компонентов (список).

Состояния: ошибка записи автозапуска → inline-алерт под тумблером, тумблер возвращается в прежнее положение.

### 4.7. Диагностика (Diagnostics)

Регионы:
1. **Баннер-принцип** (info, постоянный, не закрываемый): «Журнал содержит только метаданные: время, приложение, результат, причину. Текст, который вы набираете, и содержимое буфера обмена никогда не записываются».
2. **Состояние компонентов** (компактная сетка): Горячая клавиша конвертации · Горячая клавиша макроса · Раскладки EN/RU · Среда JS · Среда Python · Автозапуск — каждый со статусом-пилюлей.
3. **Журнал операций** — таблица:

| Время | Приложение | Операция | Объём | Способ | Результат | Причина | мс |
|---|---|---|---|---|---|---|---|
| 14:02:31 | telegram.exe | Конвертация | Поле | SendInput | ● Выполнено | — | 38 |
| 14:01:07 | winword.exe | Конвертация | Выделение | Буфер | ● Выполнено | — | 92 |
| 13:58:44 | keepass.exe | Конвертация | — | — | ◌ Отклонено | `EXCLUDED_APP` | 2 |
| 13:55:10 | chrome.exe | Макрос (JS) | Выделение | — | ✕ Ошибка | `E_TIMEOUT` | 2001 |

   - Фильтры (сегменты): Все / Выполнено / Отклонено / Ошибки; поиск по имени приложения.
   - Клик по строке → панель деталей (те же метаданные + человекочитаемое объяснение причины + ссылка-действие: «Открыть исключения», «Открыть Macro Studio»).
   - Действия: «Скопировать отчёт» (метаданные в буфер обмена, для баг-репорта), «Очистить журнал» (модалка подтверждения, т.к. удаление данных).
   - **Длину текста в журнал не пишем** (даже число символов — косвенная информация). **[SEC]**: подтвердить; допустима ли категория «> 5 000 символов» для причины `TOO_LONG`.
4. Пустое состояние: «Журнал пуст. Здесь появятся операции после первого нажатия горячей клавиши».

Коды причин — стабильные идентификаторы (`EXCLUDED_APP`, `PASSWORD_FIELD`, `ELEVATED_WINDOW`, `SECURE_DESKTOP`, `LOW_CONFIDENCE`, `TOO_LONG`, `FOCUS_CHANGED`, `CLIPBOARD_UNSAFE`, `MODIFIERS_TIMEOUT`, `MIXED_CANCELLED`, `E_TIMEOUT`, `E_MEMORY`, `E_FORBIDDEN_API`, `E_SCRIPT`) — список согласовать с архитектором **[ARCH]**; в UI показывается локализованное описание + код моноширинным.

### 4.9. Окно выбора языка для смешанного текста

Появляется только в сценарии US-04 (смешанный текст). Это **единственное** окно, которое KeySwitch показывает поверх чужих приложений.

```
┌──────────────────────────────────┐
│ Смешанный текст — исправить на:  │
│ ┌──────────────┐┌──────────────┐ │
│ │ 1  Русский   ││ 2  English   │ │
│ └──────────────┘└──────────────┘ │
│ Esc  Отмена — ничего не менять   │
│ ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬░░░░ (таймер)    │
└──────────────────────────────────┘
```

Правила:
- **Клавиатура**: `1` — Русский, `2` — English, `Esc` — Отмена. Также стрелки ←/→ + Enter, Tab между кнопками. Мышь — клик. Порядок вариантов фиксированный (не зависит от направления), чтобы выработался мышечный навык.
- **Позиция**: рядом с кареткой (под строкой, со сдвигом 8 px; если не помещается — над строкой; не выходит за границы монитора). Если позиция каретки неизвестна — центр монитора, на котором активное окно. **[ARCH]**: источник позиции каретки (GetGUIThreadInfo / UIA TextPattern) и надёжность для браузеров/Electron.
- **Фокус — минимально необходимый**: окно не должно ломать состояние целевого приложения. Варианты, требующие решения архитектора **[ARCH][SEC]**:
  - (a) окно без активации (`WS_EX_NOACTIVATE`), а клавиши 1/2/Esc временно регистрируются как горячие клавиши на время показа окна (до выбора/таймаута) — фокус не уходит из целевого поля вовсе;
  - (b) окно получает фокус; после выбора фокус возвращается в исходное окно, и перед заменой выполняется повторная проверка FR-FIELD-4 (тот же HWND/PID/RuntimeId), иначе отмена.
  Дизайн работает с обоими вариантами; (a) предпочтительнее для пользователя.
- **Таймаут**: автоматическая отмена через 10 с (полоса-индикатор, без звука) **[OWNER]** — значение. При `prefers-reduced-motion` — статичный текст «Отмена через 10 с». Потеря фокуса целевым окном / клик вне окна → Отмена.
- **Отмена = ничего не меняется** (текст и буфер). Это пишется в журнал как `MIXED_CANCELLED`.
- Окно **не показывает сам текст пользователя** (меньше площадь утечки при демонстрации экрана и проще). **[OWNER]**: показывать ли короткий предпросмотр результата — предлагается нет.
- Размер ~ 320×132 px, тень уровня `elevation-3`, тема — как у приложения. Доступность: роль `dialog`, `aria-labelledby` на заголовок, кнопки с `aria-keyshortcuts="1"`/`"2"`/`"Escape"`; при варианте (a) экранный диктор может не озвучить окно без фокуса — **[ARCH]** проверить с Narrator (UIA notification event).

### 4.10. Первый запуск (онбординг)

В главном окне, вместо обычной разметки — 3 шага с индикатором прогресса, «Назад»/«Далее», «Пропустить» на каждом шаге.

1. **Что делает KeySwitch** — пример `Ghbdtn, rfr ltkf?` → `Привет, как дела?` (статичная анимация-«перепечатка», отключаемая при reduced-motion), абзац о приватности («всё локально, без сети»). Проверка раскладок: если RU или EN не установлены — warning.
2. **Горячие клавиши** — два контрола захвата с предзаполненными значениями по умолчанию **[OWNER]: какие**, сразу с проверкой регистрации.
3. **Готово к работе** — тумблер «Запускать вместе с Windows» (по умолчанию **[OWNER]**; предлагается вкл., т.к. продукт фоновый), выбор темы, пояснение «Закрытие окна сворачивает KeySwitch в трей. Значок — в области уведомлений». Кнопка «Начать».

После онбординга открывается Обзор. Повторно — «Показать приветствие» в Настройках → О программе.

## 5. Ключевые пользовательские сценарии (flows)

### F-1. Назначить горячую клавишу при конфликте
1. Пользователь: Трей → «Открыть KeySwitch» → Горячие клавиши (или клик по алерту «Требует внимания» на Обзоре).
2. Строка «Исправить раскладку» показывает `✕ Конфликт: занято другим приложением`. Иконка трея — «требует внимания».
3. Клик по полю сочетания → режим записи («Нажмите сочетание… Esc — отмена»).
4. Нажимает `Ctrl+Alt+M` → «Уже используется для „Запустить макрос“». Прежнее значение не тронуто.
5. Нажимает `Ctrl+Shift+Space`… → `RegisterHotKey` не удался → «Занято другим приложением» + «Вернуть прежнее».
6. Нажимает `Ctrl+Alt+Q` → регистрация успешна → статус `● Зарегистрировано`; строка состояния и Обзор обновлены; иконка трея — обычная. Тоста нет.
7. Выход из записи: Esc отменяет текущую попытку, Tab уходит дальше.

### F-2. Смешанный текст
1. В чате: `Привет, rfr ltkf?`, нажата горячая клавиша.
2. KeySwitch проверяет безопасность (D-04/D-05), определяет смешанный текст → окно выбора у каретки; фокус целевого поля не теряется (вариант a) или возвращается (вариант b).
3. Пользователь нажимает `1` → окно закрывается мгновенно (без анимации выхода), текст заменён на `Привет, как дела?`, раскладка → RU. Уведомлений нет.
4. Альтернатива: `Esc` / клик вне / 10 с бездействия → ничего не меняется; запись `MIXED_CANCELLED` в журнале.
5. Альтернатива: после выбора фокус оказался в другом поле → отмена (`FOCUS_CHANGED`), опциональный звук.

### F-3. Написать и проверить JS-макрос с ошибкой
1. Трей → Macro Studio. Слот пуст → «JavaScript» → шаблон.
2. Пишет код, пропускает `)`. В строке состояния «Не сохранено».
3. `Ctrl+Shift+B` / «Проверить» → кнопка в состоянии loading («Проверка…», ≤ 2 с), проверка в песочнице.
4. Вкладка «Проблемы (1)» открывается автоматически: `✕ Стр. 4, кол. 22 — SyntaxError: ожидалась «)»`, в редакторе — волнистое подчёркивание и маркер в гуттере. Бейдж «Ошибка» у заголовка.
5. «Перейти» → курсор в позицию ошибки. Исправляет, снова «Проверить» → «Проблемы (0)», в панели «Ошибок нет» (это ответ на явное действие, а не уведомление об успехе — тихий текст, не тост).
6. Вводит тестовый текст, `F5` → во вкладке «Вывод»: `replace · 17 символов · 12 мс` + предпросмотр.
7. Пробует `fetch()` → «Проверить» → `E_FORBIDDEN_API: fetch недоступен в песочнице KeySwitch` (сообщение от песочницы; блокировка реальная, не текстовая — FR-MACRO, §11 ТЗ).
8. `Ctrl+S` → индикатор «Не сохранено» исчезает. Макрос активен по горячей клавише.

### F-4. Включить автозапуск
1. Настройки → Общие → «Запускать вместе с Windows» → тумблер вкл.
2. Тумблер меняется сразу (оптимистично), запись в HKCU Run; при ошибке — откат тумблера + inline-алерт «Не удалось включить автозапуск: …». Без тоста при успехе.
3. Диагностика → Состояние компонентов → «Автозапуск: включён».

### F-5. Временно отключить
1. Трей → Приостановить → 1 час (или тумблер в сайдбаре / кнопка на Обзоре).
2. Горячие клавиши снимаются с регистрации **[ARCH]**; иконка трея — «приостановлено»; tooltip «KeySwitch — приостановлен до 15:10».
3. В главном окне: статус в сайдбаре и строке состояния `◌ Приостановлено до 15:10`, баннер на Обзоре, строки Hotkeys со статусом «Приостановлено».
4. По истечении времени — автоматически возобновляется (тихо). «Возобновить» — в трее и на Обзоре.
5. Если при возобновлении сочетание оказалось занято → «Требует внимания» (F-1).

## 6. UX-правила

1. **Никаких уведомлений об успехе** (ТЗ §13). Ни системных toast, ни внутриоконных тостов «Сохранено!». Успех = исчезновение индикатора «Не сохранено», смена статуса-пилюли, обновлённое значение.
2. **Ошибки — inline, рядом с источником**. Тост/алерт в углу окна допускается только для асинхронной ошибки, не привязанной к видимому элементу (например, сбой песочницы во время фоновой проверки). Фоновые отказы операций (US-05/US-06) — только опциональный звук + журнал; системные уведомления Windows **не используются** в v1. Исключение для обсуждения **[OWNER]**: при старте не удалось зарегистрировать горячую клавишу — достаточно ли иконки трея «требует внимания»?
3. **Окно выбора языка** — только для смешанного текста; управление 1/2/Esc; у каретки или в центре экрана; минимально возможный захват фокуса (**[ARCH]** — см. §4.9).
4. **Безопасное значение по умолчанию**: если не ясно — отмена, а не замена. В UI это проговаривается («При низкой уверенности KeySwitch ничего не меняет»).
5. **Деструктивные действия** (очистить журнал, удалить исключение, сбросить макрос) — подтверждение модалкой с явной кнопкой-глаголом («Очистить журнал»), фокус по умолчанию — на «Отмена».
6. **Никакого скрытого состояния**: всё, что влияет на поведение (пауза, конфликт, макрос с ошибкой), видно в строке состояния и/или трее.
7. **Текст пользователя не появляется в UI**, кроме полей, куда пользователь сам вводит его в окне KeySwitch (песочница проверки, тестовые входные данные макроса). Эти поля помечены «не сохраняется».
8. **Мгновенная реакция**: переходы между разделами без анимации контента (≤ 120 мс фейд допустим); операции > 300 мс показывают состояние loading на инициирующей кнопке.
9. **Отключённые контролы объясняют причину** (подсказка/текст рядом), а не просто серые.

## 7. Доступность (WCAG 2.2 AA)

- **Контраст**: все пары «текст/фон» ≥ 4.5:1, крупный текст и нетекстовые элементы (границы полей, иконки-состояния, фокус-кольцо, дорожка тумблера) ≥ 3:1 — в обеих темах. Расчёт и таблица — `design-system.md` §2.4 (скрипт приложен). Цвет никогда не единственный носитель смысла: статус = цвет + иконка/форма + текст.
- **Фокус** (2.4.7, 2.4.11, 2.4.13): видимое кольцо 2 px `--ks-focus-ring` + отступ 2 px, только на `:focus-visible`; кольцо не перекрывается липкими панелями (scroll-padding). Порядок фокуса = визуальный порядок.
- **Клавиатура** (2.1.1, 2.1.2): все функции доступны без мыши; сайдбар — список ссылок со стрелками ↑/↓ (roving tabindex) и Ctrl+1…6; сегменты — радиогруппа (стрелки); вкладки — `tablist` (стрелки, Home/End); модалки — ловушка фокуса с возвратом на инициатор, Esc закрывает; контрол захвата — Esc/Tab выводят из записи (нет ловушки). Редактор кода: Tab по умолчанию вставляет отступ, **Esc затем Tab** выходит из редактора (стандартное поведение CodeMirror 6, нужна подсказка в UI).
- **Размер целей** (2.5.8): минимум 24×24 px; основные контролы 32 px.
- **Экранный диктор**: `nav aria-label="Разделы"`, `aria-current="page"` у активного раздела; контрол захвата — `role="button"`, `aria-describedby` на правила, во время записи `aria-live="polite"` сообщает «Запись сочетания. Нажмите клавиши» и затем результат; пилюли статуса содержат текст (не только цвет), журнал — настоящая `<table>` с `<th scope="col">`; ошибки форм связаны через `aria-describedby` и `aria-invalid`; панель «Проблемы» — `role="status"` при обновлении счётчика. Клавиши-чипы озвучиваются как «Control плюс Shift плюс Пробел» (`aria-label`).
- **Масштабирование** (1.4.4, 1.4.10): интерфейс корректен при масштабе Windows 100–200% и текстовом масштабе 200%; ширина 720 px — без горизонтальной прокрутки (кроме таблицы журнала, у которой своя прокрутка).
- **Reduced motion**: `prefers-reduced-motion: reduce` → длительности анимаций 0, индикатор таймера окна выбора — статичный текст.
- **Высококонтрастный режим Windows** (`forced-colors: active`): использовать системные цвета (`CanvasText`, `Highlight`, `ButtonText`), фокус-кольцо через `outline` (не `box-shadow`), иконки — `currentColor`. **[ARCH]**: проверить, что WebView2 передаёт `forced-colors`.

## 8. Ограничения локализации

- **Русские строки ~30% длиннее английских** (а отдельные — до 50–60%: «Settings» → «Настройки», «Run» → «Запустить тест»). Правила: не задавать фиксированную ширину кнопок и колонок по тексту; кнопки — `min-width`, а не `width`; подписи в сайдбаре — с переносом не более чем на 2 строки или обрезанием с полным текстом в tooltip; таблицы — колонки с `min-width` и переносом в ячейке «Причина».
- Ширину раскладок проверять **по русской версии** (самой длинной) и псевдолокали (+40%, напр. `[!!Ńàśţŕöĩķà!!]`) — предложение для QA.
- **Нет текста в изображениях и иконках**; иконки без букв (кроме языковых меток `EN`/`RU`, которые являются данными, а не переводимым текстом).
- **Плюрализация**: использовать ICU MessageFormat / `Intl.PluralRules` — в русском 3+ формы («1 проблема, 2 проблемы, 5 проблем», «1 минута / 2 минуты / 5 минут»). Никакой конкатенации строк («Найдено » + n + « ошибок»).
- **Форматы**: время и даты — `Intl.DateTimeFormat` по языку UI (24-часовой формат для RU); числа — `Intl.NumberFormat` (пробел-разделитель тысяч в RU: «100 000»).
- **Названия клавиш** не переводятся (`Ctrl`, `Shift`, `Alt`, `Space`/`Пробел` — **[OWNER]**: предлагается латиница `Space`, как на клавиатуре и в Windows).
- **Имена собственные**: «KeySwitch», «Macro Studio», «JavaScript», «Python» — не переводятся.
- **Коды ошибок** не переводятся (стабильные идентификаторы для поиска), рядом — локализованное описание.
- Ключи строк — по смыслу (`hotkeys.conflict.otherApp`), не по английскому тексту; расширяемость на новые языки UI (украинский и др.) — новый файл ресурсов без изменения кода.
- Шаблоны макросов: комментарии в шаблоне — на языке UI на момент создания; идентификаторы API — английские.

## 9. Неопределённости и вопросы

**Требуют валидации архитектора [ARCH]:**
1. Окно выбора языка: можно ли показать его без активации (`WS_EX_NOACTIVATE`) и принимать 1/2/Esc через временную регистрацию `RegisterHotKey`, или окно должно брать фокус с последующей проверкой FR-FIELD-4? Как поведёт себя Narrator в варианте без фокуса?
2. Источник позиции каретки для размещения окна (Win32 caret / UIA) и fallback для браузеров/Electron-приложений.
3. Контрол захвата: временное снятие регистрации текущего сочетания во время записи; перехват Alt-сочетаний в WebView2 (Alt может активировать системное меню); как отличить «занято другим приложением» от других ошибок `RegisterHotKey`.
4. Пауза: снимаются ли горячие клавиши с регистрации (предложение — да).
5. Проверка макроса: при сохранении или по кнопке; можно ли сохранить слот с ошибкой (предложение — можно, слот помечается невалидным и не выполняется).
6. Список кодов причин для журнала и детали «Состояния компонентов».
7. Поддержка `forced-colors` и `prefers-reduced-motion` в WebView2; системная тема (System) — через `prefers-color-scheme` WebView2 или через событие Tauri.
8. Добавление исключения: ввод имени exe вручную vs нативный диалог выбора файла без плагина `fs`.
9. Нативный vs кастомный заголовок окна.

**Требуют валидации Security [SEC]:**
1. Журнал: допустимо ли хранить «объём» (Выделение/Поле) и способ вставки; подтверждение, что длина текста не логируется.
2. Песочница проверки конвертации и тестовые входные данные макроса — текст пользователя внутри окна: не сохраняется, не логируется, не попадает в crash-репорты; не кэшируется WebView (autocomplete/spellcheck off).
3. Окно выбора языка поверх чужих приложений — риск «кликджекинга»/подмены: может ли другое приложение отправить нажатие `1`, пока окно открыто (вариант с временными горячими клавишами)?
4. «Скопировать отчёт» в Диагностике — копирование метаданных в буфер (с метками D-13?).

**Решения владельца [OWNER]:**
1. Акцентный цвет: синий `#2D6AD6`/`#1F5FCC` (рекомендуется), альтернативы — бирюзовый или фиолетовый (потребуют перепроверки контраста).
2. Сочетания по умолчанию (предложение для обсуждения: конвертация `Ctrl+Shift+Space`? — может конфликтовать с IME/редакторами; альтернатива `Ctrl+Alt+Q`; макрос `Ctrl+Alt+M`).
3. Разрешать ли Win-клавишу в сочетаниях (предложение — нет в v1).
4. Таймаут окна выбора языка (предложение — 10 с) и показывать ли предпросмотр текста в нём (предложение — нет).
5. Звук при отмене (Q-2 PRD) — по умолчанию вкл. или выкл.
6. Автозапуск по умолчанию в онбординге (предложение — вкл.).
7. Отключаемость переключения раскладки после конвертации.
8. Хранить ли черновики кода по каждому типу слота при смене типа (предложение — да).
9. Подпись клавиши пробела: `Space` или `Пробел` в RU-интерфейсе.

**Ограничения этой работы (честно):**
- Прототип — статичный HTML; на реальном WebView2/Windows не проверялся (хост — Linux). Шрифты Segoe UI Variable / Cascadia Mono в прототипе подставляются системными fallback-шрифтами браузера, где они не установлены.
- Контраст рассчитан по формуле WCAG 2.x для заданных hex-значений; проверка на реальных мониторах и в режиме высокой контрастности не проводилась.
- Юзабилити-тестирования с пользователями не было.
