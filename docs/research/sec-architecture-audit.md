## 2. Находки аудита

Формат: **ID · Название · Уровень** / Описание / Сценарий / Компоненты (файл:строка) / Рекомендация / Проверка исправления / Угрозы.

### 2.1 Архитектура: песочница макросов

**AF-01 · «WASI без preopen-каталогов» несовместимо с CPython; способ поставки stdlib не определён · High**
- Описание: `02-architecture.md` §6: «WASI без preopen-каталогов». CPython WASI загружает stdlib с ФС (официальный раннер: `--dir {CHECKOUT}::/`). Архитектура не говорит, как будет решено → высокий риск, что в спайке S-3 появится host-preopen (часто RW), а Wasmtime имел в 2026 несколько обходов `FilePerms`/песочницы ФС (RUSTSEC-2026-0149, -0188, -0352).
- Сценарий: S-3 ради скорости монтирует каталог stdlib из установки; скрипт через обход прав записи меняет файл stdlib → код выполняется при каждом следующем запуске любого макроса.
- Компоненты: `docs/02-architecture.md:68` (§6), будущий `crates/ks-sandbox-host`.
- Рекомендация: зафиксировать в архитектуре: stdlib только из памяти (встроенный zip + неизменяемая виртуальная ФС, реализованная в хосте для набора preview1-вызовов чтения; без rename/link/write/truncate), ни одного host-каталога; урезанная stdlib (D-08) — список модулей в документе.
- Проверка: unit-тест в S-3: `WasiCtx` не содержит preopen host-путей; враждебные скрипты записи/переименования/симлинков в `/Lib` → ошибка, хэш встроенного zip неизменен.
- Угрозы: ST-23.

**AF-02 · Второй слой (AppContainer + Job Object) описан одной строкой; не хватает обязательных мер · High**
- Описание: §6 «AppContainer без capabilities, Job Object: лимит памяти, запрет дочерних процессов, kill on close». Отсутствуют: LPAC (без `ALL APPLICATION PACKAGES`), **UI-ограничения Job** (буфер обмена, дескрипторы окон, атомы, desktop), явный список наследуемых дескрипторов, политики смягчения (win32k lockdown, strict handles, extension points, image load), проверка «я действительно в AppContainer» внутри песочницы, отключение WER для песочницы, сторожевой таймер в основном процессе.
- Сценарий: после выхода из Wasm (ST-22) нативный код открывает буфер обмена напрямую (Job без `UILIMIT_READCLIPBOARD`) или использует унаследованный дескриптор.
- Компоненты: `docs/02-architecture.md:67`; будущий `ks-sandbox-host`.
- Рекомендация: включить профиль запуска из SR-54…SR-56 в архитектуру как требование; если win32k lockdown несовместим с Wasmtime — документировать и компенсировать (Pulley/ACG).
- Проверка: Windows CI — самопроверка песочницы (SR-56) со списком ассертов.
- Угрозы: ST-30.

**AF-03 · Лимиты исполнения: fuel обходится; нет внешнего сторожа · Medium**
- Описание: «fuel/epoch (время)» — fuel обходится через WASI `poll_oneoff` (RUSTSEC-2026-0321). Ничто не гарантирует завершение, если хост Wasmtime сам завис (баг, блокирующий вызов).
- Сценарий: `time.sleep`/`poll_oneoff`-цикл держит процесс дольше лимита.
- Компоненты: `docs/02-architecture.md:68`; `docs/01-prd.md` FR-MACRO-4.
- Рекомендация: epoch interruption + дедлайн в основном процессе с `TerminateJobObject`; `poll_oneoff`/sleep — реализация хоста с ограничением суммарного времени.
- Проверка: враждебные скрипты sleep/loop/recursion → завершение ≤ 2,5 с, процесс песочницы отсутствует после дедлайна.
- Угрозы: ST-28.

**AF-04 · Протокол действий не ограничен: длина, управляющие символы, количество клавиш, противоречие 100 000 vs 5 000 · High**
- Описание: §6 возврат `{insert}|{replace}|{keys}|null`; ограничения на содержимое не заданы. PRD FR-MACRO-4 разрешает «100 000 символов вывода», тогда как лимит поля — 5 000 (D-03); вывод 100 000 символов через SendInput — минутный «клавиатурный флуд». `\r`/`\n`/`\t` в `insert` = Enter/Tab (ST-19, ST-26). Не задан формат кадрирования pipe, лимит сообщения, `deny_unknown_fields`, nonce/идентификатор запроса.
- Сценарий: скрипт возвращает текст с переводами строк в чат → несколько отправленных сообщений; или 100 000 символов → неконтролируемый ввод.
- Компоненты: `docs/02-architecture.md:70–74`, `docs/01-prd.md:85`.
- Рекомендация: схема в архитектуре: сообщение ≤ 64 КиБ; `insert/replace` ≤ 5 000 символов, без C0/C1 (кроме `\n` только для пути paste), без bidi-override и U+0000; `keys` ≤ 16; `deny_unknown_fields`; одно сообщение-результат на запуск; вывод stdout/stderr ≤ 64 КиБ (отдельно от действия). Исправить FR-MACRO-4.
- Проверка: fuzz/proptest приёмника на Linux; unit-тесты границ.
- Угрозы: ST-25, ST-28, ST-19.

**AF-05 · Клавиатурный API: белый список не закрывает «текст + Enter»; исключения не распространены на макросы · High**
- Описание: D-07 корректно запрещает Win/Alt/модификаторы, но Enter/Tab + произвольный текст позволяют выполнять команды в терминалах, уже открытом окне «Выполнить», адресных строках, табличных процессорах и отправлять сообщения. В архитектуре политика действий макроса не связана со списком исключений D-05 и не учитывает удерживаемые модификаторы (ST-11).
- Сценарий: соцнженерный макрос, запущенный в терминале, печатает команду и Enter.
- Компоненты: `docs/00-decisions.md` D-07; `docs/02-architecture.md:46,72–74`.
- Рекомендация: (1) исключения D-05 и отдельный «строгий» список (консоли, Run, адресные строки, табличные процессоры) применяются к макросам до запуска скрипта и повторно перед применением действий; (2) Enter/Tab — отдельное разрешение слота, по умолчанию выключено (**изменение D-07 — решение владельца**); (3) проверка модификаторов перед каждым пакетом; (4) сброс разрешений при изменении скрипта.
- Проверка: unit-тесты политики (окно × действие); Windows CI — тестовое окно класса консоли.
- Угрозы: ST-26, ST-11, ST-31.

**AF-06 · Разрешение чтения буфера: нет сброса, нет учёта меток менеджеров паролей · High**
- Описание: D-07: «чтение только по явному разрешению в настройках слота». Не определено: сброс при изменении скрипта, поведение для буфера с метками исключения (пароли), форматы (только текст?), лимит, отображение во время выполнения.
- Сценарий: пользователь однажды включил разрешение; позже вставил чужой скрипт в тот же слот — разрешение сохранилось; скрипт печатает пароль из буфера в текущее поле.
- Компоненты: `docs/00-decisions.md` D-07; `docs/02-architecture.md:74`.
- Рекомендация: SR-30, SR-51.
- Проверка: unit (Linux) + Windows CI (метки).
- Угрозы: ST-27, ST-04.

**AF-07 · Происхождение `quickjs.wasm`/`python.wasm` не определено; «проверка по хешу» в user-writable каталоге · High**
- Описание: «встраиваются в установщик и проверяются по хешу» — без источника/процесса сборки хэш фиксирует то, что пришло. Установка `currentUser` → каталог доступен на запись (хэш-проверка защищает только от повреждения).
- Сценарий: сборочный скрипт качает готовый `python.wasm` со стороннего релиза.
- Компоненты: `docs/02-architecture.md:68`, `app/src-tauri/tauri.conf.json:34`.
- Рекомендация: сборка из закреплённых исходников в CI (SR-66), `include_bytes!` в бинарь песочницы (SR-57), подпись бинарей перед релизом.
- Проверка: CI пересборки; сравнение хэшей.
- Угрозы: ST-49, ST-32.

**AF-08 · Политика обновлений Wasmtime противоречит правилу «зависимость не моложе 2 недель» · Medium**
- Описание: CLAUDE.md правило 3 требует версию «не моложе 2 недель». При темпе advisory Wasmtime в 2026 (44 шт.) это гарантирует окно уязвимости ≥ 2 недель для каждого security-фикса. Нет updater — пользователи не узнают об обновлении.
- Сценарий: опубликован фикс выхода из песочницы; проект ждёт 14 дней по правилу, затем пользователи месяцами на старой версии.
- Компоненты: `CLAUDE.md` (правило 3), процесс релиза.
- Рекомендация: исключение для security-патчей (с записью в PR); SLA security-релиза ≤ 7 дней; минимизация фич Wasmtime (`default-features = false`, только `cranelift`/`pulley`, без component-model/GC/threads/wasi-http/pooling); дата сборки + предупреждение о возрасте в UI.
- Проверка: ревью `Cargo.toml` фич; процесс.
- Угрозы: ST-22, ST-39.

### 2.2 Архитектура: Windows-интеграция и буфер

**AF-09 · «Дождаться потребления» буфера не определено → вставка прежнего буфера · High**
- Описание: FR-CLIP-2/§5 конвейер не определяет сигнал окончания вставки. Восстановление по таймеру/профилю (R-2 «профильная задержка») приводит к ST-01.
- Сценарий: под нагрузкой Electron читает буфер после восстановления → в чат вставлен пароль.
- Компоненты: `docs/02-architecture.md:47, 59–61, 93`; `docs/01-prd.md:72`.
- Рекомендация: SendInput — основной путь для всех длин ≤ 5 000 там, где профиль подтверждён; путь буфера — отложенная отрисовка как сигнал + пост-проверка UIA; при отсутствии сигнала — **не восстанавливать** (временный текст остаётся, пользователь уведомлён), а не «восстановить вслепую».
- Проверка: SR-11 тест с задержками чтения.
- Угрозы: ST-01.

**AF-10 · Snapshot/restore: нет белого списка форматов, нет переноса меток приватности, неатомарная проверка seq · High**
- Описание: трейт `Clipboard { snapshot; put_private; restore_if_unchanged }` не определяет: какие форматы сохраняемы; что делать с GDI/OLE/отложенной отрисовкой (FR-CLIP-3 частично); перенос меток исходных данных; проверку sequence number под открытым буфером; таймауты.
- Сценарий: ST-02, ST-04, ST-05.
- Компоненты: `docs/02-architecture.md:47`.
- Рекомендация: SR-10, SR-13, SR-14 — внести в архитектуру как контракт трейта.
- Проверка: Windows CI фикстуры буфера.
- Угрозы: ST-02, ST-04, ST-05, ST-06.

**AF-11 · Повторная проверка фокуса только перед Write; диалог активирует окно · High**
- Описание: §5 `[Re-verify focus]` один раз; SendInput — длительная операция; диалог смешанного текста забирает фокус (ST-08).
- Сценарий: ST-07 — вторая половина текста уходит в всплывшее окно другого чата.
- Компоненты: `docs/02-architecture.md:59–61`; FR-FIELD-4.
- Рекомендация: SR-20, SR-21, SR-22: проверка перед каждым пакетом, пост-проверка, неактивирующий диалог, сравнение хэша текста до/после диалога.
- Проверка: Windows CI тест смены foreground.
- Угрозы: ST-07, ST-08.

**AF-12 · Распознавание полей паролей — только `IsPassword` · High**
- Описание: D-05/FR-FIELD-3 опираются на `UIA IsPassword`; кастомные маскирующие поля, OTP/PIN, RDP/VM окна не распознаются.
- Сценарий: ST-09.
- Компоненты: `docs/00-decisions.md` D-05; `docs/02-architecture.md:41`.
- Рекомендация: SR-23 (многосигнальная политика, исключения RDP/VM клиентов, отказ до чтения).
- Проверка: Windows CI тестовые страницы WebView2.
- Угрозы: ST-09.

**AF-13 · Ctrl+A/«всё поле»: доверие ControlType, нет профиля Excel, переводы строк через SendInput · High**
- Описание: D-04 разрешает Ctrl+A после проверки UIA `Edit`; `role=textbox` у `contenteditable` выглядит как Edit. Excel-ячейка вне режима редактирования, вставка с `\t`/`\n` в таблицу, формульные префиксы. FR-CLIP-1 (SendInput для коротких текстов) не учитывает `\n` = Enter в чатах.
- Сценарий: ST-16, ST-19, ST-20.
- Компоненты: `docs/00-decisions.md` D-03/D-04; `docs/02-architecture.md:55, 59–61`; `docs/01-prd.md:71`.
- Рекомендация: SR-31, SR-32, SR-35, SR-36; профили по умолчанию — «только выделение» для браузеров и rich-редакторов, пока ручная приёмка (D-10) не подтвердит иное.
- Проверка: Windows CI (WebView2-фикстуры) + ручная матрица.
- Угрозы: ST-16, ST-19, ST-20.

**AF-14 · Горячие клавиши: AltGr-конфликты, Win-модификатор, синтетический запуск · Medium**
- Описание: примеры сочетаний в ТЗ (`Ctrl+Alt+Q`) совпадают с AltGr-символами в ряде раскладок (немецкая: `@`); D-14 не запрещает Win; синтетический хоткей неотличим.

- Компоненты: `docs/00-decisions.md` D-14; `docs/01-prd.md` FR-HK.
- Рекомендация: SR-26, SR-27.
- Проверка: unit-валидатор + Windows CI `VkKeyScanEx`.
- Угрозы: ST-12.

**AF-15 · UIA-клиент: нет тайм-аутов и ограничения объёма чтения · Medium**

**AF-16 · Запуск с повышенными правами и молчаливый UIPI · Medium**

**AF-18 · Crash-дампы и WER не рассматриваются; `panic = "abort"` · High**
- Описание: NFR-4 требует «текст не попадает в crash-репорты», но в архитектуре нет механизма. Release-профиль `panic = "abort"` (`Cargo.toml:24`) → аварийное завершение → WER.
