### 1.2 Предложение: минимальная версия — **macOS 15 Sequoia**
Обоснование:
1. **Безопасность:** поддерживаем только версии, получающие обновления безопасности Apple (15, 26, 27); на 14 их, вероятно, уже нет.
2. **Проверяемость:** для 15 и 26 есть бесплатные CI-раннеры обеих архитектур; для 14 — больше нет (CI проекта не смог бы её проверять, правило 7 — не выдумывать результаты).
3. **API:** все нужные API (`SMAppService` — 13+, AX, TIS, `CGPreflightPostEventAccess` — 10.15+) доступны; ограничения хоткеев macOS 15 (Option-only, `MACOS_PLATFORM_MAP.md` §1.5) учитываются в любом случае.
4. **Пользователи:** Mac, способные запустить 14, почти все могут запустить 15 [гип.: по спискам совместимости] — потеря аудитории мала.
`bundle.macOS.minimumSystemVersion = "15.0"` в `tauri.conf.json` (изменение — с ревью CISO по §6 SECURITY_REVIEW). Политика: поддерживаем текущую и две предыдущие версии; при выходе macOS 28 минимум пересматривается.
Альтернативы: (а) минимум macOS 14 — +небольшая аудитория, но без CI и, вероятно, без патчей Apple → не рекомендую; (б) минимум macOS 26 — проще матрица, но отсекает пользователей 15, которые ещё получают патчи.

## 2. Архитектуры: Apple Silicon / Intel

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Universal binary (arm64 + x86_64), рекомендую** | один артефакт и одна запись updater на обе платформы [сообщ.]; Intel-пользователи macOS 15/26 получают патчи | ~2× размер бинарей; Wasm-модули песочницы (QuickJS/CPython) архитектурно-независимы → прирост в основном за счёт нативного кода [гип.]; нужно тестировать обе архитектуры |
| B. Две отдельные сборки | меньше размер загрузки | две записи updater, две нотаризации, больше путаницы |
| C. Только Apple Silicon | минимум тестов; macOS 27+ всё равно только Apple Silicon | Intel Mac на 15/26 ещё получают обновления безопасности Apple [гип.: до ~2028] — исключаем часть аудитории; Rosetta не выход (после 27 Apple сокращает Rosetta 2 [сообщ.]) |

**Рекомендация:** A в v1; Intel — «поддержка по CI + ручная приёмка при наличии Intel Mac», с прекращением поддержки Intel синхронно с концом обновлений безопасности macOS 26 (решение владельца L3-4, `MACOS_PLATFORM_MAP.md` §5.2). Если у команды нет доступа к Intel Mac для ручной приёмки — Intel помечается «экспериментально».

## 3. Приложения

Обозначения способов записи: **M1** — AX-запись выделения, **M3** — синтез Unicode через CGEvent (≤ порога, без `\n`/`\t`), **M2** — вставка через буфер (только по профилю), см. `MACOS_PLATFORM_MAP.md` §1.3. Во всех строках обязательны проверки S1–S6 (S5 на macOS = «временный текст не попал в историю менеджера буфера, уважающего nspasteboard.org, и не ушёл в Universal Clipboard»).

| Приложение | Технология / AX (гипотеза) | Уровень (предложение) | Ожидаемое поведение | Особые риски | Статус |
|---|---|---|---|---|---|
| **TextEdit** | AppKit `NSTextView` — эталон AX [док] | L-REQ | выделение; фрагмент до каретки в документе; M1 при подтверждённом Undo, иначе M3 | rich-текст с вложениями → `EmbeddedObjects`; Undo после AX-записи [гип.] | UNVERIFIED |
| **Notes (Заметки)** | AppKit/TextKit, собственный редактор [гип.] | L-REQ | выделение; фрагмент до каретки; M3 по умолчанию до подтверждения M1 | чек-листы/таблицы/вложения → отказ; синхронизация iCloud не влияет на нас | UNVERIFIED |
| **Safari** | WebKit — нативный AX без включения [сообщ.] | L-REQ | до приёмки — только выделение/фрагмент (V7 §5, D-19(a)); `<input>` «всё поле» — после M-2 | `contenteditable` (Gmail, Google Docs — свой canvas/скрытые поля → отказ); поля паролей `AXSecureTextField` | UNVERIFIED |

2. Ручная приёмка на реальном Mac (владелец/QA): каждая строка §3 на macOS 15 и 26/27 (arm64), Intel — при наличии; протокол Pass/Fail/N/A по S1–S6, F1–F7.
3. Строка получает «поддерживается» только после Pass; результаты — в эту матрицу с датой, версией приложения и ОС.
