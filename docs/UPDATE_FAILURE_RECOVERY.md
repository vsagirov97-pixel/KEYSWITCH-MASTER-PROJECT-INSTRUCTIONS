# UPDATE_FAILURE_RECOVERY — сбои обновлений и восстановление

Статус: **проект (AGENT 03)** · Редакция 1 · 2026-11-10 · утверждают CISO, QA, AGENT 09; GATE 10.
Основа: `UPDATE_SECURITY_ARCHITECTURE.md` (далее [USA]), `UPDATE_RELEASE_CHECKLIST.md` (далее [URC]).
Главный принцип: **никогда не возвращать пользователя на известную уязвимую версию; сохранность настроек и макросов важнее скорости.** Пользовательский текст в диагностику не попадает ни при каком сбое (правило 1).

## 1. Режимы отказа на клиенте

|---|---|---|---|---|---|

## 2. Действия выпускающей стороны

1. **Остановить выпуск:** `rollout.halted = true` → новый `seq` манифеста → `timestamp` (вручную, не ждать ежедневного). Клиенты, не установившие X, удаляют артефакт при следующей проверке (≤ 6 ч + джиттер).
2. **Отозвать версию:** `revoked_versions += X` (только если X опасна или массово ломает работу).
3. **Roll-forward:** X+1 = X без регрессии (или X−1 с новым номером, если регрессия глубокая). Новый номер обязателен: откат кода ≠ откат версии.
4. **Временная emergency-политика:** отключить сломанную/уязвимую функцию ([USA] §12) до выхода X+1, срок ≤ 30 дн.
5. **Если X закрывает уязвимость, а X ломает работу:** X **не** отзывается, если X−1 уязвима; вместо этого — emergency-политика + срочный X+1 (вернуть уязвимую версию хуже, чем временно отключить функцию).
6. Коммуникация: заметка в релизе + advisory; владелец — немедленно, если затронуты данные или безопасность.

## 3. Безопасный режим клиента
- Включается: F-9, F-10 (провал самопроверки), F-11.
- Ограничения: Macro Studio не запускается; W2 (буфер) выключен; конвертация — только выделение/фрагмент через W1/W3; emergency-политики продолжают действовать.
- Проверка обновлений — каждые 30 мин (EMERGENCY/исправление ставится как только доступно).
- Выход: успешная самопроверка на следующей версии или ручное действие пользователя «Выйти из безопасного режима» (нативный диалог).
- Диагностика — только коды и версии.

## 4. Сохранность данных пользователя
- Перед установкой: `VACUUM INTO` копии `keyswitch.db` в `%LOCALAPPDATA%\KeySwitch\backup\pre-<from>-to-<to>.db` (macOS — аналогичный путь), хранится до 2 последних копий; `secure_delete` сохраняется.
- Черновик Macro Studio сохраняется перед `Draining`.
- Миграции — только вперёд, в транзакции; новая версия читает старую схему или выполняет миграцию после бэкапа; схема не понижается.
- Восстановление настроек из бэкапа — ручное действие пользователя в Диагностике.

## 5. Возврат на предыдущую версию (крайний случай)
Разрешён **только** если одновременно:
1. подписанный манифест помечает текущую версию X как отозванную **и** содержит `rollback_target = Y` для X (поле в записи релиза, подпись `release`);
2. `Y ≥ min_safe_floor` и `Y ∉ revoked_versions`;
3. артефакт Y доступен и проходит полную проверку [USA] §8 (кэш предыдущего установщика или загрузка);
4. после возврата `highest_installed_version` **не понижается** — клиент ждёт X+1 > X.
Иначе — только roll-forward и безопасный режим. Самостоятельного «отката по кнопке» нет.

## 6. Проверка (QA, GATE 10)
- F-1…F-11 воспроизводятся в CI на тестовом канале с тестовыми ключами (подмена, обрыв, истечение, kill установщика, падающая сборка с флагом `test-hooks`, поломанная миграция).
- Ожидание: ни в одном сценарии не установлена версия < `min_safe_floor`; данные пользователя целы (сравнение БД с эталоном); в журналах нет пользовательского текста.
