## 0. Методика и честная оценка силы доказательств

- Метки: **[V]** — прочитан первичный источник; **[R]** — сводка поисковой выдачи / вторичный источник; **[A]** — вывод аналитика.
- **Ограничение.** Из облачной сессии не открываются `habr.com`, `alternativeto.net`, `reddit.com`, `apps.apple.com`, `yandex.ru`, `github.com` (issues). Прямых пользовательских отзывов прочитано мало; часть доказательств — **косвенные**: что конкуренты исправляют в changelog и что выносят в заголовок README (это показывает, на какие жалобы они отвечают). Такие свидетельства помечены «косвенно».
- **Частота (Ч)**: 3 — встречается у многих продуктов/в нескольких независимых источниках; 2 — в 2–3 источниках; 1 — единичные. **Тяжесть (Т)**: 3 — потеря/утечка данных, порча текста, отказ от продукта; 2 — регулярное раздражение, обходные пути; 1 — неудобство. **Ранг = Ч × Т**. Оценки — экспертные [A], не статистика.
- Даты обращения ко всем источникам — 2026-11-10.

## 2. Детали и доказательства

### N-01. Страх кейлоггера и телеметрии (ранг 9)
- Punto Switcher содержит функцию «Дневник», записывающую весь набор в файл [R: https://www.anti-malware.ru/threats/keyloggers]; anti-malware.ru пишет, что злоумышленники используют его как «легальный» кейлоггер, потому что антивирусы его не детектируют [R].
- Habr-статья 2026 г. «Меняем Punto Switcher на macOS: открытый код, ноль телеметрии и ноль зависимостей» строит сравнение именно на «телеметрия есть (по сообщениям)», «кейлоггер-дневник есть» [R: https://habr.com/ru/articles/1050394/].
- История 2010 г.: тема «Яндекс шпионит через Punto Switcher 3.1.1» и последующие опровержения [R: https://yandex.ru/blog/punto/6286, https://yushchuk.livejournal.com/254576.html].
- **Косвенно [V]:** все новые open-source конкуренты выносят приватность в первые строки README: Kright — «Private by design — no network, nothing stored», «passively watches the keys you type — never recording them»; RuSwitcher — «No telemetry — your keystrokes stay on your Mac»; LangSwitcher — «Privacy first — no data leaves your Mac»; Espanso — «Privacy-first (100% local, no tracking)». Это ответ рынка на эту боль.
- **Нюанс [A]:** даже «приватные» OSS-конкуренты *технически слушают все нажатия* (`WH_KEYBOARD_LL`/`CGEventTap`) и имеют сетевые функции (автообновление, загрузка словаря). Их обещание — «не записываем», наше может быть сильнее — «не слушаем и не можем выйти в сеть».
- **Тяжесть 3:** при утечке — пароли и переписка; плюс корпоративные запреты.

### N-02. Ложные автосрабатывания (ранг 9)
- Пользователь Habr: на коротких словах и сокращениях у Punto регулярно были ложные срабатывания; перешёл на ручное исправление [R: https://habr.com/en/articles/979382/comments]. Другие советуют выключить автоматику и исправлять по Break, оставив запоминание раскладки для приложений [R: https://habr.com/en/articles/54777/comments, https://qna.habr.com/user/Maklaut/answers].
- **Косвенно [V]:** RuSwitcher делает автоконверсию «precision-first», явно пропуская слова < 3 букв, URL, CamelCase, аббревиатуры, терминалы/IDE/менеджеры паролей и добавляя «learn-from-undo» → значит, именно это ломалось у пользователей. Caramba для Mac предлагает «паузу для отдельных приложений (код, игры)» [R]; MySwitcher — «ручной режим» для терминалов, IDE, игр [R].
- **Вывод [A]:** решение KeySwitch «только по нажатию + отказ при сомнении» — это прямой ответ на главную боль автопереключателей. Это надо продавать как достоинство, а не оправдываться за отсутствие автоматики.

### N-03. «Не работает в приложении X» (ранг 9)
- **[V] Kright:** WhatsApp для Windows «renders its whole UI inside a WebView2 control that exposes nothing to UI Automation», подтверждено тестами на устройстве (CHANGELOG 1.1.0, 2026-07-18). → Для KeySwitch это значит: в WhatsApp Desktop чтение поля через UIA, скорее всего, невозможно; остаётся только путь «выделение + Ctrl+C по профилю» (Q-7) или честный отказ. **Передать Product Analyst и Architect (матрица приложений, S-2).**
- **[V] RuSwitcher 3.5.0** исправлял «потерю слова в браузерах и веб-чатах», «Enter в Outlook», «буфер обмена при конвертации выделенного»; VS Code не отдаёт позицию курсора через Accessibility.
- **[V] Kright:** терминалы (cmd, PowerShell, Windows Terminal) отклоняют запись через Accessibility → fallback на эмуляцию клавиш и буфер.
- **[R]** Kirgudu (Mac, 2009): «автопереключение работает не со всеми приложениями… Opera и Firefox» [https://lifehacker.ru/kirgudu/]. Punto перестаёт работать после обновления Parallels Tools в Windows 11 [https://forum.parallels.com/threads/parallels-tools.358783/].
- **Вывод [A]:** рынок обещает «работает везде», а реальность — нет. Открытая, датированная матрица совместимости с результатами тестов (MI-07) — отличие, которого нет ни у кого.

### N-04. Буфер обмена (ранг 6)
- «Punto периодически терял буфер обмена, и это стало последней каплей» [R: https://habr.com/ru/articles/1050394/]. В Punto 4.5.0 — «исправлена замена буфера обмена» [R: yandex.ru/soft/punto/win/release].
- **[V]** Kright: в терминалах сохраняет/восстанавливает буфер, «не может гарантировать восстановление», нетекстовые данные (файл, картинка) не восстанавливаются. Keyboard Switch работает только через copy→convert→paste. SimpleSwitcher: «всегда очищает или восстанавливает буфер обмена после использования, очищает память по таймеру» — вынесено как фича безопасности.
- **Вывод [A]:** «Мы не трогаем буфер, а если трогаем — помечаем и не светим в истории Win+V» (D-13) — понятное пользователю преимущество; полезно показывать в Diagnostics, каким путём выполнена замена (без текста).

### N-05. Пароли и защищённые поля (ранг 6)
- **[V]** Kright добавил «auto keyboard language» — переключение на латиницу в полях e-mail/URL/пароль; «password / secure fields are never read».
- **[R]** Отзыв о MLSwitcher (Mac App Store): ошибка с символами над цифрами в полях паролей при Shift как клавише смены раскладки.
- **[A]** Ввод пароля не в той раскладке — частая бытовая боль, но KeySwitch в полях паролей по определению отказывается (D-05). Идея-компенсация без чтения поля: MI-10 (подсказка о раскладке при фокусе в поле пароля — только если реализуемо без хуков; требует оценки Security).

### N-06. Эргономика триггера (ранг 6) — **разрыв с рынком**
- **[V]** RuSwitcher: одиночный/двойной модификатор (Option, Shift…), пара модификаторов; Caramba: Shift×2 [R]; LangSwitcher и Boomkey: Shift×2 [V]/[R]; Keyboard Switch: Ctrl+Shift×2 [V]; SimpleSwitcher: CapsLock, F24, double/up-триггеры [V]. Это стандарт ожиданий.
- **[R]** Windows 11: Alt+Shift «не всегда срабатывает или срабатывает медленно», Right Alt+Shift работает в одну сторону; рекомендуют Win+Space [https://techcommunity.microsoft.com/discussions/windows11/windows-11-language-switch-hot-keys-dont-always-work-or-work-slowly-/4105408, https://learn.microsoft.com/en-us/answers/questions/5648231/].
- **Конфликт с решениями:** D-14 (`RegisterHotKey`, обязательна не-модификаторная клавиша) делает Shift×2 и «одиночный модификатор» невозможными без хука. Это осознанная цена принципа.
- **Что можно сделать без хука [A]:** (а) предложить по умолчанию удобные сочетания, проверенные на конфликты (Pause/Break, Ctrl+Shift+Space, F-клавиши); (б) поддержать клавиши, которые редко используются (Pause, ScrollLock, F13–F24) и объяснить, как переназначить CapsLock→F13 штатными средствами (PowerToys Keyboard Manager) — MI-11; (в) честно объяснить в онбординге, почему нет Shift×2 (это и есть «мы не слушаем клавиатуру»).

### N-07. Заброшенные продукты (ранг 6)
- [R] Orfo Switcher 3.050 — 2011-09-09 [https://cyclowiki.org/wiki/Orfo_Switcher]; Keyboard Ninja 2.1 — запуск в режиме совместимости с Windows 98 [https://www.npackd.org/p/com.keyboardninja.KeyboardNinja/2.1]; Switch It (switchit.ru) — «работа, видимо, прекратилась» [https://habr.com/en/articles/110359]; dotSwitcher — discontinued [AlternativeTo]; Punto — «фоновая поддержка» [https://qna.habr.com/user/Dwellss/comments?page=6]; Punto для Mac — пользователи на Sequoia ищут альтернативу [https://qna.habr.com/q/1303436]; Beeftext в режиме поддержки с 2023 г. [R].
- **Вывод [A]:** ценность — предсказуемость: публичная дорожная карта, история релизов, политика поддержки версий Windows.

### N-08. Раскладка по контексту (ранг 4)
- [V] Kright: правила по приложению и по контакту (Teams/WhatsApp на Mac); RuSwitcher: память раскладки по приложению. [R] Input Source Pro (Mac): по приложению и по сайту.
- Для KeySwitch: переключение раскладки *после конвертации* уже в v1 (ТЗ §5); «раскладка по приложению» без хуков реализуема через событие смены переднего окна (`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` — это не клавиатурный хук), но требует оценки Security/Architect (MI-09).

### N-09. Сложность настроек (ранг 4)
- [R] «Вместо 96 настроек Punto у Caramba одна» — подано как достоинство [https://lifehacker.ru/caramba-switcher/]. Комментатор: «ошибочных переключений не так уж много» (то есть часть пользователей устраивает минимум).
- Для дизайна: разумные значения по умолчанию + раздел «Дополнительно» (см. UI-отчёт).

### N-10. Игры, античит, RDP, конфликты хоткеев (ранг 4)
- [V] SimpleSwitcher: локальный хук перехватывает клавиши, уходящие в RDP-сессию; нужны исключения `mstsc.exe` и др.
- [R] Raycast для Windows добавил Game Mode (отключение хоткеев во время игры) [https://www.raycast.com/changelog/windows]; Caramba Mac — пауза для игр [R].
- [R] Прямых доказательств банов античитом за переключатели раскладки **не найдено**; есть общие жалобы на Vanguard, блокирующий устройства ввода/драйверы [https://www.ginx.tv/en/valorant-s-anti-cheat-is-now-disabling-input-devices-users-report]. → **Слабое доказательство**, не преувеличивать.
- [R] PowerToys 0.94 ввёл обнаружение конфликтов хоткеев — признак, что конфликт хоткеев — массовая проблема Windows-утилит.
- Для KeySwitch [A]: `RegisterHotKey` не видит чужой ввод → в играх/RDP KeySwitch пассивен, если не нажат его хоткей. Полезно: автоматическая пауза в полноэкранных приложениях (MI-13).

### N-11. Антивирусы и корпоративная ИБ (ранг 4)
- [V] AutoHotkey держит в README раздел «False positives» и страницу о том, как их решать.
- [R] Эвристика антивируса помечала `pshook.dll` Punto как «подозрение на Keylogger» (единичный отчёт).
- [R] Конкретных случаев официального корпоративного запрета Punto **не найдено**.
- [A] Отсутствие хуков/инъекций/повышения прав снижает риск ложных срабатываний, но неподписанные сборки (D-11) — сильный фактор SmartScreen/AV. Kright подписал Windows-сборки в 1.1.1 и прямо указывает, что «SmartScreen no longer warns» [V].

### N-12. macOS (ранг 4)
- [R] Punto для Mac заморожен с 2017 г. (по Habr) [https://habr.com/ru/articles/1050394/]; пользователи Sequoia спрашивают, как его запустить, им советуют Caramba [https://qna.habr.com/q/1303436]. На Mac много новых OSS-альтернатив (RuSwitcher, LangSwitcher, Kright) — рынок на Mac конкурентнее, чем на Windows [A].
- На macOS механизм без «Input Monitoring» — только по выделению/Accessibility; для будущей версии это будет то же преимущество, что и на Windows [A, оценка Architect].

### N-13. Отмена (ранг 4)
- [V] RuSwitcher: «Tap again to undo» и «learn-from-undo» (добавление слова в исключения после отмены). Kright — нет явной отмены [A].
- KeySwitch: Ctrl+Z (D-12), повторное нажатие — вне v1 (NG-12). Рынок ожидает «нажал ещё раз — вернулось» [A]; стоит вернуть вопрос владельцу после S-2 (MI-08).

### N-14. Другие языки (ранг 4)
- [V] Kright и RuSwitcher конвертируют любую пару установленных раскладок; RuSwitcher добавил иврит (RTL). [R] MySwitcher — отдельный словарь украинского и контекст для слов, совпадающих в UK/RU.
- [A] Украинский рынок особенно чувствителен к «продуктам Яндекса»; это окно для KeySwitch после v1 (D-15 — «новый язык = файл»).

### N-15. Случайная отправка сообщения (ранг 3)
- [V] RuSwitcher 3.5.0 исправлял «Enter в Outlook». [A] Для KeySwitch уже закрыто FR-WRITE-4.

## 3. Выводы для команды

1. **Три первые боли (N-01…N-03) совпадают с принципами KeySwitch** — это редкая удача: принципы, которые выглядят ограничениями, отвечают на главные жалобы рынка. Их надо сделать видимыми в продукте (Diagnostics, онбординг, отчёт о приватности) — см. MI-01…MI-07.
2. **Главный разрыв — N-06 (триггер).** Рынок привык к Shift×2/CapsLock; `RegisterHotKey` этого не даёт. Решение — не нарушать D-14, а дать хорошие сочетания по умолчанию, поддержку F13–F24/Pause и объяснение.
3. **Новая техническая находка для S-2:** WhatsApp Desktop (WebView2/WinUI3) не отдаёт ничего через UIA (по тестам Kright) — внести в `pa-app-matrix.md` как ожидаемый «отказ/только выделение» (решает Product Analyst).
4. **Слабые места доказательной базы:** нет прямых отзывов из App Store / Microsoft Store / Reddit / 4PDA; нет данных о частоте. Рекомендация: после разрешения доменов повторить сбор; до релиза — 5–10 интервью с пользователями Punto/Caramba (задача Product Analyst, с согласия владельца).
