## 2. Навигация и информационная архитектура

**Что делают.**
- PowerToys: левая навигация по модулям + домашний дашборд с плитками состояния; с 0.94 — плитка «Shortcut Conflicts» со счётчиком и переходом к полному списку [R: https://devblogs.microsoft.com/commandline/powertoys-0-94-is-here-settings-search-shortcut-conflict-detection-and-more/].
- VS Code: настройки как список с группировкой, поиском и фильтрами (`@modified` и др.) [R: https://code.visualstudio.com/docs/configure/settings].
- Linear: «keyboard-first» — командная палитра Ctrl/Cmd+K + мнемонические одиночные клавиши; принцип «ускорять экспертов, не мешая новичкам», «не перехватывать клавиши, когда фокус в текстовом поле» [R, сторонние разборы: https://blakecrosley.com/guides/design/linear, https://www.techinterview.org/post/3233475370/frontend-system-design-build-linear-project-management/].

**Рекомендации.**
- **Принять:** левая навигация из 6 разделов (уже в `design-concept.md` §2) + Ctrl+1…6. Обзор — дашборд из плиток состояния (как PowerToys): «Конвертация: активна, Ctrl+…», «Макрос: JS, разрешения», «Конфликты хоткеев: 0», «Последний отказ: причина» (без текста).
- **Адаптировать:** командная палитра в полном виде избыточна для 6 разделов и ~30 настроек [A]. Достаточно, чтобы Ctrl+K/Ctrl+F открывали поиск по настройкам и действиям («Приостановить», «Открыть журнал»).
- **Избегать:** одиночные клавиши-мнемоники в главном окне без модификаторов — в Macro Studio это конфликтует с редактором кода (правило Linear «не красть клавиши у полей ввода» [R]).

## 3. Поиск по настройкам (UI-01, UI-02)

**Что делают.** PowerToys 0.94 добавил поиск по настройкам (Ctrl+F, нечёткий) [R]. VS Code: строка поиска сверху, фильтр «Modified», цветная полоса слева у изменённых настроек [R: https://code.visualstudio.com/docs/customization/userandworkspace].

**Рекомендации.**
- **Принять:** поле поиска в шапке главного окна (Ctrl+F), результаты — с хлебными крошками «Настройки › Поведение › …», Enter — переход и подсветка поля на 2 с (с учётом `prefers-reduced-motion`).
- **Принять:** искать по синонимам на обоих языках UI (RU/EN): «автозапуск / startup / autostart», «буфер / clipboard». Поиск — полностью локальный, по статическому индексу строк интерфейса [A].
- **Принять:** у каждой изменённой настройки — маркер (не только цвет: точка + текст для экранного диктора «изменено») и действие «Сбросить». В Settings — фильтр «Только изменённые».
- **Принять:** «Сбросить все настройки» — только с подтверждением и **без** удаления макроса (удаление пользовательских данных требует отдельного явного действия — ТЗ §18) [A].

## 4. Горячие клавиши (UI-03, UI-04)

**Что делают.**
- PowerToys: конфликтующие сочетания подсвечиваются красным, учитываются конфликты с другими модулями и с Windows; плитка с числом конфликтов [R].
- Raycast для Windows: автоочистка «устаревших» хоткеев при переназначении/удалении приложений, Game Mode, исправление приоритета хоткеев (v0.40–v2.9, 2025–2026) [R: https://www.raycast.com/changelog/windows].
- 1Password: глобальный хоткей Quick Access по умолчанию **Ctrl+Shift+Space** на Windows; меняется в настройках через поле с кнопкой «✕» [R: https://support.1password.com/keyboard-shortcuts/, https://1password.com/blog/navigate-1password-quick-access]; на форуме жалобы на некоторые неизменяемые сочетания и конфликты [R].
- Microsoft: не использовать глобальные системные сочетания Windows; не мешать StickyKeys/FilterKeys — пользователь StickyKeys нажимает клавиши последовательно [R: https://learn.microsoft.com/en-us/windows/uwp/accessibility/keyboard-accessibility, https://msdn.microsoft.com/en-us/library/ms971323.aspx].
- Конкуренты-переключатели предлагают Shift×2, CapsLock, Pause/Break [V/R, см. `2026-11-10-user-needs.md` N-06].

**Рекомендации.**
- **Принять (уже в 4.4):** запись с чипами, Esc — отмена, Tab — выход из записи, прежнее сочетание сохраняется до успешной регистрации.
- **Дополнить:**
  1. **Ctrl+Shift+Space занят 1Password по умолчанию** [R] — не предлагать его как умолчание для KeySwitch или показывать предупреждение «часто используется 1Password» (это не детект чужих программ, а статический список известных сочетаний) [A]. Нужна общая таблица «известные занятые сочетания» (1Password, PowerToys Run Alt+Space, Windows Win+…, Microsoft Teams и т. п.) — собрать в S-2.
  2. **Плитка «Конфликты» на Обзоре** со счётчиком и переходом в Hotkeys (как в PowerToys) — включать конфликты, обнаруженные при каждом старте (`RegisterHotKey` вернул ошибку).
  3. **Подсказки удобных сочетаний** в контроле записи: «Pause», «Ctrl+Shift+Space», «F13–F24 (если клавиатура поддерживает)». Отдельная ссылка «Как превратить CapsLock в F13» (штатными средствами, например PowerToys Keyboard Manager) — с честным примечанием, почему KeySwitch не может слушать Shift×2 (D-14) [A].
  4. **StickyKeys:** если включены залипающие клавиши, режим записи должен корректно собирать последовательно нажатые модификаторы (требование Microsoft) [R] — проверить в S-2.
  5. Показ сочетаний в UI — в нотации текущей раскладки и языка (Ctrl/Strg не нужен, но для RU-интерфейса «Ctrl» остаётся латиницей) [A].
- **Избегать:** неизменяемые («зашитые») глобальные сочетания — повод для жалоб у 1Password [R].

## 5. Онбординг (UI-05, UI-14, UI-15)

**Что делают.**
- Caramba Switcher продаёт простоту: «одна настройка» [R: https://lifehacker.ru/caramba-switcher/].
- Kright: «Planned — Onboarding + trust-focused Key Log on Windows (parity with macOS)» — онбординг, построенный вокруг доверия [V: https://raw.githubusercontent.com/walteryaron/kright/HEAD/CHANGELOG.md].
- Mac-утилиты (RuSwitcher, LangSwitcher, Keyboard Switch) начинают с запроса разрешений Accessibility/Input Monitoring [V].

**Рекомендации.**
- **Принять (дополнение к 4.10):** на шаге 2 после выбора хоткея — **встроенное тестовое поле** («Наберите здесь `ghbdtn` и нажмите ваше сочетание»). Это проверяет регистрацию хоткея и показывает результат *в окне KeySwitch*, без риска для чужих приложений. **[ARCH]:** конвертация в собственном окне запрещена политикой («фокус в окне самого KeySwitch» — отказ, `synthesis.md` §1.5) → нужен отдельный безопасный режим «демо» внутри UI, не идущий через платформенный путь, либо отказ от идеи (MI-14).
- **Принять:** шаг «Что KeySwitch не делает» вместо стены разрешений: «не слушает клавиатуру, не выходит в интернет, не читает поля паролей» — с ссылкой на страницу доверия (UI-06). У нас нет разрешений, которые надо выпрашивать, — это стоит показать как достоинство [A].
- **Избегать:** диалога согласия на телеметрию (её нет), регистрации/входа, рекламы Pro-функций в онбординге.

## 6. Страница доверия и диагностика (UI-06, UI-11)

**Что делают.**
- Kright на macOS: вкладка Key Log, где видно, что захват приостанавливается в полях паролей («you can watch capture pause in the Key Log») [V: README].
- LangSwitcher: локальный журнал конвертаций **выключен по умолчанию**, с экспортом JSON [V: https://raw.githubusercontent.com/reg2005/langSwitcher/HEAD/README.md] — у нас журнал без текста вообще, это строже.
- SimpleSwitcher: «иммутабельные» сборки на GitHub Actions, подчёркнутые в README как гарантия чистоты бинарников [V].
- 1Password: публичная позиция «Security isn't a feature. It's our foundation» [R: https://1password.com/product/] — отдельный раздел о модели безопасности как часть продукта [A].

**Рекомендации.**
- **Принять — страница «Приватность и безопасность»** (Settings → Приватность, ссылка из Overview и онбординга), где каждое утверждение сопровождается *живой* проверкой на устройстве [A]:
  - «Сетевые подключения: 0 с момента запуска» — только если это можно проверить без сетевого кода и без повышения прав (например, по таблице TCP-соединений собственного процесса через `GetExtendedTcpTable` — **[SEC][ARCH]** оценить);
  - «Глобальные хуки клавиатуры: не установлены» (по архитектуре — утверждение, плюс ссылка на исходный код);
  - «Песочница макросов: изолирована (AppContainer), доступ к ФС/сети: нет» — статус из `ks-sandbox-host`;
  - «Журнал не содержит текста» — кнопка «Показать сырые данные журнала»;
  - версия, хэш сборки, ссылка на тег и workflow сборки (MI-03).
- **Принять (уже в 4.7) + дополнить журнал:** ретенция (например, 7 дней / 1 000 записей — **[OWNER]**), «Экспорт отчёта» с предпросмотром ровно того, что копируется; отсутствие заголовков окон и URL (уже в `synthesis.md` §1.7).
- **Избегать:** «дневник» или любой журнал набора, даже опциональный — это главный репутационный груз Punto [R, см. user-needs N-01].

## 7. Трей (UI-08, UI-09, UI-16)

**Что делают.**
- Microsoft (Win32-гайд): правый клик по значку уведомлений — обычное контекстное меню, клик — основное действие [R: https://learn.microsoft.com/da-dk/windows/win32/shell/notification-area]. В Windows 11 значки по умолчанию часто уходят в меню переполнения [R].
- JetBrains Toolbox: анимация значка во время фоновой работы; пункты Settings / About / Quit; автозапуск включается в настройках [R: https://www.jetbrains.com/help/toolbox-app].
- Raycast: Game Mode отключает хоткеи во время игры [R].

**Рекомендации.**
- **Принять (уже в 4.8):** левый клик — главное окно, правый — меню, пауза 15 мин / 1 ч / до перезапуска.
- **Дополнить:**
  1. Поскольку значок в Windows 11 может быть скрыт в переполнении, в онбординге показать, где он, и предложить закрепить (инструкция, без автоматического изменения системных настроек) [A].
  2. Индикатор раскладки в значке трея **не делать** в v1: Windows уже показывает раскладку; дубль усложняет иконку и требует отслеживания раскладки [A].
  3. **Анимацию значка избегать** — продукт «тихий» (ТЗ §13), анимация тревожит [A].
  4. Авто-пауза в полноэкранных приложениях (UI-16) — только как опция и после оценки (MI-13).

## 8. Macro Studio (UI-17, UI-18)

**Что делают.**
- VS Code / JetBrains: панель «Проблемы» с переходом к строке; inline-подсветка ошибок; вывод в отдельной панели [A, общее знание].
- Espanso: макросы в файлах конфигурации, пакеты из hub, скрипты и shell-команды без ограничений [V: README].
- Raycast: Script Commands (v0.45, 2026-02-13) с параметрами и хоткеями [R].

**Рекомендации.**
- **Принять:** трёхпанельная схема (уже в концепции) + **«Тестовый запуск»** на образце текста, который пользователь вводит в поле внутри Macro Studio (не из чужих приложений): видно `input → output`, время, лимиты; результат **не применяется** никуда.
- **Принять — бейджи разрешений** рядом с названием слота: «Читает буфер обмена», «Нажимает Enter/Tab» (если Q-2 = да), «Только текст». Бейдж = не только цвет; при изменении исходника разрешения сбрасываются (X-7) — показать это явно: «Код изменён — подтвердите разрешения заново».
- **Принять:** «Шаблоны» — встроенные примеры (регистр, «Ёлочки», обрезка пробелов, обёртка в кавычки/код-блок) как стартовые точки; это помогает ценности одного слота [A].
- **Избегать:** терминологии «скрипт выполняется с правами системы», консоли с доступом к ОС, установки пакетов (pip/npm) — ни в UI, ни в документации [A, D-08].

## 9. Темы и доступность (UI-12)

**Что делают / факты.**
- Media query `forced-colors` определяет режим принудительных цветов (Windows контрастные темы); поддерживается в Chromium-браузерах; Microsoft выводит из употребления `-ms-high-contrast`; `forced-color-adjust: none` — для элементов, которым нужны собственные цвета [R: https://developer.mozilla.org/en-US/docs/Web/CSS/@media/forced-colors, https://www.elevenforum.com/t/microsoft-deprecating-ms-high-contrast-and-ms-high-contrast-adjust-in-edge.24763/]. Поддержка именно в WebView2 в выдаче **не подтверждена** (WebView2 основан на Chromium — вероятно, наследует) [A].
- Microsoft: клавиатура — основная модель взаимодействия; стандартные индикаторы фокуса слишком незаметны — нужны явные [R: https://learn.microsoft.com/en-us/windows/uwp/accessibility/keyboard-accessibility].

**Рекомендации.**
- **Принять:** System / Light / Dark (уже) + **проверка в контрастных темах Windows** (`@media (forced-colors: active)`): чипы клавиш, пилюли статусов и бейджи разрешений должны оставаться различимы без цвета. Добавить в чек-лист GATE 3 и в CI-скриншоты, если возможно [A].
- **Принять:** видимый фокус 2 px+ на всех интерактивных элементах (уже в дизайн-системе — проверить).
- **Избегать:** Mica/Acrylic-эффектов «под Windows 11» через CSS-имитацию — в WebView2 это будет неубедительно и дорого; плоские токены дизайн-системы честнее [A].

## 10. Локализация (UI-13)

**Рекомендации [A, общепринятая практика].**
- Закладывать +30–40 % длины строк для RU относительно EN в кнопках и пилюлях; проверять псевдолокализацией (`[!! Ŝéţţîñĝš !!]`) в dev-сборке.
- Плюралы — через ICU MessageFormat (`{count, plural, one {# конфликт} few {# конфликта} many {# конфликтов}}`), а не склейкой строк.
- Коды причин отказа (`EXCLUDED_APP` и т. п.) — не переводить, показывать моноширинно рядом с переводом (уже в 4.7) — это помогает поддержке и поиску в интернете.
- Язык UI по умолчанию = язык Windows; переключение без перезапуска.
- «Macro Studio» — имя собственное, не переводится (уже в концепции).
