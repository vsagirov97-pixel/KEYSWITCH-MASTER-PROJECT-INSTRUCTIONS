## 2. Карточки идей

### MI-01. Страница доверия с живыми проверками — `proposed`, v1
- **Проблема.** Главная боль рынка — страх кейлоггера и телеметрии (user-needs N-01, ранг 9). Конкуренты лишь *заявляют* «no telemetry».
- **Доказательства.** Punto «Дневник», «телеметрия по сообщениям» [R]; Kright показывает Key Log как доказательство паузы в полях паролей [V]; все OSS-конкуренты выносят приватность в первые строки README [V].
- **Предложение.** Раздел Settings → «Приватность и безопасность»: утверждения + живой статус: «хуков клавиатуры нет» (по архитектуре + ссылка на код), «исходящих соединений процесса: 0 с запуска» (если реализуемо локально без повышения прав), «песочница: AppContainer, сеть/ФС — нет», «журнал без текста — показать сырые данные». См. UI-06.
- **Ценность.** Превращает D-14/ТЗ §14 в доказуемое отличие; материал для позиционирования H-1.
- **Сложность.** M.
- **Риски.** Если проверка неполна (например, WebView2 ходит в сеть мимо нашего процесса) — это будет ложное утверждение → репутационный и правовой риск. Формулировки — только проверяемые.
- **Оценивает.** Security (что можно утверждать честно) → Designer → Architect.

### MI-02. «Справка для ИБ» — `proposed`, v1
- **Проблема.** Корпоративные пользователи и ИБ подозревают переключатели (N-11); Punto используется злоумышленниками как «легальный кейлоггер» [R].
- **Предложение.** Одностраничный офлайн-документ (в репозитории и в «О программе»): какие API используются (`RegisterHotKey`, UIA, SendInput), чего нет (хуков, инъекций, повышения прав, сети), где хранятся данные, как удалить. Генерируется из модели угроз, без маркетинга.
- **Ценность.** Снижает трение при установке на рабочие ПК; подготовка к H-4 (B2B).
- **Сложность.** S. **Риски.** Устаревание → привязать к релизному чек-листу.
- **Оценивает.** Security → Product Analyst.

### MI-03. Проверяемая сборка — `proposed`, v1
- **Проблема.** Неподписанные сборки и закрытый код вызывают недоверие и предупреждения SmartScreen (N-11; D-11).
- **Доказательства.** SimpleSwitcher рекламирует «иммутабельные релизы, собранные на GitHub» [V]; Kright подписал Windows-сборки в 1.1.1 и пишет, что SmartScreen больше не предупреждает [V]; RuSwitcher — бесплатная подпись через SignPath Foundation [V].
- **Предложение.** Релизы только из CI; публикация SHA-256 и аттестаций происхождения сборки (provenance) для каждого артефакта; в «О программе» — версия, коммит, хэш, ссылка на запуск workflow. Отдельно — оценить бесплатную подпись для OSS (SignPath Foundation) как вариант для D-11.
- **Ценность.** Высокая для доверия; дешевле аудита.
- **Сложность.** M. **Риски.** Новые Actions — только с SHA-пиннингом (CLAUDE.md п.4); подпись — решение владельца.
- **Оценивает.** Release Engineer → Security → владелец (подпись).

### MI-04. «Сетевой ноль» как инвариант CI — `proposed`, v1
- **Проблема.** «Без сети» легко нарушить случайно (зависимость, плагин, WebView2-ресурс). Конкуренты-«приватные» всё равно имеют сеть: автообновление (Kright), загрузку словаря и проверку обновлений (RuSwitcher) [V].
- **Предложение.** Набор автоматических проверок: (1) CSP `connect-src 'none'` и запрет внешних ресурсов во фронтенде; (2) нет Tauri-плагинов `http`/`updater`; (3) проверка таблицы импорта бинарников (`ks-*`, sandbox host) на сетевые API; (4) sandbox — AppContainer без сетевых capabilities; (5) интеграционный тест на Windows CI: процесс KeySwitch не открывает сокетов за сценарий. Результат — бейдж в README и строка на странице доверия (MI-01).
- **Ценность.** Высокая: превращает ТЗ §14 в проверяемое свойство, которого нет у конкурентов.
- **Сложность.** M. **Риски.** WebView2 runtime — общий компонент Edge, может иметь собственный сетевой трафик (обновления рантайма) вне нашего контроля → формулировать как «процесс KeySwitch и его код», а не «компьютер».
- **Оценивает.** Security → Architect → Release Engineer.

### MI-05. Видимые разрешения и «паспорт песочницы» в Macro Studio — `proposed`, v1
- **Проблема.** Экспандеры и AHK исполняют пользовательский код с полными правами (Espanso: shell commands [V]; SimpleSwitcher: процессы с правами SS [V]). Пользователь не видит, что может макрос.
- **Предложение.** Бейджи разрешений слота («Читает буфер», «Нажимает Enter/Tab»), сброс при изменении кода (X-7) с явным сообщением; «паспорт» среды: рантайм, версия, лимиты (2 с, 64 МБ, 5 000 символов, ≤ 50 клавиш), «сеть: нет, файлы: нет». См. UI-18.
- **Ценность.** Делает безопасность макросов осязаемой (позиционирование H-3).
- **Сложность.** S. **Риски.** нет существенных.
- **Оценивает.** Designer → Security.

### MI-06. Встроенные шаблоны макросов — `proposed`, v1
- **Проблема.** Один слот — малая ценность, если пользователь не знает, что в него положить; конкуренты-экспандеры сильны каталогами (Espanso hub [V]).
- **Предложение.** 8–12 встроенных шаблонов, поставляемых в продукте (не импорт): РЕГИСТР/регистр/Каждое Слово, кавычки «ёлочки», типограф (дефис→тире, неразрывные пробелы), trim/схлопывание пробелов, обёртка в `код`/```блок```, удаление форматирования (текст как есть), «Ё-фикатор» (только словарный, локальный). Шаблон копируется в слот и становится кодом пользователя.
- **Ценность.** Быстрый «первый успех» с Macro Studio.
- **Сложность.** S. **Риски.** Не должно выглядеть как импорт чужих макросов (D-07): шаблоны — часть сборки, проходят ревью Security как код продукта.
- **Оценивает.** Product Analyst → Security.

### MI-07. Публичная датированная матрица совместимости — `proposed`, v1
- **Проблема.** «Не работает в приложении X» — ранг 9 (N-03); рынок обещает «работает везде».
- **Доказательства.** RuSwitcher 3.5.0 исправлял браузеры/веб-чаты/Outlook [V]; Kright: WhatsApp Desktop (WebView2) не отдаёт ничего через UIA [V].
- **Предложение.** `pa-app-matrix.md` → публичная страница + экран в приложении (Languages/Overview → «Где работает»): приложение, версия, режим (поле/выделение/отказ), дата и способ проверки (CI-фикстура / ручная приёмка владельцем). Неизвестные приложения — «не проверено».
- **Ценность.** Высокая: честность как отличие; снижает поток «не работает».
- **Сложность.** M. **Риски.** Устаревание — показывать дату проверки, не обещать.
- **Оценивает.** Product Analyst → QA.

### MI-08. Повторное нажатие = отмена — `proposed`, later
- **Проблема.** Неудачную конвертацию хочется вернуть одним нажатием (N-13).
- **Доказательства.** RuSwitcher: «Tap again to undo», «learn-from-undo» [V].
- **Предложение.** Хранить в памяти (не на диске, `UserText` + zeroize, TTL ≤ 10 с) только последнюю операцию; повторное нажатие в том же поле, если текст поля равен результату, — обратная замена. Иначе — обычная конвертация.
- **Ценность.** Средняя. **Сложность.** M.
- **Риски.** Хранение текста в памяти дольше операции; гонка с изменением поля. Пересекается с NG-12 и Q-07 PRD.
- **Оценивает.** Product Analyst → Architect → Security; решение владельца.

### MI-09. Раскладка по приложению без клавиатурного хука — `proposed`, later
- **Проблема.** Пользователи хотят «в терминале всегда EN, в Telegram — RU» (N-08).
- **Доказательства.** Kright — правила по приложению и контакту [V]; RuSwitcher — память раскладки по приложению [V]; Input Source Pro — по приложению и сайту [R]; RuSwitcher-Win использует `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` [V].
- **Предложение.** Опция (выкл. по умолчанию): при смене переднего окна переключать раскладку по правилу. Используется событие смены окна (не хук клавиатуры); хранится только имя exe.
- **Ценность.** Средняя. **Сложность.** M.
- **Риски.** WinEvent-хук out-of-context — формально «хук», хотя не клавиатурный; нужно решение Security о совместимости с CLAUDE.md п.8 и восприятием пользователя.
- **Оценивает.** Security → Architect.

### MI-10. Подсказка о раскладке в поле пароля — `proposed`, later
- **Проблема.** Ввод пароля не в той раскладке — частая бытовая ошибка (N-05); KeySwitch в полях паролей ничего не делает (D-05).
- **Доказательства.** Kright автоматически переключает на латиницу в полях пароля/e-mail/URL [V].
- **Предложение.** Опция: при фокусе в поле `IsPassword` и нелатинской раскладке — ненавязчивый индикатор/звук «раскладка RU» (без чтения поля и без изменения раскладки).
- **Ценность.** Средняя. **Сложность.** M.
- **Риски.** Требует подписки на события фокуса UIA (постоянный мониторинг) — противоречит духу «работаем только по нажатию»; утечка метаданных (момент ввода пароля) в журнал недопустима.
- **Оценивает.** Security → Architect.

### MI-11. Помощник выбора горячей клавиши — `proposed`, v1
- **Проблема.** Рынок привык к Shift×2/CapsLock (N-06), а D-14 их запрещает; Alt+Shift в Windows 11 ненадёжен [R]; конфликты хоткеев массовые (PowerToys 0.94 [R]).
- **Доказательства.** 1Password по умолчанию использует Ctrl+Shift+Space на Windows [R] — один из примеров в ТЗ §10.
- **Предложение.** В контроле записи: рекомендованные сочетания; статический список известных занятых сочетаний популярных программ с предупреждением; поддержка Pause, ScrollLock, F13–F24; ссылка-инструкция «CapsLock → F13» штатными средствами; честный текст «почему нет двойного Shift». Плитка конфликтов на Обзоре (UI-03).
- **Ценность.** Высокая: снимает главный разрыв с рынком без нарушения D-14.
- **Сложность.** S. **Риски.** Список конфликтов устаревает → дата обновления; не сканировать чужие программы.
- **Оценивает.** Designer → Architect (S-2: проверка F13–F24 и Pause с `RegisterHotKey`).

### MI-12. Офлайн-changelog и политика поддержки — `proposed`, v1
- **Проблема.** Пользователи уходят от заброшенных продуктов (N-07); без сетевой проверки обновлений (NG-7) пользователь не узнает о новых версиях.
- **Предложение.** В «О программе»: встроенный changelog, дата сборки, «эта версия старше 6 месяцев — проверьте обновления на странице проекта» (по локальной дате, без сети), поддерживаемые версии Windows.
- **Ценность.** Низкая–средняя. **Сложность.** S. **Риски.** нет.
- **Оценивает.** Release Engineer → Designer.

### MI-13. Авто-пауза в полноэкранных приложениях — `proposed`, v1?
- **Проблема.** Игры/RDP/полноэкранные приложения: случайное срабатывание хоткея мешает (N-10).
- **Доказательства.** Raycast Game Mode [R]; Caramba — пауза для игр [R]; SimpleSwitcher — проблемы в RDP [V]. Доказательства банов античитом **не найдены**.
- **Предложение.** Опция (вкл./выкл. — решение владельца): когда передний процесс в эксклюзивном полноэкранном режиме или является RDP-клиентом, не регистрировать хоткеи (снимать `RegisterHotKey`) и показывать «приостановлено» в трее.
- **Ценность.** Средняя. **Сложность.** S–M.
- **Риски.** Ложная пауза → «не работает»; определение полноэкранного режима без хуков нужно проверить.
- **Оценивает.** Architect → Product Analyst.

### MI-14. Безопасная демо-площадка в онбординге — `proposed`, v1
- **Проблема.** Пользователь не уверен, что всё работает, а первый тест в чужом приложении может попасть в «неподдерживаемое» поле.
- **Предложение.** Поле в онбординге/Обзоре, где текст конвертируется **только через `ks-core` внутри UI** (без UIA/SendInput/буфера), с проверкой, что хоткей зарегистрирован. Помечено как «демо».
- **Ценность.** Средняя. **Сложность.** S.
- **Риски.** Политика запрещает конвертацию в собственном окне (`synthesis.md` §1.5) — демо должно быть отдельным путём, не исключением из политики. Текст демо — тоже `UserText`.
- **Оценивает.** Architect → Designer.

### MI-15. «Почему не сработало?» — `proposed`, v1
- **Проблема.** Отказ без объяснения воспринимается как «программа сломана» (N-03); уведомлений нет по ТЗ §13.
- **Предложение.** Пункт трея «Последний отказ: Поле пароля · 14:02» (только код причины и время) → клик открывает запись журнала с объяснением и действием («выделите текст и повторите», «откройте исключения»). Без тостов.
- **Ценность.** Высокая: превращает честный отказ в понятное поведение. **Сложность.** S.
- **Риски.** Метаданные в трее видны при демонстрации экрана — без имени окна, только exe/код.
- **Оценивает.** Designer → Security.

### MI-16. Корпоративный режим — `proposed`, later
- **Проблема/сигнал.** Caramba публикует параметры тихой установки для Intune [R]; ИБ настороженно относится к переключателям [R]. Прямых доказательств спроса **нет**.
- **Предложение.** MSI, политики HKLM (ADMX): отключить Macro Studio, зафиксировать хоткеи и исключения, запретить изменение настроек; документ MI-02.
- **Ценность.** Средняя (потенциал B2B-монетизации). **Сложность.** L.
- **Риски.** Спрос не подтверждён; затраты на поддержку.
- **Оценивает.** Product Analyst (валидация спроса) → Architect → Security.

### MI-17. Языковые пакеты; первым — украинский — `proposed`, later
- **Проблема.** Нужны языки помимо RU/EN (N-14); часть аудитории избегает продуктов Яндекса (санкции Украины 2017 [R]).
- **Доказательства.** MySwitcher — отдельный словарь украинского и контекст UK/RU [R]; Kright/RuSwitcher — любые пары [V].
- **Предложение.** По D-15: пакет = файл раскладки + n-граммная модель; подпись пакета, поставка вместе с релизом (без сети); первым — UK↔EN и UK↔RU с особыми правилами (і, ї, є, ґ).
- **Ценность.** Высокая для роста. **Сложность.** M на язык.
- **Риски.** Лицензия данных модели (R-7); качество различения UK/RU.
- **Оценивает.** Product Analyst → Architect.

### MI-18. Мастер «Переезд с Punto/Caramba» — `proposed`, v1?
- **Проблема.** Два переключателя одновременно конфликтуют (оба меняют раскладку/текст; хоткей может быть занят).
- **Предложение.** При первом запуске и в Диагностике: проверить, запущен ли известный переключатель (по имени процесса из короткого статического списка), и показать: «Обнаружен X: отключите его автопереключение или выберите другую клавишу». Никаких действий с чужим процессом.
- **Ценность.** Средняя: снижает «KeySwitch не работает» у мигрирующих пользователей. **Сложность.** S.
- **Риски.** Перечисление процессов — приватность (только сравнение имён, ничего не сохраняется); упоминание чужих торговых марок в UI — юридическая проверка формулировок.
- **Оценивает.** Security → Product Analyst.

### MI-19. Решение о лицензии кода до монетизации — `proposed`, v1 (решение)
- **Проблема.** Репозиторий публичный (D-09); ТЗ §11 предполагает «1 бесплатный слот» и будущую коммерцию. Лицензия определяет, можно ли продавать дополнительные слоты/пакеты.
- **Доказательства.** OSS-конкуренты — MIT (Kright, RuSwitcher) [V]; RuSwitcher отдельно защищает имя и иконку через TRADEMARKS.md [V].
- **Предложение.** До GATE 9 выбрать модель: (а) пермиссивная лицензия + платные подписанные сборки/поддержка; (б) open core; (в) copyleft + коммерческая лицензия. Отдельно — политика товарного знака.
- **Ценность.** Высокая (стратегическая). **Сложность.** S (решение), юридическая проверка — вне команды.
- **Риски.** Юридические; влияние на привлечение контрибьюторов.
- **Оценивает.** Владелец + Orchestrator (юрист — по решению владельца).

### MI-20. Название «KeySwitch» и товарный знак — `proposed`, v1 (до публичного релиза)
- **Проблема.** На Product Hunt уже есть продукт **KeySwitch** того же назначения (Windows, исправление неверной раскладки по хоткею; упомянута macOS 1.0.9) [R: https://www.producthunt.com/products/keyswitch, https://hunted.space/product/keyswitch]; на crates.io — crate `keyswitch` (macOS-переключатель, MIT, 2025-10-12) [R: https://lib.rs/crates/keyswitch].
- **Предложение.** Владельцу: решить до публичного релиза — сохранить имя (с проверкой реестров товарных знаков) или выбрать новое; до решения не публиковать crates/пакеты под именем `keyswitch` в публичных реестрах.
- **Ценность.** Критическая: путаница с конкурентом, риск претензий, SEO.
- **Сложность.** S (решение). **Риски.** Юридические; стоимость переименования растёт со временем.
- **Оценивает.** Владелец + Orchestrator.

### MI-21. Личный список «никогда не конвертировать» — `proposed`, later
- **Проблема.** Ники, логины, бренды в «чужой» раскладке ошибочно конвертируются (N-02).
- **Доказательства.** RuSwitcher — списки «Never/Always convert», learn-from-undo [V].
- **Предложение.** Список слов, добавляемых **только явно** пользователем в настройках; хранение локально, исключён из журнала и отчётов.
- **Ценность.** Средняя. **Сложность.** M.
- **Риски.** Это хранение фрагментов пользовательского текста — противоречит духу правила `UserText` → нужна явная политика Security (шифрование DPAPI, отображение, экспорт запрещён).
- **Оценивает.** Security → Product Analyst.

### MI-22. Встроенная офлайн-справка по кодам отказа — `proposed`, v1
- **Проблема.** Стабильные коды причин (`EXCLUDED_APP`, `PASSWORD_FIELD`…) полезны, только если объяснены (N-03, N-09).
- **Предложение.** Для каждого кода — страница справки внутри приложения: что случилось, почему KeySwitch так поступил (принцип «лучше отказаться»), что сделать. Ссылки из журнала и MI-15.
- **Ценность.** Средняя. **Сложность.** S.
- **Риски.** нет.
- **Оценивает.** Designer → Product Analyst.
